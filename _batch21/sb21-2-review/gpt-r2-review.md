## 重要发现与实现验收条件

1. **Cleanup 方案可堵住重入覆盖，但当前夹具需改为捕获预期冲突。** 初始快照须包含原始字节与文件存在性；释放路径锁后执行回调；提交时重新获取同一路径锁，对固定文件原始字节比较，比较与原子替换之间持续持锁。变化时抛明确冲突异常，不回滚内层提交、不重跑回调。回调只接触隔离副本，决策绑定原始项，不能污染待提交快照。跨线程屏障夹具须证明回调在锁外；修复后断言冲突、A 未被外层取消、B 和新 H 完整保留，并逐字节等于内层提交后的文件。

2. **legacy 的 int.MaxValue 下界可排除合法历史 int 请求碰撞，但迁移路径须完整覆盖。** 对合法旧请求 `0 ≤ g ≤ int.MaxValue`，迁移后首次新分配 `g_new ≥ 2147483648 > g`，不依赖宿主重启假设。必须在任何 Remove、裁剪、取消操作之前从完整根快照取得 H；首次实际写入同时持久化 v4 和 H；Load 本身不改写旧文件。当前只测 v3/B(9)，还须测 v1/v2、空旧文件、Remove/prune 首次写入、Store 重建、旧 `R_A(int.MaxValue)` 明确过期。

3. **v4 严格校验方向正确；调用方代际输入范围尚须唯一确定。** 必须 `-1 ≤ H ≤ long.MaxValue`，所有项包括取消墓碑满足 `0 ≤ g ≤ H`；H=-1 仅空 items；v4 项代际字段必需；每次持久化携带同一根快照的 H，非分配写操作保持 H。确认新登记代际由 Store 私有物化对象确定，避免读两次可变来件。明确是否所有 Upsert 请求都必须 Generation=0，或只限制新 ItemId；若允许重激活来件非零，也不得由其决定存储代际。增加非零/负数来件拒绝、来件并发改写不影响提交、非法 v4 响亮拒绝且原文件不变。

4. **C5 Remove-only 红证据已拆独立。** `Consume_RemovedCachedSnapshot_IsExpired` 不再依赖重登代际断言，已独立暴露旧缓存 API 缺陷。修复必须移除旧公开快照重载（只新增 Store 重载不够），并保留身份/状态/规范代际各类既有测试；null 项场景改为空 Store；损坏文件需响亮失败。修复后 Store-backed API 复核。读取线性化时点及不承诺至多一次消费的边界合理。

5. **long 尚缺 Trigger 修剪链路和耗尽/持久化错误路径证据。** Consumer 与 `PruneHandledExceptGeneration` 都须使用规范非负 long 十进制、拒绝符号/空白/前导零/溢出。验收 `2147483648` 完整串联：写入、重建读回、Trigger 产请求、Store-backed 消费有效、同实例按身份×代际修剪旧键且保留当前键/其他身份/迁移键。验收 H=Max-1 成功分配 Max；H=Max 时新登记/重激活在加法和写盘前拒绝且文件逐字节不变，Waiting 幂等/Cancel/Remove/裁剪仍可用、H 不下降；另覆盖写入/替换失败后的原件保留。
