## 重要发现（原级别保留）

1. **`PersistCleanup` 回调重入可用旧快照覆盖高水位。** 该方法在持锁读改写期间调用外部 `invalidationReason`；`lock` 可重入。反例：外层读 `H=0` 与 A；回调经同路径另一 Store 登记 B 并提交 `B(1),H=1`；外层随后提交旧 A 快照与 `H=0`；再次登记 B 可复用代际 1，使 `R_B(1)` 重新匹配。只用同路径锁及原子替换不足。最小修复须拒绝同路径嵌套写，或检测快照失效并拒绝旧快照覆盖。回调具体执行方式尚未独立核实，但接口和读改写窗口须处理。

2. **legacy 迁移无法恢复已删除的历史代际，不限于空旧文件。** 反例：旧文件曾有 A(10) 并产出 `R_A(10)`，之后删除 A，文件只剩 B(9)；按当前项最大值迁移得 H=9，重登记 A 分配 10，旧请求仍通过。新建 Store 实例不等同宿主重启。若全部旧请求与触发器去重状态会随宿主重启丢弃，则可由迁移前置条件排除此反例；当前材料没有该生命周期证据，不能声称条件已验证。合同至少要保证迁移后分配不复用，并明确无法恢复的旧代际及切换时如何使旧请求失效。

3. **v4 读取及 Store 分配权不变量须明确。**
   - v4 的 `generationHighWater` 缺失、null、类型错或越界必须响亮拒绝，不得退回 legacy 推导。
   - H 必须覆盖全部现存项（包括取消墓碑）；例如 `H=0,A(7)` 必须拒读。
   - 明确“尚未分配”的唯一表示；空 items 不代表尚未分配。
   - 所有写路径必须携带同一根快照的 H；迁移需在 Remove/prune 删除最大代际项之前取得高水位。
   - 新代际须由 Store 在其私有持久化快照中确定，不能把可变调用方对象赋值后再从该对象读回持久化。
   - 明确新登记的调用方代际非零/负数如何处理；现有负数拒绝夹具不可无说明删除。

4. **当前 C5 新红夹具存在前置断言遮蔽。** `Consume_StaleSnapshotAfterRemoveAndReregister_IsExpired` 先断言新代际为 1，而基线即在此失败，旧 API 消费断言未执行；Remove/prune 两例亦在消费前失败。因此不能据四个失败声称已独立证明 C5 缓存快照问题。拆出：旧实现中 ABA 后旧请求仍有效；仅 Remove 后缓存快照仍被旧 API 接受。修复后使用 Store-backed 消费入口，并验证不存在公开的快照消费重载。

5. **long 扩展须贯通代际链路。** 模型、Store 解析与 Consumer 同步调整；`PruneHandledExceptGeneration` 的规范实现未提供。必须测 `2147483648` 的落盘、重建 Store、请求消费及旧键修剪联动，不能只测重激活不回绕。

## 其他合同边界

- 历史 R37 与 R46 不冲突：R37 接受旧请求最多额外走一次完整准入的有界后果，R46 保留该行为违反 C5 字面 ABA 合同；新方案是更强合同，不能冒充历史顾问背书。
- 高水位耗尽规则：H=`long.MaxValue-1` 可分配 `long.MaxValue`；H=`long.MaxValue` 时，在加法/写盘前拒绝下一次分配；幂等 Waiting 登记、取消、Remove、裁剪仍应可用。
- `Consume(request, store)` 每次内部 Load 并检查 ID、身份、Waiting、规范非负 long 代际，足以给出读取线性化时点的组件级复核；Load 后可并发 Remove，因此不保证返回时/准入时仍有效；连续调用两次均可能 Valid，不提供至多一次消费保证。
- 请求恒为 `RequiresFullAdmission` 且无发送许可字段；这表达组件合同，但不能证明未提供的下游一定执行完整准入。
- 跨进程写入仍由原合同排除；路径别名的锁共享未验证。原子替换只支持对已完成替换后的正常重启作有限表述，不能推称断电持久性。
