## 重要发现与验收缺口

1. **当前关键断言反向突变证据未闭环，旧突变标签有两处已失去判别力。**
   - `Consume_ItemIdMismatch_And_NoGeneration_AreExpired` 的错误 ItemId 现先走 Store 项不存在；删除 Evaluate 内 ItemId 比较不会使其变红。
   - `Upsert_NegativeGeneration_Rejected` 即使移除物化处负数检查，后续 `Generation != 0` 仍拒绝，因此不能独立证明负数检查。
   - 实现后的当前保护需要重新对应突变证据；冗余分支如实说明。此前 M51/M63 标注不能直接沿用为当前分支证据。

2. **legacy 迁移的历史请求闭环不完整。**
   - 目前迁移下界 `int.MaxValue` 可避免复用合法旧 int 代际，但 `LegacyV3WithDeletedHigherGeneration...` 没有显式构造旧 `R_A(int.MaxValue)` 并通过重建后的 Store 断言过期。
   - v1/v2 新增覆盖只测空文件；尚缺非空迁移、旧存量代际保留及旧请求仍可消费的完整链路。

3. **v4、Max、异常路径尚有重要验收缺口。**
   - v4 错误形状尚未覆盖 H 溢出/小数，以及项 generation 为 null、错类型、负数、溢出；现有相似测试针对 legacy v3，不能替代 v4 分支证据。
   - `H=long.MaxValue` 时尚未证明 Cleanup 取消和墓碑裁剪成功且 H 不下降。
   - Store-backed Consume 缺损坏文件响亮失败的直接测试。
   - 替换失败测试可证明 Windows 原件字节保留；尚未独立模拟临时文件写入失败，不应扩张为所有持久化失败阶段均已验证。

4. **规范路径别名未共享锁，且支持边界未落实。**
   - `Path.GetFullPath` 字符串锁键不等价于解析目录 junction/symlink 的物理路径；两个别名可获得不同 `_sync`，并发 Store 可能各自从同一 H 分配同一下一代。
   - Cleanup 比较与替换持锁只约束共享锁键的写者；现有夹具使用同一 `_dir`，没有覆盖物理路径别名。
   - 若生产只支持唯一规范路径表示，应检查生产构造点并明确调用方限制；否则需别名共享锁或拒绝机制。部署是否传入别名未有证据。
