茶包版使用攻略（核弹密码）
更新时间：2026-10-19，按当前茶包版源码、正式界面和实际调用关系整理。
本文只介绍茶包版独特功能的使用方法。与公版一致的功能不在本文重复说明。

一、先看这里：入口和数据已经变化

1、茶包版（LCB版）基于 BetterGI 开发。BGI 负责识图、键鼠与游戏任务；Nexus-BGI 是独立助手，负责计划表、连续一条龙、联机组织和监控。助手里有“耕地机”“嘟嘟可”“槲寄生”等页面。
2、计划表和连续一条龙已经移到 Nexus-BGI，不再从 BGI 一条龙右上角的旧“计划表”弹窗配置。点击 BGI 窗口右上角的助手图标（提示“启动联机锄地助手”），再进“槲寄生 → 任务中心 → 基础模式 · 计划表”。
3、BGI 原生“一条龙”仍用于编辑、执行单个配置。多账号、执行日期、定时和连续计划在助手中安排；只想执行当前账号的日常，可以直接用 BGI 一条龙。
4、先备份数据！BGI 数据主要在程序目录的 User；助手数据默认在当前 Windows 用户的 %APPDATA%\NexusBGI。只备份 User，不会包含助手的新计划、房间和启动设置。
5、手工备份或覆盖配置前，先结束相关任务并关闭会写入这些目录的程序，保留原件。建议公版与茶包版分别存放，避免来回覆盖。脚本、路线和键鼠录制也属于需要保留的资源。
6、旧教程的“首次整份 User 自动备份到 Backups”“计划表弹窗手动备份 User”“生成 NewToOldUser”已经不适用。当前自动兼容一条龙时，只会把需要改写的单个 JSON 原件保存到 User\OneDragon\.compat-backup，不能把它当作整份 User 备份。
7、正常旧一条龙配置会自动整理为公版可读结构；助手接上当前 BGI 后，会接续可识别的旧计划，不自动开始任务。遇到无法读取的个别文件，保留原件，按页面提示处理，不要删除整个 User 重来。
8、当前一条龙配置不需要再经旧按钮“转回公版”。需要跨版使用时，保留两边备份，再按需复制配置及其依赖的脚本、路线、策略。助手的账号绑定、计划编排和定时循环不会因为复制 User 就变成公版 BGI 的功能。

二、计划表、连续一条龙与多账号

1、打开 Nexus-BGI → 槲寄生 → 任务中心 → 基础模式 · 计划表。新建或选中一张计划表，点“＋任务”，从“配置组 / 整龙 / 单项”选择已有 BGI 资源，再点“添加到计划”。
2、勾选要执行的行，拖左侧把手调整先后顺序。点击执行日期、UID/账号字段可编辑每行的条件；相关改动自动保存。
3、整龙行的齿轮可管理配置内部任务的启用、顺序和执行起点。“修改”可打开 BGI 对应配置；在 BGI 改完后，点“读取刚才的修改”刷新计划引用。
4、“启动单任务”只跑当前选中的一行；“连续一条龙”按计划顺序运行已启用项目。计划行右击可选“在此任务开始执行”或“清除在此执行”；起点标记在一次启动受理后清除。
5、多账号在对应任务行设置 UID/账号，可添加或移除绑定。自动切号依赖 PC 游戏中已有的账号记录和绑定码识别，不是输入任意账号密码就能自动登录；编辑框留空表示保留当前值，删除绑定要使用相应移除操作。
6、先用单个账号和一两项任务确认配置正确，再扩展成多账号计划。绑定 UID、账号记录与当前游戏账号应一致，账号校验失败时先看原因，不要反复点击启动。
7、右上方“计划设置”可设开始时间；留空表示点击“连续一条龙”后立即开始，也可选择错过开始时间后顺延次日。
8、循环可选“执行一轮”“每天到点开始下一轮”“完成后立即开始下一轮”，并可设截止时间。失败处理可选停止计划或继续下一项，失败重试为0～3次；完成动作可选保持打开、关闭游戏/软件或关闭计算机。
9、选好计划设置后点“完成”，自动保存。运行中的计划保留启动时的计划设置；运行中修改任务列表，则后续节点按更新后的列表接续，本轮已完成的项目移到后面也不会再次执行。
10、任务中心运行卡片的“暂停”在当前节点结束后生效，“恢复”继续后续任务；需要结束当前计划，点运行卡片的“停止”并等待确认。BGI本地停止与助手计划停止的作用范围不同。
11、开始时间和循环需要助手保持运行、计划已经启动等待；仅填时间不会在电脑关闭或助手未运行时自行开机。Windows 登录自启动、助手启动后流程和计划定时是不同设置。
12、当前正式使用上述基础计划表。“高级模式 · 流程编排”仍在独立施工，“执行策略”“三方接入”仍属规划，不要把它们当成已经可用的完整高级编排功能。

三、配置组中的独立任务与茶包设置

1、入口：BGI → 全自动 → 调度器 → 选中配置组 → 添加 → 独立任务。选择任务后加入本组，可与JS、路线顺序执行；右击任务打开“修改独立任务配置”。
2、联机锄地有专用的“锄地一条龙（联机）”任务和设置窗口，可保存到不同配置组，为不同成员、线路分别绑定，见第八节。
3、茶包行走、战斗及本体模板拾取名单在配置组“设置”中。组战斗配置启用后使用本组参数，未启用时地图追踪回落到全局战斗配置；配置组里的独立任务另用自身任务配置。
4、第三方JS自身的拾取、配队和路线选项仍以脚本说明为准。下面介绍的是茶包宿主提供的能力，不把某个第三方脚本的参数当作所有任务的统一配置。

四、茶包战斗引擎：自动EQ、盾奶、吃药与回点

1、当前保留茶包版与公版两套战斗引擎，默认茶包版。全局开关在“独立任务 → 自动战斗”；配置组启用战斗配置后，可独立选择“使用公版自动战斗引擎（本配置组）”。配置组未启用战斗配置时，地图追踪采用全局战斗配置。
2、两套引擎有各自参数。茶包版的自动EQ、战斗吃药、特殊角色处理和战斗中回点等，不能理解为切到公版后仍会照搬执行。联机锄地始终使用茶包版战斗。
3、当前独立任务页直接点击“自动战斗”仍走茶包实现；地图追踪、自动秘境/首领/幽境/地脉、JS战斗等已接入的路径按各自作用域的引擎开关执行。不要仅凭开关旁的概括文案判断所有入口都已切换。
4、先选择适合当前队伍的战斗策略。茶包路径可按策略类型执行 TXT、JSON 或自动连招；策略文件、队伍序号和实际角色需要对应。以下自动EQ、战斗自动吃药和通用战斗中回点说明适用于茶包TXT任务，JSON与自动连招按各自实现执行。
5、战斗结束检测先保留默认参数，确认不会漏怪、未引战就结束或打完不结束，再逐项调整快速/连续检查、派蒙检查、二次检查及旋转寻敌。不要同时把所有旋转拉满、把所有检测延时降到极限。
6、茶包版“战斗过程回到战斗开始节点”有独立开关、检查间隔、触发距离和停止距离。时间触发还要求开启旋转寻敌，距离触发不要求；不要再按旧教程只填一个“精英40、小怪7、0关闭”的数字。

茶包版自动EQ与盾奶位：
7、盾奶位填队伍序号，按角色需要选择短E或长E。“禁用盾奶位战斗策略”的开关会影响该角色是否继续执行原策略，配置时不要把自动技能与策略执行重复叠加。
8、开启“实时自动检测Q技能，按队伍中序号进行释放”后，“Q释放的序号顺序”用英文逗号分隔，例如 1,2,3C。普通序号按填写顺序参与自动Q；没列出的角色不参加自动Q，但仍可执行常规策略。
9、大写C同时排除该角色的自动Q与常规战斗策略。例：1,2,3C 表示1、2参与自动Q，3禁用这两类执行，4不自动Q但仍可跑策略。
10、“自动Q过程中的技能设置”：普通序号为短E，H为长E，F为盾位技能后的首个E，A为E后普攻（默认600毫秒），A(800)为普攻800毫秒。例：1HF,2A(800),3H,4A。使用大写C/H/F/A，同一角色不重复填写，F只给一个角色。
11、战斗自动吃药需佩戴便携营养袋，默认关闭；当前默认检测间隔200毫秒、吃药间隔1500毫秒、单场上限5次。按自己的药量、回血角色和战后恢复需求开启，不默认要求所有队伍打开。
12、万叶/琴聚集材料、战后回血、“扫描掉落物光柱”等按需求开。扫描光柱是战后寻找并靠近掉落物，主要作为无万叶时的补充，与自动按F拾取不同；减少战后等待可能漏材料。

五、茶包赶路、回血补充与快速拖图传送

1、配置组“设置 → 地图追踪行走配置”中，茶包新增“红血仅切角色”和“Q技能回血”。红血仅切角色用于优先换到非红血角色；Q回血填写队伍序号，需角色实际有有效回血方式及可释放的Q，内置有爱可菲、闲云的相关处理。
2、赶路系统可在茶包版与“新版赶路系统（莫酱版/公版）”之间切换，两个版本各自记忆所选角色。默认茶包版，支持玛薇卡、瓦雷莎、希诺宁；需要新版时打开对应开关，使用其独立角色列表选择。
3、茶包玛薇卡赶路另有“跳飞距离”参数，控制挑飞触发距离，填0关闭。先按路线测试赶路动作和接近节点的表现，再调整距离。
4、茶包的战后“减少等待”和“执行简易策略后的延时”会影响拾取完整度。简易策略等待默认900毫秒，按实际掉落需求调整；旧教程的100毫秒与固定提速幅度不再作为通用推荐。
5、配置组可单独开启“关闭地图追踪过程中的自动领取派遣奖励”；它以全局已经选择自动领取城市为前提，适合只让部分配置组在传送时领取派遣。
6、茶包快速拖图传送入口：“设置 → 大地图地图传送设置 → 使用公版传送”。默认关闭时用茶包版快速拖动，打开后切回公版；页面只显示相应模式的参数。
7、茶包传送的整体识别延时默认0，表示自动适配；遇到拖不动、误点或识别过快时逐步提高，鼠标移动间隔也可调整。先保留默认值，按当前窗口和机器表现调整。

六、本体模板拾取与配置组独立名单

1、在“实时触发 → 自动拾取”打开“本体模板拾取”，使用茶包模板匹配；关闭后使用公版OCR。两套方式使用各自名单，切换后原规则保留。
2、本体模板拾取有全局黑名单，配置组还能单独设置本组白名单、黑名单。组黑名单优先于组白名单，组白名单可覆盖全局排除；模板组白名单并不是“只捡这些、其他一律不捡”的独占模式。
3、额外模板放在 User\mojang_templates。调度器组设置中的“本体模板拾取名单”只影响本体模板方式，不会替代公版OCR规则。
4、“测试自动拾取”会继续识别、记录和扫描，但不按拾取键。出现“识别到了却不捡”，先检查该测试开关、名单、拾取按键及是否真的启用了自动拾取。

七、茶包内置单机锄地

1、当前BGI已内置“独立任务 → 锄地一条龙”。可选择执行路径组、游戏内配队名称、路线排序、拾取方式、目标精英/小怪数量、优先/排除关键词和仅指定怪物等。先用正常“运行锄地路线”，调试分配和刷新记录不是普通开始按钮。
2、路线和关键词按页面说明填写，注意部分字段要求中文逗号；自动EQ字段则用英文逗号。目标怪物按图鉴名称填写，排除关键词会排除匹配线路，不是只跳过该线路内某一只怪。
3、本体锄地和第三方锄地JS是不同入口，参数不能简单互抄。泥头车角色、拾取二次校验和料理按配队需要设置，先确认正常一轮再开额外优化。

八、联机锄地：先配BGI，再由助手组织

1、每台执行机器都需要BGI和Nexus-BGI助手；统一开锄还需要兼容的协调服务端。不要只更新其中一个程序就假定所有联动能力相同。
2、助手“设置 → 打开房间设置”：协调服务器填根地址，不加 /hub；设置4～8位控制房间密码、各机不同的玩家名称、自己的游戏UID，以及各机完全一致的队伍UID列表，列表必须含自己。
3、控制房间号由队伍UID列表生成，可在助手顶部点击复制。这里的房间密码不是原神账号密码；助手“预期开锄人数”用于组织上线等待，与BGI联机任务中的组队人数、超时动作要分别检查。
4、BGI“独立任务 → 锄地一条龙”的联机设置可配置联机；也可在调度器“添加 → 独立任务”选择“锄地一条龙（联机）”，打开专用配置窗口，启用“联机锄地模式”。
5、本机选“房主（创建房间）”或“成员（加入房间）”。房主选线路、组队人数、超时动作与多世界轮数；成员选择指定房主名称或随机加入现有房间，指定名称对应房主填写的玩家名称。
6、“联机队伍名称”“联机起始角色名称”留空沿用当前。成员可在“按线路切换角色”的“角色”设置中配置自己的角色，房主负责线路和需同步的有关参数。
7、固定联机策略通常使用 User\AutoFight\联机战斗策略.txt；关闭“固定使用联机战斗策略”后使用普通策略选择，固定文件不存在也会回退。联机环境的技能和策略应单独检查。
8、助手成员卡片“锄地”绑定该成员自己的联机锄地配置组，可顺序绑定多组；“一键锄地”确认后统一组织准备。看成员和任务状态，区分已受理、准备中、执行中与结束，不能把命令发出当作已经开打。
9、“多世界连续锄地”按加入顺序轮换房主，最多4轮。“锄地守护模式”在符合掉线/掉房或未跑完条件时至多完整重开一次；主动停止、经验上限正常结束和单机不触发。
10、“线路重试模式”按线路名关键词开启，任一成员复苏时全员停止当前战斗、跳过战后拾取、回神像重跑该段，仅重试一次。
11、“基于经验判断停止锄地”需主动启用，按所选目标在全员连续4场没有相应经验后结束。正常使用不要开启跳过路线一致性验证或单人调试；单人调试不记录CD，也不能用于确认真实多人链路正常。
12、需要停止整个联机批次，用助手“停止 → 确认全部停止”并选择所有成员；等待目标回执确认。离线成员无法实时接收，不能仅凭“已发送”认定全员已经停止。
13、“清除上线”取消上线意图；“重置状态”会停止任务并整理任务中心状态，不是刷新按钮。仅在BGI本地停止，不能代替对其他成员和助手自动续跑意图的统一处理。
14、联机参数较多，专用窗口顶部有“联机锄地使用教程”，详细线路、角色和变体配置继续看该文档。

九、启动中心、监控端与远程查看

1、助手“执行端/监控端”与“单机/在线”是两组独立状态。执行端连接同一Windows会话内的BGI并实际执行，单机时仍可运行本地计划、查看日志；监控端负责查看和远程下发，不参加联机战斗、不占成员名额。监控端要编辑或执行另一端的计划，先“连接执行端”，本机不提供任务中心执行。
2、执行端“槲寄生 → 启动中心”可按顺序添加判断、动作节点，最后用“进入任务中心执行”指向已有计划。“立即执行”手动运行一次，“启动后自动执行流程”及延迟决定助手启动后的自动动作。监控端连接执行端后可使用其远程界面，本机启动中心只提供本机动作。
3、启动方案可命名保存、恢复和JSON导入导出。定时器、电子狗、日志触发器需要助手保持运行；退出后失效，重新启动需由启动流程挂载。日志触发器只处理挂载后的本机新日志。
4、“嘟嘟可”包含实时日志、日志浏览、异常监控、锄地数据和桌面监控。共享实时日志与共享日志文件是不同开关，需要对方分别开启；“清空视图”仅清界面，不删除日志文件。
5、桌面监控可看本机主屏、单成员或全员同屏，并支持刷新、放大和下载。共享的是桌面画面，开启前检查会展示的内容；完整日志也可能含本机路径等个人信息。
6、监控端可在槲寄生顶部选择执行端，或用“扫描同机 → 连接执行端”。远程修改保存到所连接执行端，先确认目标；遇到草稿冲突或结果未知，先读取状态，不反复点启动。
7、协调服务器的网页控制面板可填写6位房间号、4～8位密码和昵称进入，查看成员和下发快捷指令。网页不能替代各机实际执行任务的BGI和助手；仍需看目标端结果。

十、配置分享、完整迁移与备份

1、分享计划：任务中心“导出配置”将全部正式计划导出到所选目录，每张计划一个JSON；“导入配置”可多选JSON。单张导入/导出使用左侧计划管理。计划导出会剔除已知UID和绑定码，接收者需要重新绑定账号，并具备计划引用的本机资源。
2、跨电脑搬家：助手“设置 → 配置迁移 → 导出全部设置 / 导入全部设置”，生成或读取ZIP。先在目标机助手选定本机 BetterGI.exe，再导入包含BGI资源的包。
3、ZIP可含房间、启动策略、启动流程/方案、任务中心计划、嘟嘟可、监控规则、桌宠、成员缓存，以及已定位BGI的配置组、一条龙、JS、路线、键鼠脚本、战斗和七圣策略资源。
4、未定位到BGI User时，导出会提示包里没有BGI资源。ZIP不包含软件本体、BGI全局设置、外部程序、运行记录和本机身份；游戏路径、截图/按键等本机设置仍需在目标机检查。
5、导入需在没有任务、上线等待或未结束命令的情况下进行；会先备份原配置，结果弹窗显示备份位置。同名不同内容的BGI资源保留目标机版本，导入副本改名并修复引用。
6、导入本身不启动任务，导入的定时上线需在本机重新确认时间和任务后启用。不要把从另一台机器带来的设置当作本机已经授予自动执行许可。
7、“全部设置ZIP”保留私人账号、房间和有关设置，妥善保存，不作为公开分享包；分享计划也应检查自己填写的名称、备注和资源内容。
8、默认助手数据目录 %APPDATA%\NexusBGI 中，assistant-config.json是主要配置，startup-flow.json和startup-flow-schemes.json是启动流程及方案，flows是任务中心计划，runs是运行记录。不要靠删除文件夹来取消运行；优先使用界面的停止、删除和恢复功能。

十一、助手多用户与登录启动

1、助手设置和计划按Windows用户分开保存，每个执行端应与自己控制的BGI位于同一用户/会话；监控端可以连接其他会话的执行端。
2、出现“跨会话”提示时，检查助手与BGI是否在对应会话，不要用另一个管理员账号的凭据代替目标用户启动。
3、助手“开机自启动”登记当前登录Windows账号的启动入口；完整文件需包含 NexusBGI.Startup.exe，该登录入口不要强制设为管理员运行。它与计划定时、启动中心的自动流程需要分别配置。

十二、其他茶包专属设置

1、网络检测：“设置 → 其他设置 → 电脑网络检测失败时，自动暂停BGI脚本”。填写可Ping的主机名或IP，不加HTTP前缀；默认地址 www.baidu.com、间隔5秒。连续检测失败并复核后进入网络暂停，恢复后尝试继续；它不能保证任何类型的游戏断线都无损续接。
2、临时识别新角色：“设置 → 其他设置 → 队伍角色假装识别设置”。先看茶包战斗识别日志，再填容易误认成的角色、目标角色和置信度，固定新角色位置。阈值越高越容易替换，也越可能误替换正常角色。添加自定义角色后按界面提示重启BGI；映射名称不等于完整适配角色技能和战斗策略，也不保证公版引擎使用同一映射。
3、额外UID遮盖：“设置 → 实时UID遮挡”中，茶包增加“遮盖派蒙菜单UID”和“遮盖联机输入UID”，按需要分别打开，适合录屏或共享桌面时遮挡对应位置。

十三、连续一条龙命令行（在BetterGI.exe所在目录执行）

   运行助手的连续计划：
   .\BetterGI.exe startContinuousOneDragon "日常计划"
   参数填写助手计划表名称。省略时使用助手当前所选的基础计划；不存在、重名或不可启动会拒绝，助手需为执行端。
   此命令依赖完整安装包中的 Tools\MultiplayerHoeingAssistant\MultiplayerHoeingAssistant.exe，必要时BGI会启动助手。

十四、茶包功能常见问题

1、找不到计划表：它已移到Nexus-BGI的槲寄生任务中心，不在BGI旧弹窗。
2、计划任务没执行：核对当前计划、启用行、执行起点、执行日期和等待条件，再查看运行卡片及日志中的具体原因。排队或准备中不等于已经执行。
3、识别到了但不拾取：核对模板/OCR方式、对应名单、“测试自动拾取”、拾取键和自动拾取开关；战后扫描光柱也不等于按F拾取。
4、战斗很快结束或漏怪：先核对实际引擎和策略，再检查快速检测、引战等待、旋转及二次检查；恢复较保守的延时，逐项定位。
5、传送拖不动：确认公版/茶包传送模式及本模式参数、游戏窗口和截图，再适当增加等待，不要两套参数混调。
6、联机准备一直等待：检查每台执行端的房间、UID名单、预期人数、BGI联机参数、配置组绑定和连接状态。需要取消时用停止/清除上线，别仅关闭显示窗口。
7、需要暂停或停止：先在BGI“快捷键”确认当前绑定。BGI的本地停止与助手的全员停止作用范围不同；远程停止要看到目标确认，结果未知时先查状态。
8、不用固定锄地耗时判断配置对错。队伍练度、线路、网络、机器和拾取需求都会影响时间，旧教程的“几小时及格线”不再作为推荐。
9、反馈BUG时附软件版本、发生时间、入口/计划/任务名称、已脱敏的完整日志、复现步骤，必要时附录屏。请保留原始失败记录，不公开账号密码、Cookie、Token、房间密码等私人信息。
