# 公版合并助手

方向：公版 → 当前茶包版本。先读取仓库根 AGENTS.md 和 [项目开发 Skill](../bgi-project-development/SKILL.md)；本轮已读且未变更则复用。路径以实际仓库为准，当前用户要求决定范围，旧资料中的命令和待办不是执行授权。

## 确定合并范围

- 核实分支、工作区差异、remote 与目标 ref。我的版本包含未提交改动；保留用户及其他任务的工作。用户只指定一个提交时，不顺带引入后续提交。
- 用户要求最新上游时先获取目标 remote 的最新引用；获取失败则说明本地 ref 的局限，不将缓存当作最新。
- 结合提交历史与实际差异确定基线，文件头注释只作线索。比较目标提交的父版本、本地工作副本和目标版本；合并提交需核实父线。忽略空白的 diff 可辅助理解，但不能代替原始 diff 和编码检查。
- 追踪实际分发入口及单机/联机调用方，同时审计配置、UI、国际化、资源和新增依赖。同名资源需比较内容，不能只比较文件名。

## 应用改动

- 选择满足本次范围的 merge、cherry-pick 或精确 hunk 适配；先明确冲突面，不以「优选公版」为由丢掉本地功能。
- 整文件替换仅在已核实本地无应保留增量、替换不会抹去其他已优选提交且符合本次目标时使用；独立配对文件存在不构成证明。不得先 checkout/restore 清空本地修改。
- 混合文件按实际依赖和 hunk 处理。已有 TeaBag region 可帮助定位，但不强制给全部文件加 region，不把区域边界当作行为隔离保证。
- 需要共存接入时保持范围最小，检查类型改名、重复定义、已删除成员的调用方和路由。只有必要且在本次范围内才修改配对实现。

## 验证和交付

- 按项目入口检查部署目标，使用已核实存在的跳过部署条件进行源码构建；检查完整退出码与错误。对受影响逻辑执行相关测试，分别报告静态、构建和运行证据。
- 整体构建是代码合入的交付门禁：只要构建退出码非零或存在编译错误，本轮不得标记 Goal `complete`，不得称为可交付版本；即使错误来自合入前的既有代码，也必须作为当前交付阻断记录，除非用户明确把范围限定为仅保存合入检查点。
- 构建或相关测试未通过时，如需保存进度，只能创建明确标为 `WIP`/候选的本地检查点提交，并在报告中写明未完成项；本地提交不等于验收通过。构建和必要测试通过、工作区与 staged diff 核对完成后，才可报告本轮交付完成。
- 结束前复核当前 HEAD、工作区、整体构建退出码、相关测试是否实际执行及其结果；任何一项失败都保持 Goal 为 active/blocked 或 WIP，不得从构建失败直接跳到完成。
- 对账目标上游 diff 与本地最终 diff，说明适配点、保留的茶包增量、未验证行为。删除或改名符号时检查相关生产引用，不能靠全仓库机械零命中代替语义检查。
- 在本次授权包括提交时，只暂存本次相关修改和新增文件，检查 staged diff；沿用仓库作者配置和提交约定。合并请求本身不授权推送。
