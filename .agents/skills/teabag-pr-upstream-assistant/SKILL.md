# 茶包版向公版 PR 助手

方向：茶包功能 → 公版 PR 分支。先读取仓库根 AGENTS.md 和 [项目开发 Skill](../bgi-project-development/SKILL.md)；已读内容复用。当前请求决定功能及分析、实现、提交、推送的授权范围。

## 明确功能和基线

- 核实源分支、未提交增量、目标 remote/ref；公版默认 origin-lcb/main。区分用户要搬运的功能与整个茶包版本，不自动发布其他功能。
- 读取 [PR 工作流](../../specs/teabag-refactor/pr-to-upstream-workflow.md) 中当前功能相关章节，作为历史方案与依赖线索。旧版本号、分支、行数、完成状态及传送专用清单必须结合当前代码重新核实。
- 若用户只要求审计，先交付审计结果，不自动改代码或创建提交。实施时从已核实的公版基线建立独立 worktree，保留原茶包工作区；默认新分支用 codex/ 前缀，用户指定名称时遵从用户。
- AGENTS.md 与 .agents/ 当前不受 Git 跟踪，新 worktree 未必包含它们。进入前确保能读取原工作区规则及所需资料，不误称已自动继承，不将这些本地资料顺带加入 PR。

## 代码与资源审计

- 用 `git show <公版ref>:<仓库相对路径>` 核实成员，用实际调用链列出编译依赖和运行依赖。记录每项依赖在公版是否存在、是否同语义、如何解耦及验证。
- 对 png、Recognition.json、配置和项目资源包含规则作同等审计；通过 git blob 或字节哈希核实同名内容，并检查资源加载路径和 key。
- 默认排除与目标功能无关的联机代码。若用户明确要贡献联机功能，按其范围审计端到端依赖，不能套用「联机符号一律删除」。
- 公版缺失依赖可按场景实现为本机逻辑、剥离无关分支或引入必要自包含依赖；只有证明调用语义和兜底安全后才使用常量返回。传送文档中的 return false 不是通用替代方案。

## 整理和交付

- 共享同名文件只带必要 hunk，新增文件按功能组织；不要覆盖整份茶包共享文件，不直接搬运混有其他功能的历史提交链。
- 核实配置开关的实际默认值和迁移行为；默认保持公版用户原有路径，除非本次目标明确要求改变。联机解耦扫描结合依赖审计，不能仅以符号零命中证明可运行。
- 在 PR worktree 完成相关构建和测试；构建前检查部署目标。与公版基线比较最终 diff，检查资源、项目引用、共享文件和功能边界。
- 授权提交时按功能整理干净 commit。推送前提供具体 commit 清单、`git diff --stat -M <基线>`、共享文件复核、验证及剩余风险，并核实 remote 和目标 PR 分支。
- 尚未获得推送授权时，完成可审查的本地结果后再请求确认；已有明确推送授权则不重复询问。只推目标 PR 分支，不推公版主线或茶包分支，不将 PR 分支自动合回茶包；创建或提交远端 PR 也遵循当次授权。
