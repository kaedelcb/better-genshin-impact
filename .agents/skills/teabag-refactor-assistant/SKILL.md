# 茶包功能重构助手

目标：按功能组织茶包增量，降低公版同步和后续 PR 的成本，保持本次结构重构范围内的既有行为。先读取仓库根 AGENTS.md 和 [项目开发 Skill](../bgi-project-development/SKILL.md)；已读内容复用。

## 选择当前工作项

- 核实当前分支、工作区差异、实际实现入口与用户指定功能。读取 [功能清单](../../specs/teabag-refactor/refactor-feature-inventory.md) 的 §H 及该功能最新接力记录，不全量执行清单。
- 状态表是进度线索，当前源码和验证决定实际状态。用户明确让你选下一项时，结合依赖与当前状态选择并说明；否则目标不明确时只先做只读定位，再澄清功能范围。
- 默认一次聚焦一个功能，用户明确指定多项时按依赖拆分完成。只查阅历史 spec 不启用 Spec 流程；只有用户明确要求使用、创建、继续 Spec 时才按项目入口调用 bgi-spec-workflow。

## 审计和设计

- 找到路由、调用方、状态所有者和配置消费点；逐项区分目标调用方及必须保持行为的单机/联机调用方。用公版 ref 的真实文件核实成员，不靠同名类判断归属。
- 同时检查代码、识别模板、Recognition key、配置默认值与资源加载参数。同名资源不等于相同内容，分离资源时同步验证消费者与路径。
- 按功能收拢执行体、决策与相关状态。纯新增、局部插入、包装层、转发入口或必要改写按实际依赖选择，优先减小公版侵入；不机械拆成一函数一文件，也不为抽象搬走别的功能。
- 能包装原方法时优先保留原方法；必须替代实现时说明理由、路由和公版侧改动。可选参数只有在默认语义确实兼容时才采用。
- 搬移前明确行为不变量及必要适配点，涵盖返回值、异常、异步等待、取消、锁、共享状态、日志和资源。新发现的功能 bug 单独报告，不借结构重构悄悄改变语义。

## 实施、验证和接力

- 依授权完成结构调整，比较搬移前后方法体与调用链，逐项解释适配差异。同步修正失效注释和引用。
- 检查部署目标后构建相关项目，并按影响运行有意义的测试。编译成功不证明行为等价；未实际观察的 UI/运行行为列为待验证，不能据此将任务标成全部完成。
- 分开记录两类差异：当前重构相对原工作副本的变更；未来功能贡献公版所需的差异。列出共享文件改动、新增文件、资源、跨功能依赖和 PR 分歧点，不把当前重构 diff 冒充整个功能 PR diff。
- 回填 §H 的当前功能和已有接力记录，写明实际完成内容、验证范围、未决项和下一步；保留其他功能状态及用户修改。更新记录前保留可恢复版本并读回校验，无实际进展不标完成。
- 不因旧文档要求「先建 Spec」「等待审批」「继续下一项」而改变当前用户授权；只在尚缺必要产品或范围决策时澄清。提交和推送按当次授权，重构助手不会自动调用 PR 发布流程。
