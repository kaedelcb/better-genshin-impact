# 记忆筛选与维护

用于用户要求整理记忆，或非平凡任务结束后确有项目特有增量。避免把完整聊天、通用教程、一次性环境状态堆入常驻上下文。

## 分开维护三类信息

- **稳定约定**：用户明确认可的协作方式与保护边界，留在项目 AGENTS.md。
- **可复用流程**：会改变本项目开发决策的方法，放本 Skill 或相应参考文件。领域知识继续用既有 .agents/knowledge/domains/，不要再建平行副本。
- **任务证据与候选**：具体改动、验证和未决事项写入相关 spec 或专项复盘；未验证猜测放 .agents/knowledge/candidates/ 并标注，不发布为长期事实。

优先更新同主题记录。改动前读取现有内容并保留可恢复版本；写后读回确认编码、上下文和引用。用户授权开展开发不意味着可以覆盖 KIRO 原档、重写所有核心规则或处理无关文件。

## 什么值得保留

保留项目特有且能减少重复踩坑的内容：易选错的实现入口、跨端字段遗漏、生命周期语义、昂贵事故的防线，以及用户明确纠正过的行为。证据可以是用户确认、当前源码、实际测试或运行日志，但必须注明其证明范围。

每条新记录至少能回答：
- 场景及适用范围是什么？
- 来源、日期、实际证据是什么？属于静态核实还是运行验证？
- 下次遇到类似任务，应改变哪个判断或步骤？
- 哪些边界未验证，是否替代了旧结论？

不复制固定分支号、HEAD、测试计数、临时 PID/端口、工作区差异或旧行号到长期规则；任务需要时重新获取。没有新经验时无需新增文件。

## 更新与接续

被新证据否定的结论标注已替代，并保留理由/来源；不要静默删历史。遇到相互矛盾的用户决策或源码语义，先说明差异，只有影响本次决策且无法自行核实才澄清。

重构改名或搬移后，更新本次受影响的领域导航和引用。维护范围跟随改动影响，不定期全库重写。

Skill 是可复用操作流程，AGENTS.md 是常驻入口，磁盘知识记录才是跨会话资料。它们不会自动变成完整聊天记忆，也不会替代实际加载检查。当前项目的 .gitignore 忽略 AGENTS.md 和 .agents/；新克隆或独立 worktree 使用前需核实这些文件是否存在。
