# BGI 项目开发协作

先核实际仓库和项目 AGENTS，按[当前交付流程](../../../_workflow/usable-delivery-20261003/DELIVERY-FIRST-POLICY.md)选工作。用户当前目标和取舍优先；旧 Spec、报告、事故规程和未勾选清单只供相关事实检索，不启动其历史任务。

## 定位问题

- 查当前用户入口、决定行为的配置/路由/状态及调用方；源码和实际观测决定技术事实，不凭旧标签重复施工。
- BGI、助手、服务端分开核。战斗/传送双实现及共享单机/联机调用方必须查实际路由，不能按同名文件选实现。
- 查历史时按需读 references/project-knowledge.md 或相关领域资料；跨端故障按需读 references/cross-end-diagnosis.md。已读且未变的材料复用，不加载整本历史。
- 根据具体功能缺口或实际使用故障集中修复。下一项验证必须能改变当前修复/交付决定，写一句理由和结束判据即可，不另建通用表单。

## 完成当前用户能力

- 保留总计划全部约定功能及正式可操作 UI、正常旧数据合同；功能不能用和现实误执行/数据/停止风险现在修，获准的普通小范围 BUG 登记后修。
- 实施时做定向检查，稳定版本集中执行影响相称回归与实际入口验证。同源码、直接依赖和运行条件的有效证据复用，变化只重验受影响部分。
- 不默认每次小改前后审、全量回归、反向突变、全部 SDK 认证、全部历史逐项重述或 begin/audit/verify。采用工具只为本次明确需要的核验，遵守真实协议与存储边界。
- 当前已批准的独立整版审查按原范围、模型/强度/有限次数完成；新审查不自动发生。需要独立意见时按[审查流程](../../../Docs/design/mistletoe-review-process.md)集中追查真实影响链，保留原报告及当前版本范围。
- 相关并行成果在安全集成窗口读取索引的 deliveries/preparations，核当前输入与终态后消费；不重做有效准备，不让用户协调。

## 保护与报告

- 保护真实 User、第三方 JS、.kiro、其他写者、未提交数据和历史失败；构建先核部署条件，必要时用当前已存在的 DeployToBgiTools=false。
- 新材料经共享存储 Session，按实际规模预约；不复制整树、不绕预算、不清失败证据。不因工具机械限制另开工具工程或冻结无关产品工作。
- 构建、测试、实机和最终交付分别说明。文档/技能维护只核内容、引用、格式和改动范围。
- 只有有证据的新项目经验才按 references/memory-curation.md 的适用范围整理；全局 memory 仅在用户明确要求时更新。
