# 节点与运行封印接续

沿原 usable-delivery-control-recovery-20261003、原 opening/history、两次 blocked 前审和全部原级义务。交付优先授权允许红例/定向修复，尚无综合后审或实机验收，生产门关闭。

共同协议：节点封印留存完整提交、该出现前置和结果，允许下一节点；整运行封印仅在全部主体/前置/收尾清偿且最终 State 明确时发布。封印只由 RunStore 同门从最新耐久事实生成；普通写入不能造/删/换封印。节点封印保护原出现，旧提交进入不可变完整历史。最终封印绑定全部运行事实。Host 在门外回写，hook 只读封印；失败用同封印重试并读回。

|维度|场景|预期|
|---|---|---|
|状态|raw terminal 但退出未确认|节点及运行都不释放|
|状态|完整主体退出，前置效果未知/收尾历史未知|不释放|
|状态|早节点已清偿，run Running|节点可封印，run 不封印，后继可推进|
|并发|旧提交替换、节点封印后同出现改写/新增|保存完整历史，拒绝改写或重发|
|并发|运行封印后准备/发送/恢复/事实新增回退|拒绝，零新调用|
|故障|封印发布失败|不回写、不释放|
|故障|仲裁回写失败/重启|同封印重试，确认同身份最终回写|
|锁序|仲裁 hook|只读证据，不反向取 RunStore 写门|

当前唯一写者串行处理共同存储/Host协议；源码持续变化且同一推理链紧耦合，临时只读分工净收益不足。稳定整控制包后仍执行独立综合实现后审、当前来源认证、规定全量及关键因果。相关源码/合同/构建条件改变旧证据失效，不重绑历史。
