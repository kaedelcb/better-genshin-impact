# 耐久观察及冻结事实：候选修复

沿用 `usable-delivery-control-recovery-20261003`、原 opening、两次 blocked 前审、原级发现及请求历史。采用交付优先、工作包合批、自动本地提交政策。本段不是独立验收包，不增加纯方案前审，不关闭原四 CONTROL MUST 或其他原级义务。

结果：主体、前置和收尾在每次同原 epoch / job / key / wireRunId / node / occurrence / iteration / attempt 的可信观察后立即合并落盘。之后查询 OCE、延时取消、连接变化或活动态回退不会删除已读终态；退出及效果仍是独立事实。前置/收尾按原键唯一命中后先耐久绑定，核对最新盘上冻结载荷和句柄，再发严格原身份取消；发布失败、身份冲突或所属运行不唯一时禁止取消与补发。

生产 Runner 的恢复/停止入口传入所属 run；旧形状入口从完整可读记录中寻找唯一耐久所属运行，不能把未落盘对象当取消授权。合并更新只改观察字段，保留并发 Note / StopRequested 等字段并 rebase；当前动作引用在 rebase 后保留，避免 Runner 后续状态回写到脱离运行的旧对象。

RunStore 现有门内新增单调事实检查：完整已发送冻结身份、非空既有 job、合法已读终态和已确认退出不得回退；前置/收尾原票据、指纹、有效期、类型及出现保持；收尾可在同一原子事务首次发布退出/效果并移入 CompletionHistory。既有历史记录（含扩展字段）不得删除或替换。主体上一笔已经清偿后创建新节点意图仍允许。本段尚未提供终局释放封印，也未证明 Host 所有释放入口消费资格。

验证过程和失败原件：首次 red 夹具在查询回调中断言，断言被生产瞬态异常捕获，测试无法有界结束；已按创建身份只停止本次私有 testhost，原日志及中止 TRX 保留。red-r2 把读回观察与断言分离，10/10 在旧产品失败。green 初次 11 个失败来自未落盘的旧组件夹具，补齐耐久意图前提并保留结果断言；green-r2 139/139。monotonic-red 16/16 在旧存储校验失败；首次 guard 编译因局部变量同名失败原件保留。monotonic-green-r2 450/4，修复原子清偿资格并增强两项旧夹具：先断言真实 RunStore 拒绝改写，再在私有临时目录显式损坏文件，保留原下游冲突断言；monotonic-green-r3 454/454。最终恢复、扩大与全量结果另见 test-observations.json。

关键 P/F/P 为观察落盘、取消前绑定、单调事实、历史不可删。各项指定 testId / 失败断言及精确源码恢复在 causal-* / record.json。它们是普通受控日志/TRX，非 execution_evidence 认证收据。整控制包固定源码后仍需统一认证、规定回归/关键因果和独立综合实现后审。

随后静态追查发现：停止链处理多个前置时，后一个观察合并/rebase 可能洗掉前一个尚未发布的归一化结果。新反例 multi-red 1/1 实际失败；第一次补丁脚本因 CRLF 锚点不符在写入前中止，multi-green 为原未修版本 464/1，原件保留。Runner 在主体结果/备注之后和每个前置结果之后及时发布，multi-green-r2 465/465；移除逐前置发布的第五项因果亦实际 P/F/P，并逐字节恢复。首次全量 final-full 为该两行修复之前的 2069/原六/2、2077，新增38、删除0、原 testId outcome变化0；它不改称最终修复版全量。最新 full-r2 与确切版本对比另见 test-observations.json。

本段因果不是整个当前冻结域的认证：早四项之后测试增加了实际 delay 取消/10秒 cleanup 预算到期及多前置 rebase 反例；部分测试调用从旧形状所属查找改为显式 run 形状。其突变 subject 哈希和原失败断言仍可复核，但必须保留调用路径/测试版本差异，整包最终认证时按真实新快照补齐需要的当前因果，不能补写旧认证身份。

最终 single-owner-snapshot 修正：旧形状接口原先先读 UnknownFiles 再读 List，现复用 RunStore 同门 ListWithIntegrity，一次快照同时判完整性和唯一所属。owner-snapshot-red 两例为1红/1绿（健康路径实际读了两次，坏记录路径原来已经保守拒绝）；修复后定向见 final-impact。此前 final-full-r2 2070/原六/2，共2078，新增39、删除0、原 outcome变化0；它是这次所属读取修正之前的全量，不能改记为修正后全量或认证。此局部修正后按影响运行当前定向，整个控制包稳定后仍须当前全量与认证后审。

局限：RunStore 的实例门不证明跨进程写入互斥；同一 run/动作对象仍按驱动链串行所有权使用。外部直接损坏文件必须保守拒绝，不能用本段代码宣称跨进程认证。出口标记和退出不是 C17 不可逆效果的实机证明；BGI 收尾 result_unknown 不变。未动真实 User、第三方 JS、.kiro、旧安装或用户程序。构建复用已有专属 products，DeployToBgiTools=false，不复制历史产物。

依赖顺序：耐久观察与原身份单调保护 → 同 prepared Stop 耐久零调用清偿 → RunStore 不可逆终局封印及原身份/三段退出/效果资格 → Host 所有释放入口锁外消费/回写/同封印失败重试 → 等待/暂停/LocalWait、Completing/Unknown 实际停止/只读对账 → 原功能接线和完整交付。该顺序与原 control-plan-v2.md 共用停止/恢复责任，没有分包重置历史。
