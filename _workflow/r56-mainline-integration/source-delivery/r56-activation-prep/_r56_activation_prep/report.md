## 去重核销与材料修正

1. 将 §21.10 启用门归并为 A–F 六个现有前置。真实引用与激活归 A；恢复目标清单归 B；调用检查点归 C；静止窗口归 D；入口状态/回执归 E；路径身份证据归 F。条款重复提及实际消费/生产门时只映射责任面，不复制成多份估工。
2. 将 MarkReferenceUpdateCompleted、MarkActivated 定性为阶段推进 API；它们不执行引用写入或 candidate→active 操作，离线演练使用 Noop quiet-window；不以名称推断真实服务消费者。
3. 区分助手运行恢复与迁移恢复。TaskCenterHost._runs.RecoverOnStart() 属于助手 run ledger 恢复，不调用 MigrationSwitchTransaction.RecoverOnStart()，不能代替迁移恢复。
4. 将真实 User 根路径提供器的用途限制为演练目录隔离/重叠防护证据，不归因为迁移源/目标接线。
5. 组件崩溃演练证明组件可从隔离根恢复，不证明 BGI 实际进程、全部真实写方静止、助手数据域原子回滚或真实入口回执。
6. 词法校验/注入错误和可构造盘符测试不证明真实 UNC、映射盘、SUBST、启用 8.3 环境上的最终目录身份。
7. 总计划 R5 行含重复 R5.6 描述及较早 §24.97–§24.108 指针；原准备批收口时读取的 R5.3 工作树材料出现 §24.124，是未提交旁证。共享计划/索引只记录为主线唯一写者后续评估项，本批不改写。

## 正式消费批最小实施顺序

按依赖顺序在“R5.6 主线迁移集成批”消费，本批不施工：

1. 按权威条款和实际调用面列出引用文件、候选/活动指针、助手引用/激活元数据恢复集合；先做反例夹具，语义争议保留 owner 检查点。
2. 接入真实引用更新服务和 candidate→active 编排；真实副作用成功且可核对后才推进事务阶段；定义写后不明与重试责任。
3. 从真实 Host/VM/运行入口贯穿事务调用者，加入生产检查点，证明实际执行路径受同一门约束；API定义存在不算接线证据。
4. 明确助手工作流/引用/激活状态在快照和恢复中的边界；仅纳入真实依赖清单，禁止猜测迁移整个 RunStore。
5. 静止窗口覆盖真实引用/激活/助手元数据写方、启动恢复和提交后回滚；窗口与事务身份/生命周期绑定，释放、重获、重启及代际变化闭锁。
6. 定义入口回执及失败/确定拒绝/未知/取消责任、重复调用语义；把目标机路径身份验证列入环境门。
7. 在隔离可恢复配置根执行故障/恢复演练，然后按主线要求做定向与助手回归；实机与 R5.8 验收由对应批次执行，不由本包代签。

详见 acceptance.md 和 acceptance-matrix.md。本顺序是准备型，不替代权威设计与 owner 裁决。
