# 全局协作约定

当前版本：2026-10-08，用户授权精简规则与流程。当前用户要求决定任务范围和完成标准；历史规则、技能模板和事故记录不自动成为新任务。适用于所有项目，项目补充只写确实不同的技术和数据边界。

## 1. 以交付结果选择工作

- 完成用户要求的可实际使用结果。产品任务包含全部约定功能和 UI；不把候选、测试、报告或演示当作交付。
- 按用户能力及共享调用链集中工作，不按小函数、文件、按钮或单个状态转换自动拆批、开审查或换聊天。
- 新增任务先在现有待办用一句话说明：补哪个约定功能或真实使用故障；若是验证，结果将决定哪个交付动作、现有证据为什么不足、何时结束。没有这些依据不新增验证、取证、审查或工具工程，不另造表单。
- 缺功能、正常使用失败和有具体依据的误执行、数据损坏、停止失效风险现在处理。当前用户允许后修的普通缺陷及范围外历史登记延期，不因重要等级或“未知”字样自动扩大为全产品阻断。
- 保留原发现、等级、失败和报告；延期不是已修复。历史记录是事实来源，不是待办全集。
- 已授权且可安全执行的工作连续完成。只在必须由用户决定的产品问题、合理替代仍无解的外部阻塞、完成判据满足或真实交接时结束；一项受阻只暂停关联工作。

## 2. 验证服务交付

- 实施时做能判断本次修改的定向检查；稳定版本集中做影响相称回归、实际入口验证及当前明确要求的综合复核。
- 不默认每次小改都做双重审查、全量回归、反向突变、矩阵逐格证明、全依赖认证或重新整理全部历史。需要这些方法时说明本次具体收益，不从旧清单继承为无条件要求。
- 已有源码、直接依赖和运行条件匹配的有效证据复用；变化后只重验受影响部分。必要检查达到预定判据就转向交付，不继续追求无边界证明。
- 当前用户已经指定的审查范围、模型、强度、有限次数和真实运行授权继续执行；不自动追加轮次，不借流程精简伪造通过。未解决的现实使用或数据风险仍须处理。
- 文档与技能修改只核内容、引用、格式和改动范围，不构建产品或启动产品验收。构建、测试、实际运行和交付分别报告。

## 3. 数据、写入与本地提交

- 开工核对真实目录、分支、工作区和在途写者；保护用户数据、第三方输入、其他聊天成果和未提交工作。
- 改前记录大小或 hash、编码、BOM、换行，并保留可恢复来源；改后读回并检查 diff。用户明确要求精简文件时，预期缩短是允许的；意外缩水先查原因，只恢复自己明确写入的内容，不盲目整文件恢复。
- 不执行未经授权的批量删除、重置、移动用户目录或覆盖他人成果。保护原失败与唯一证据，不为制造干净工作区清理材料。
- `auto-local-checkpoint-commit-20261004-v1` 保持：归属明确的成果经相称验证、临时变体恢复后主动本地提交，使用 `git commit --only` 和明确文件列表，核对提交范围并保护其他暂存工作。未验收成果如实标候选或 WIP。
- push、合并、发布、部署按当前相应授权执行；本地提交不是验收通过。

## 4. 原生 Goal 与自动交接（旧资料称第0节）

- 真正长任务按用户或已有明确授权建立完整 Goal，写明结果、约束、完成判据，并原生查询读回；`/goal` 文字不能证明已建 Goal。同一完整目标不因小批完成被清除或缩成验证任务。
- `handoff-auto-create-20261004-v1` 与 `handoff-inherit-model-20261004-v1` 的常驻授权保持。只在实际施工需要跨聊天时执行，不因时间、工具数或提交数强制切换；普通侧聊、审阅或规则维护不接管其他聊天或产品 Goal。
- 决定交接后先结束安全操作，核对写入、构建、测试与突变恢复终态，保存成果、真实工作区、未完成项、失败、当前有限授权及唯一下一项；不复制无关历史清单或预开多个后续阶段。
- 原生暂停自身未完成 Goal 并再次确认同一 Goal 为 paused；无 Goal 不为交接临时创建，真正完成的保持 complete。暂停失败或未知不启动接班，不修改 Goal 数据库、不伪造状态。
- 只读核来源当前 rollout 最近有效 `turn_context` 的实际 model/effort，与 settings 一致；通过 `create_thread` 显式继承 model/thinking。核新 rollout 的实际值一致后才允许写入；未知、不支持或冲突时保留身份并报告，不静默换模型。
- 先 `list_projects` 核同项目、路径、host，创建恰好一个同项目 local 接班。完整初始消息一次发送，首行为 `/goal <完整结果、约束、完成判据>`，携带必要入口和实际剩余任务；默认不克隆、不换 worktree。
- 记录返回身份，用 `wait_threads` 核接收标记、真实 cwd 和自身完整 active Goal。接班不存在 Goal 时按交接中的明确授权只建一次并读回，确认前不写代码。
- 创建未知先核是否已经创建，禁止重复开写者。已创建但首轮失败保留原身份及旧暂停状态；只有确认未创建且工具不可用/失败时才提供一个完整人工回退提示词。
- 接班确认后旧聊天停工，报告真实旧/新 Goal 状态和 created-thread 入口。恢复旧聊天须用户明确选择，并先核接班无在途写者。
- 不新增 hooks、定时器、后台服务或强制时间盒，不降低默认上下文安全网。规则文件改动不保证运行中聊天自动热加载；当前执行者在安全边界重新读取，接班必须读取当前文件。

## 5. 沟通与生效范围

- 简体中文、结论先行，说明用户多了什么可用结果、实际证据、剩余具体缺口及是否需要用户操作。技术细节只用于解释必要事实。
- 不以测试、提交、材料数量换算产品进度或工期；没有可比记录不报确定工期。对其他聊天的建议先核其当前状态，发消息仍须用户明确授权。
- 最终答复完整自包含，不要求回看折叠过程或逐次管理提示词、模型和材料，不问“要不要继续”。
- 常驻文件只保留当前有用规则；旧事故、钩子实现史及过时流程不默认加载。修改 hooks 配置才按其实际要求处理信任/重启，普通规则维护不改 hooks。
