# 槲寄生独立审查

审查服务当前完整产品交付。先读当前需求、用户取舍、项目 AGENTS 和当前实际版本；只执行本次已授权范围。历史任务、重要等级或缺证明标签不自动扩大审查。

## 任务选择

- 用户要求独立意见，或稳定完整版本需要当前明确授权的综合复核时使用。方案未知会影响真实执行/数据时定向评估；常规已知修复不默认先方案审查。
- 当前在途请求及用户指定模型、强度、固定次数保持；槲寄生默认 gpt-6.1-sol/medium，复杂或现实高风险时 high，不自动降配或加轮。
- 先说明本次要决定哪个产品修复/交付结论、必要材料和结束判据。不给每个文件、函数、子 Agent 任务或每次修改自动派审查。

## 独立检查

使用真正独立只读 Agent 或适用只读 CLI。提供当前需求、版本/Git/相关未提交差异、入口、证据和关联原问题；不要提供施工者整段思考代替原材料。

按需追查相关调用方、被调用方、配置、故障恢复和依赖；路径是导航，不是白名单。无需为“全项目可读”一次读完整源码、认证全部依赖或重写全部历史。

真实 User、凭据、无关私密材料不属于读取域。保护源码与现有成果，不操作生产运行、不写原报告，不由主执行者自审冒充独立结果。

报告给出当前结论、发现的根因/实际后果/位置/最小修复验证、覆盖与未知。区分本版阻断、普通 BUG 后修和范围外历史；原发现原级保留，延期不是 closed。相关旧问题按 ID 引用，不要求每次逐 key 重述全历史。

修复闭合依据应能针对原问题层次与根因；真实使用和数据风险不能用分类掩盖。反向突变、全矩阵、认证收据只在具体判别需要时使用，不默认每个断言都做或将格式缺项等同功能坏。

## 来源、复用和结束

保留原始独立报告及实际可用来源/版本，不修改原文、不制造 receipt。旧 pass 只适用于原范围；相关源码/直接依赖/运行条件等价则复用，变化只补受影响部分。

稳定版本集中复核，需要修复的新阻断成批处理并按当前有限授权复查关联部分；不自动开启新的整包前后审或因发现新问题重置额度。无结果不能称通过，检查结束回到产品交付。

## 可选协议

`native_review.py`、`review_process.py`、checkpoint、JSON schema、implementation_proofs、TRX 与 mutation_check 是选用旧工具时的实际协议，不是所有审查或产品修改的默认任务。需要该工具时按实际协议核验，失败/漂移原样保存；不为放行改旧 bundle、owner_policy、历史报告或收据。

通常的独立原始报告、当前版本、相关实际结果即可据实说明结论和局限。使用其他可复核来源不声称得到旧工具认证，也不绕共享存储预算。普通文档/规则修改只核文字、引用和范围。

源方法参照保留原 MIT 许可证和来源记录；上游模板仅在当前任务需要时参考，其默认审查频率不能覆盖用户取舍。相关流程以当前项目交付与审查文档为准。
