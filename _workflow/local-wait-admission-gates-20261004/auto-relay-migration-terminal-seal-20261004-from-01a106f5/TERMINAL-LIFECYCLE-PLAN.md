# Host终局回写与退出

沿原共享包和全部原级open责任；采用delivery-first限定技术修复，不新增独立请求或改历史预算。写集为TaskCenterHost.cs、TaskCenterHost.Admission.cs及既有真实路由测试的加法反例。保护材料外/User/JS/.kiro，生产门关闭。

当前因果假设：Runner业务终态先完成，观察器异步回写未纳入Shutdown等待；Shutdown取消同一令牌并释放租约，后续回写可能取消/失去所有权。原三轮失败保留，不靠sleep或改封印预期。

确定反例经真实面板/移交→节点发送→Runner终态入口，在既有终局读取接缝暂停回写；调用Shutdown后断言其未完成且租约仍归原所有者，再解除屏障，断言所有对应操作TerminalCompleted、真实封印成立、无额外发送。保存隔离run/lease原字节。分别覆盖面板与移交；初始化/读/写失败保持pending不伪成功，Unknown不得强封。

修复方向：每个登记Drive有观察器完成任务，业务任务与完整终局回写是同一受跟踪生命周期；关闭先取消执行和接纳，终局清理使用独立有界取消源，在既有退出预算内等待观察器，终态后再释放所有权。超预算/故障保留耐久责任，不延长现有预算。面板空RunId从实际Runner返回值补准确身份，不能借当前定义猜造。保留册外路径边界，明确检查关闭并发与重复Shutdown。

矩阵：面板/移交×回写前/回写中/完成后关闭；业务Succeeded/Failed/Cancelled对账，Unknown/Interrupted不封；IO读取/写入失败及重开Stop重试；既有三轮拒绝拒绝受理历史、33节点、历史封印、停止与恢复。先新红例，再集中修复；串行Rebuild/定向与共享完整回归、指定断言PFP finally原子恢复SHA、声明面。稳定整链后才真实依赖认证与全源域独立综合后审；普通证据不替代认证/实机。
