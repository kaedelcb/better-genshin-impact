# BetterGI 茶包＋槲寄生：本地交付版本

本目录包含同套 BetterGI 与 Nexus BGI 助手、正式 WPF 调度界面及现有运行资源，可直接使用。全部约定功能的实现已完成本次整版 Sol/high 复核；支持范围的本机实际入口、停止、冷重启与数据保留证据成立。游戏内效果按原约定由用户测试后主动反馈，没有写成已经通过。

## 启动和开始使用

1. 双击本目录的 [启动本机槲寄生.cmd](启动本机槲寄生.cmd)，同时启动匹配的 BetterGI 和助手，无需拼装测试 DLL。BetterGI 也可单独使用公版原生一条龙能力。
2. 打开助手“槲寄生 → 任务中心”。选择流程时核对可见 ID；完整修订和状态在提示信息中。同名流程不会因名称相同成为同一执行目标。
3. 新建或编辑调度列表，通过“＋添加任务”或“资源目录”加入任务、判断和结束节点。保存后执行；普通点击只选中，真实拖动才改时间。流程预览可选择起点。
4. 启动器固定使用当前 E 盘隔离助手数据根，不自动迁入或覆盖现用 D 盘安装及真实 User。使用自己的资源时，在设置确认这份 BetterGI 路径，通过“流程管理 → 连接BGI资源目录”连接。实际账号、兑换码和队友参数由用户配置。

详细的正常旧数据读取、安装/激活、正式回退、停止/对账和恢复步骤见 [启动、迁移与恢复说明](E:/Program%20Files/better-genshin-impact-LCB/Docs/technical/mistletoe-startup-migration-recovery.md)。旧 User 作为只读来源保留；不要手工覆盖整个运行目录或修改运行记录。

## 本版修复与已知边界

- 路径运行被编辑为顺序定义时，恢复明确拒绝不兼容，保留原暂停定义、游标和等待。先停止旧运行再处理新定义，不用新链首替代旧到达。
- 暂停态显式停止完成耐久取消、有效 runstore seal 和原仲裁 TerminalCompleted。封印失败保留责任并报告未完成，允许显式重试，不假记成功。
- 重启使用同一数据根。重启 BGI 后跨 epoch 的旧运行可能被安全拒绝；保留原记录，按停止/对账反馈处理，不手改或把新运行当原运行恢复。
- 取消后个别小卡片/流程图可能保留旧“执行中”标签，以顶部“已取消”、原运行记录和对账结果为准。集合展开后的收拢交互仍需完善；先保存草稿再重新选择流程。普通界面问题登记后修。
- 原 LocalWait corrupt/unsupported 失败、旧报告/等级和历史未决原样保留，不由本次普通本机证据改成通过，不因旧标签重开无关施工。
- 验收载体末尾 id/Id 错误保留为 controller exit1；应用退出0/0/0、Job0、原运行/原操作及User保留由独立补核和整版复核确认，未伪造载体正常终态。
