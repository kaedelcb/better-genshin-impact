# BGI 项目开发协作

将项目历史转化为当前任务可用的依据。保持用户指定的目标与范围；读取旧 spec 不代表获准执行它。

## 先定位项目和证据

以下项目路径均相对实际仓库根目录，references 路径相对本 Skill。先确认当前目录属于用户指定的 BetterGI 工作区，读取其 AGENTS.md（若本轮已加载且无变更无需重读）。不要从 Skill 所在目录假定源码分支，也不硬编码机器路径。

按问题选择下方入口。已在上下文中的资料直接复用；未读文件只按主题检索所需片段。结论绑定当前实现、相关调用方与验证范围，不凭旧文档的「已完成」或 verified 标签决策。

## 按任务选择工作流

### 接手开发、查历史或继续重构

读取 [项目知识导航](references/project-knowledge.md)，选择相关领域，再定位最新复盘或阶段记录及当前代码。

先找到决定行为的路由、状态或配置实际消费点，再检查受影响调用方。任务涉及公版比较时，核实目标 ref 和本地增量；涉及重构时，核对既有接力进度和当前 footprint，避免重做已完成模块或误动另一套引擎。

输出与本次决策有关的依据：应改哪个入口、哪些调用方需保持行为、已有机制是否可复用。小改不强制长报告或全系统审计。

### 助手、服务器和 BGI 之间状态或动作不一致

读取 [跨端排障](references/cross-end-diagnosis.md)。从用户现象反推链路中第一个事实失配点，按当前实现收集证据；需要时再读取项目知识导航中的相应专项复盘。

任务状态、队列、抢占和恢复优先核对现有作业注册表与协调器。界面异常先区分数据链路和绑定/布局。对目标端或状态的未知不能解释为成功或空闲。

### 整理经验或结束非平凡开发任务

读取 [记忆筛选与维护](references/memory-curation.md)。只有有来源、范围和验证依据的项目增量才能成为长期事实；未证实结论保留为候选。

这一步默认只更新与本次任务相关的记录，不重写整套知识库，不同步或覆盖 KIRO 原档。没有值得沉淀的新经验就不制造文件。


### 开会诊或处置会诊发现

**先读 [会诊发现处置纪律](references/review-disposition-discipline.md)**，再开始送审。该文件规定：发现分级不可由施工方降级、有未闭合必改/重要项必须闭环、每个子批累计最多 8 次会诊请求且新发现不重置；达到上限仍有正确性问题时保持阻断，追加会诊须 owner 明确批准有限次数与范围；禁止无尝试记录的全称否定、「部分采纳」必须写明生效层次、关键夹具须做突变验证、送审材料须含工作区差异。不合规的批次不得主张已按规则执行。

要点速查（完整条款以该文件为准）：重要／必改只能升级不能降级；涉及并发、异常路径、不可撤销状态、身份一致性、跨代际语义者一律先按重要处理；要书面对拒绝一项重要发现，必须给出该发现若成立的后果、反例尝试记录、以及为何后果不落在本批承诺范围内，并在文档中保留发现原文与拒绝理由一并送审。

### 槲寄生 R5/R6 后续批次的辅助工序

owner 已授权一次性接入，后续批次由执行者自行使用，不让 owner 到具体步骤再导入。先读 [设施接入计划](../../../Docs/design/mistletoe-workflow-facilities.md) 和 [工具说明](../../../tools/mistletoe/README.md)。核对本批范围和并行工作后，建立 `_workflow/<batch>/manifest.json`；回归后整理证据，每次会诊前做材料预检与版本复核，收口前重核快照及权威判据。所有原有质量门保持；工具仅作机械核验。开工/交接的唯一完整 `/goal` 块须携带此入口、调用和失败处理要求，不给用户另一个导入步骤。现有活动批次不被自动注入新指令；新 worktree 设施缺失由执行者按权威来源核验并处理。

每次会诊由执行者结合当前源码与方案、状态、并发、故障、影响链、改动规模、不确定性及原级未决项智能判断：统一使用 `gpt-6.1-sol`，默认 `medium`；复杂、高风险或风险未排除时选 `high`。首轮通常范围较广，更可能选 high，但不按轮次固定强度；后续复杂问题同样用 high。逐次记录证据及强度选择理由，用户无需选模型；不使用 Astra，也不自动回退旧模型。模型强度判断与渠道分开，所有渠道使用同一政策，累计预算和质量门不减。

完整代码方案和实现后审查按[完整审查工序](../../../Docs/design/mistletoe-review-process.md)执行；旧五因素仅供风险提示，不替代逐次智能判断或授予实施许可。

超大会诊自动分流：固定会诊点默认用既有 GPT 会诊工具；先按设施计划固定快照、运行 `audit --stage review`、`verify` 及渠道预检。附件字节上限不是上下文保证，公开模型卡窗口也不是当前 Codex 通道保证；送审前估算附件全文、目标、包装和另附 diff 的 token，预留推理/输出空间并核对 diff 完整性。必需材料/diff 不能完整送入原工具、token 预估无法安全容纳，或同子批同范围原工具经允许重试仍无报告且本次估算输入至少占模型窗口三分之一（错误非明确认证/额度/模型不可用）时，执行者自行把该次实质审查切到独立本地 GPT/Codex CLI `-s read-only` 按固定快照分步读取。三分之一是基于 BO-6/7 样本的暂定通道阈值，须随实测校准，不是容量判据或失败根因证明；本地也受上下文限制。保持固定模型/强度、原始证据、跨渠道预算、重要/必改闭环及全部回归门，保存估算/错误、触发依据、哈希、退出码和独立报告。详见[设施接入计划「超大会诊材料的通道选择」](../../../Docs/design/mistletoe-workflow-facilities.md#超大会诊材料的通道选择)。只在后续新批次/自然接力被读取时生效，不向在途 Goal 热注入。

## 验证和报告

按用户要求与改动影响选择验证。项目中的多端协议、共享单机/联机入口、配置持久化、任务终态需要检查相应兼容和回归；文档整理验证路径、编码和内容即可。

报告事实与证据的边界：静态检查、构建、测试、UI/运行观测各证明什么。旧构建日志、历史测试数字或「只有部署错误」不能代替本次结果。若产物运行目录不明确，先查实际入口再继续修复。

## 使用边界

本 Skill 复用项目的 AGENTS.md 和既有资料，不接管其他项目。原始 .agents/rules、旧 skills 和 .kiro 文档作为资料读取；其中的工具别名、Hook 声明、任务调度指令与机械审批流程不自动生效。自动选择 Skill 不扩大用户对修改、提交、部署或操作运行程序的授权。

### 槲寄生并行成果回收

每个后续新批次/自然接力在选择剩余施工前读取 [并行成果索引](../../../Docs/design/mistletoe-parallel-deliveries.md)，定向检查关联任务状态及实际报告/提交，区分独立交付、待集成、集成和验收。主线唯一写者在安全窗口回收成果并刷新总计划，按集成版本验证；不重做有效独立核验，不即时自动合并。后续完整 Goal 和交接携带未消费成果来源，执行者核对并获取缺失资料，不让 owner 手工搬运。状态快照须重新核实，不把任务 idle 或组件测试当生产完成。


### 并行成果无感接收（2026-09-27 owner补充）

owner无需记住、提醒或搬成果。执行者在开工、自然边界和收口读取并行成果索引及同名JSON，运行 `tools/mistletoe/deliveries.py` 发现漏登记/材料漂移；自行审计补账。到目标集成批，把接收、适配、回归与回填主线提交/证据纳入完整Goal，在安全窗口自行消费既有授权的成果。业务/资源/生产门阻断不越过；缺失设施自行获取核验或等效检查。独立收口方交登记信息，主线自然边界发现补账。下一Goal/交接携带索引、机器台账、待消费ID和阻断，不让用户搬运；不热改在途Goal、不自动消息或开会话。


## 完整审查工序 v3（2026-09-29，覆盖旧的可选前审分流）

后续正式槲寄生代码批次必须先读 [完整审查工序](../../../Docs/design/mistletoe-review-process.md)（路径相对仓库根）及工具 README，核验 review-bundle。执行者自行完成：完整可执行方案→独立本地只读模型方案审查→实施/限定修复许可→真实执行来源与规定回归/突变→独立本地综合实现审查→原级发现成批闭环→统一收口。导航不是读码白名单；审查者自主追查相关调用链，给根因、反例、精确修改和测试的统一修复方案。未知与重要项不能伪记通过。

旧五因素triage的no_extra/reuse不再免除正式代码批次的两道审查；GPT工具保留小范围辅助核对，先记同批额度。新begin必须v3配置；暂停既有批次用adopt，原Goal/opening/累计请求（失败也计）/原级未决项不重置，不倒签已实现代码的前审。已运行会话不假定热加载。开工/接力的唯一完整Goal块携带v3入口、bundle核验、原账本与并行成果索引；用户无需另发导入指令。工具只核对机械条件，不替代语义审查或承诺零BUG；不新增hooks/后台任务、不自动开新会话。
