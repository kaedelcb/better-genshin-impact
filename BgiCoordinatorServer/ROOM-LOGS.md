# 每日房间卡片与日志下载

管理页新增“每日房间记录”：选择北京时间日期，按 **助手房间 → 锄地大房间（完整批次）→ 世界小房间** 展示。批次显示真实批次 ID、参与成员、结果和开锄时间；小房间显示六位房间号、房主及建房／结束时间。批次未创建世界房间也会保留记录；房间结束、成员离线或服务器重启后仍可按日期查找。搜索支持助手号、小房间号、批次 ID、成员姓名和 UID。

每张卡片的日志按钮会自动带入所选日期：助手自身日志、该批次全部已确认关联的世界日志、指定小房间会话日志。默认范围为当天，可在弹窗修改为跨日范围。同码不同会话和同一天不同批次不会混入批次／小房间下载；下载 TXT 内注明实际范围、来源与条数，文件名包含范围标识，方便区别同日多次下载。

旧版关联没有保存批次 ID 的，显示“批次归属未记录”；只有日志文件、没有可信关联的，列为“其他已保存房间日志”，仍能按六位房间号直接下载。未保存的历史不能补造。小房间未记录结束时间时会明确提示，不能据此声称仍在运行。

卡片接口 `GET /api/admin/logs/cards?date=2026-10-27`、日期列表和房间列表只读取持久索引及文件元数据，不再为页面刷新扫描全部日志正文。日期列表不把没有文件的今天冒充为已保存日期。新关联在原 `room-links.jsonl` 中兼容追加批次及房主字段；跨北京时间零点的实际日志会更新会话的最后观察日期。保留这个文件、按日日志和 `hoeing-history/` 即保留卡片数据。

范围下载新增可选参数：`direct=true` 只取此房间号自身日志；`batch=<批次ID>` 取助手房间下确证属于此批次的世界日志；`session=<会话ID>` 取指定世界房间的确切会话。三者互斥，未知批次／会话返回无记录，绝不退回整房间下载。网页默认按房间号直接下载；勾选“同时合并已确认关联的历史世界日志”才执行旧版关联恢复。原来不带过滤参数的 API 保持合并历史的兼容行为。

## 时间范围与保存说明

管理员进入 `/admin`，打开房间的“服务器日志”，或在“历史房间日志”中选择已保存的房间。房间结束、被销毁或服务器重启后仍可下载历史。日期通过日历弹窗选择，小时和分钟通过下拉框选择，不需要手输时间数字。默认今天 00:00—23:59，也可点击“今天全天”或“最近一小时”。统一按北京时间筛选，开始分钟和结束分钟都包含，例如选择 10:00—10:30，会包含 10:30:59.999；支持任意已保存日期及跨日时间范围，不设 31 天上限。下载不受预览的 200 条和内存的 5000 条限制，保留完整消息和异常堆栈。

时间段接口为 `GET /api/admin/rooms/{code}/logs/download?start=2026-10-14T23:59&end=2026-10-15T00:01`，已保存日期接口为 `GET /api/admin/rooms/{code}/logs/dates`，历史房间列表为 `GET /api/admin/logs/rooms`。下载界面和 TXT 显示实际条数、记录首尾、来源房间及保存说明。时间范围无效时明确提示调整，没有匹配记录时提示该范围暂无日志。页面下方最近 200 条始终只是当前进程的实时预览，不代表下载内容或条数。旧 `/logs/today` 接口保留为直接房间日文件兼容接口；正式按钮使用范围下载，按卡片选择限定范围。

旧 `/hub` 和新 `/gateway` 共用可信房间日志作用域，按服务器已登记的连接身份归档，补齐没有房间字段的命令转发、回执和异常。记录服务器日志配置实际启用的级别；不强制打开 Debug/Trace。未处于调用作用域的后台事件仍使用结构化 `RoomCode`、`Code`、`Room`、`Group` 字段。无法确认归属的全服日志不猜测塞入某房间；不收集成员电脑上的 BGI、助手日志。下载接口与监控页使用相同管理员鉴权。

控制房间与每次游戏房间会话的关联持久保存在 `room-links.jsonl`。关联必须有同服务端批次身份与完整参与名单，或游戏完整 UID 名单与已认证控制房间完整配置吻合；不能凭单个共同成员猜测。按控制房间下载时合并这些历次游戏会话，按时间排序，并保留来源房间和会话标识。同一事件有可靠事件 ID 时去重，同码的新游戏会话不会自动归入旧会话。控制端与游戏端若部署在不同服务器，只能导出当前服务器实际保存的记录。

已有按日 TXT 不改写。旧版记录存在明确建房边界、完整权威轮换 UID 名单且能由官方算法对应到实际保存的控制房间时，可恢复历史关联；否则不猜测合并，并提示旧关联缺口。旧记录和没有结束边界的旧会话不能据此宣称历史全量认证。保存阶段漏掉的记录不能靠改变日期或条数上限补回。

`ROOM_LOG_ROOT` 指定日志存放目录，默认在服务内容目录下的 `data/room-logs`，不位于 `wwwroot`。现有 `docker-compose.yml` 已挂载宿主机 `./room-logs`，继续使用原来的 `bash deploy.sh` 部署即可，重建容器后会继续追加、读取同一天的文件。部署时需同步整个服务端源码和更新后的 compose 文件。此改动不主动部署或重启在线房间。

日志文件按天、房间分开持久保存，不自动删除；更新部署时应保留整个日志目录及关联文件。范围下载先固定各文件的读取长度，再以有限内存和临时外排合并，下载开始后的新增记录不混入本次结果。临时下载文件在完成、取消或失败后释放；持久日志和原失败标记保持。目录不可读写或范围内有 `.incomplete` 保存失败标记时明确报错。旧版未保存的历史无法补回；若另有服务器原始日志，应另行核对，不能把少量现存记录标成全天无缺口。

## B 房间工作台（2026-10-29）

监控页沿用助手网页的紫金风格，左侧为房间目录，右侧只展示所选房间。默认进入“实时房间”，可按助手／世界房间和运行状态筛选，查看实际成员、路线、心跳及今日锄地记录。目录与详情在桌面分别滚动，手机改为单列且目录限高；定时刷新保留选择，房间消失时明确提示，不静默跳到另一个房间。

“历史与日志”是单独视图：先选北京时间日期，再选助手房间，右侧展开批次或批次归属未记录的世界组。批次默认收起，世界列表内部滚动；完全未关联的房间单独归组、每页20个。搜索助手／成员时不会展开全部历史，搜索确切批次或世界号时才自动展开相关组。直接输入或选择房间号也可打开日志窗口；批次、会话和直接房间号三种下载语义保持不变。

页面拆分为 admin-monitor.css、admin-monitor-ui.js、admin-monitor-logs.js、admin-monitor-events.js，引用使用站点绝对路径；管理员 CSP 只增加允许本站脚本与样式，不依赖外部 CDN。房间数据继续通过原有管理员鉴权 API 获取，静态文件不包含用户数据。

本次验收：服务端定向67项、前端10项通过；6个助手房间、25条世界记录和至少26个未关联房间的真实隔离服务浏览器验证通过，覆盖默认折叠、目录与世界列表滚动、筛选、选中房间上下文、日期及三类实际下载。使用独立Chromium完成桌面与手机检查；最终发布的页面、四份静态资源及服务程序集与浏览器已验证输入一致。
