# 可选本体模板拾取

自动拾取设置中的“本体模板拾取”开关控制识别方式：关闭使用公版 Paddle/Yap OCR，开启使用模板匹配。默认关闭；升级旧配置不会自动改变原拾取方式。两种方式互斥，各自保留名单配置，随时可以切回公版。

## 使用入口

在“实时触发”页面展开“自动拾取”，开启“本体模板拾取”。下方可设置匹配阈值、二次确认、连点和滚轮间隔，并打开全局模板黑名单。配置组设置中也有独立的“本体模板拾取名单”。

模板名单优先级：组黑名单 > 组白名单 > 全局黑名单 > 有模板即拾取。“调查、烹饪、观察点、七天神像”默认排除；组白名单可以显式放行。原 OCR 黑白名单和模糊名单只用于公版模式，不会因切换模式被删除。

内置资源来自 `origin-mno/mno-version` 的 `56bbb8907`（功能提交 `4450304ef`）：400 份模板，按交互名称去重展示 361 项。额外 PNG 放入 `User/mojang_templates`，遵循该目录 readme，重启后生效。自动收集的未知文字截图写入独立的 `User/mojang_template_captures`；确认名称对应正确后再放入额外模板目录启用。

“测试自动拾取”禁止发送拾取键；识别和耗时输出仍可使用。开启自动截图时仍会生成截图。脚本 `dispatcher.getPickRecords()` 返回交互尝试记录，不能将其当作获得物品成功的凭据。

## 茶包接入边界

保留当前触发器生命周期、脚本租约、输入后端和遮罩实现；模板输入通过 InputHub，每次输入前重新核对原运行会话。公版战斗、茶包战斗、传送和锄地专用模板拾取没有替换实现。

本机组名单沿现有原子保存通道落盘；远程组名单仅修改编辑会话内存，随原“保存并回传”提交，不写本机同名配置组。旧端提交其他组设置且没有新名单字段时，接收端保留已有模板名单。

关闭模板模式不预加载模板，不让新增资源成为原 OCR 模式的启动前置。构建必须包含 `GameTask/AutoPick/Assets/莫版模板.bin` 与 `itemFull.png`；缺失或运行异常会提示并切回公版 OCR。
