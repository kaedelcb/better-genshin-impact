# 联机锄地线路整包运维与升级

日期：2026-11-17。适用于采用 schemaVersion=1 线路包协议的新版 BGI、协调服务器与线路管理网页。

**本文是上线操作说明，不是部署或验收记录。** 源码变更、静态核对、构建成功均不能表示已部署、已安全清退旧安装文件或游戏内效果已通过。上线前必须完成同套服务端、客户端、网页及发行产物的集中验证；本说明不执行部署、迁移、删除或用户脚本。

协议依据：[线路整包实施合同](../design/hoeing-route-packages-20261117.md)。玩家入口：[联机锄地使用教程](../../BetterGenshinImpact/联机锄地使用教程.md)。

## 一、上线条件与配置

### 1. HTTPS 与可信代理

- 生产统一使用受信任证书的 HTTPS 地址；只有 loopback 本机隔离开发例外。管理页、上传页、清单和 ZIP 下载均不得经明文公网 HTTP，客户端不得关闭证书校验。
- 反代与应用保持同源，正确转发 Host、HTTPS scheme 及已有 SignalR/WebSocket 流量；ZIP 使用普通 HTTP 下载，不走 SignalR。外部访问不得直达可伪造转发头的后端端口。
- TLS 在代理终止时，应用必须以**明确的受信任代理 IP**接收转发头，且在 HTTPS 判定、认证及路由包端点前应用。代理覆盖外来 `Forwarded` / `X-Forwarded-*`，只写入自己的可信值；不能信任任意客户端的 `X-Forwarded-Proto: https`，不能以“信任所有代理”或全网放开后端代替接线。
- 服务端使用 `ROUTE_TRUSTED_PROXY_IPS` 配置**逗号分隔的精确代理 IP**，默认空表示不消费 `X-Forwarded-*`。本版仅接收一跳 `X-Forwarded-For` 与 `X-Forwarded-Proto`，两头必须同时存在且数量对称；代理应将它们分别覆盖为实际来源 IP 与 `https`，不保留任意外来转发链。默认信任列表被清空后只信任该配置的 IP，不能填全网或用网段/CIDR 代替精确 IP。也可使用应用端实际 TLS，但仍需校验证书及网络边界。
- 管理员 Cookie 必须在外部 HTTPS 场景下具备安全属性，公共清单返回 `Cache-Control: no-store`；反代不得缓存或改写登录、CSRF、上传、发布/回滚及 current/policy 响应。
- 代理上传体积上限须容纳 128 MiB ZIP（应用自身仍执行上限校验），上传/下载超时覆盖实际线路包大小；转发下载 Range/HEAD，不启用会修改 ZIP 字节的内容转换。排查 413/超时先核代理与应用两端，不提高协议安全上限来掩盖问题。

### 2. 必填环境与持久化

| 配置 | 要求 |
|---|---|
| `HOEING_REQUIRED_CLIENT_VERSION` | 生产允许的**精确完整 BGI 版本字符串**，从本次交付的客户端实际版本读取并逐字核对，包含后缀；不是最低版本、范围、主版本或 alpha 通配。不能把示例版本直接当上线值。 |
| `ROUTE_PACKAGE_ROOT` | 独立线路包持久化根，包含 ZIP、目录元数据、publication、审计等；容器部署须显式绑定持久卷，不能只写容器可写层、临时目录或 wwwroot。 |
| `ROUTE_PACKAGE_MAX_BYTES` | 整个线路包存储的字节额度，默认 `2147483648`（2 GiB），按基线、当前包、仍被轮次引用的历史包及上传临时空间规划；与宿主磁盘余量一起检查，不以循环删历史版绕额度。 |
| `ROUTE_UPLOAD_TOKEN` | 至少 32 字符的独立上传口令，经安全渠道交给上传者。只授予上传草稿权，不得使用管理员密码代替；轮换后旧口令不再可用。 |
| `ROUTE_TRUSTED_PROXY_IPS` | 逗号分隔的精确代理 IP；默认空且不读取转发头。一跳代理须同时覆盖 `X-Forwarded-For` / `X-Forwarded-Proto`，详见前节。 |
| `ADMIN_MONITOR_PASSWORD` | 现有全服监控的管理员密码，沿用其配置和强度要求；不得交给仅负责上传线路的人员或嵌入网页/公开文档。 |
| `ADMIN_MONITOR_KEY_ROOT` | 可选 Cookie 认证密钥目录；容器可显式持久化，隔离验证必须指向自己的临时数据根。未配置保持原有 Data Protection 行为；不要与公开文件目录混用。 |

- 精确版本未配置或无有效已发布线路包时，新联机入口应拒绝开跑，不得“先临时关闭校验”。仅全队版本相同、版本为空或使用通配均不满足准入；重连与开锄也须再验，不能仅在首次入房检查。
- 上述准入只针对合同约定的新联机入口，不借本次上线停用既有其他房间、控制和日志业务。
- 服务端进程仅获所需存储权限；线路包目录不能被静态文件中间件直接暴露，不能与房间日志、用户配置或上传者任意可写目录混用。保留现有日志与其他业务数据卷。
- 将服务版本、精确 BGI 版本、持久卷实际宿主路径/容器挂载点、配额、当前 revision/包 ID 和发行产物摘要记入现有发布记录；不记录密码或 token。
- 服务重启或管理员密码/会话策略变更后，应重新登录；旧 CSRF 不能复用。上传 token 的撤销与管理员会话独立。

## 二、首次上线顺序：先离线部署，再放行

1. **锁定整套产物。** 核对同一协议的客户端、服务端、网页和发行包，确认产品版本与 `HOEING_REQUIRED_CLIENT_VERSION` 一致。确认新包不含旧线路更新器或同名兼容启动器，不把普通 BGI 产品更新器 `BetterGI.update.exe` 误认为要删除的线路工具。
2. **保持新联机入口不对玩家开放。** 在隔离/维护访问下先部署服务端及网页，配置 HTTPS 可信代理、精确版本、上传口令、存储额度和持久卷。保护原房间/控制/日志数据；不使用真实客户端 User 做开发侧验证。
3. **离线分发并准备客户端。** 先把同一精确版本交给全员安装，尚不启动真实联机。升级前由安装使用者核对既有配置组中的 Shell/批处理/PowerShell 步骤并停用旧线路更新命令；不自动改写、迁移或试运行用户脚本。不要复制旧工具来“临时兼容”。
4. **建立首个基线包。** 按第三节在浏览器选文件夹、打包、上传草稿，再由管理员核对并发布。没有首个正式包时，`GET /api/hoeing-routes/current` 应返回 503；这不是空线路、无怪或成功初始化。
5. **验证完整入口。** 在隔离数据根下验证原生独立更新任务、包安装/修复、版本准入、轮次锁定、取消及失败保全、回滚、客户端停止/重启恢复，并定向回归单机/自定义线路及现有管理监控。不以单个 API 200 或构建成功替代这些检查。
6. **完成放行核对后再开放新版联机。** 核 current 返回的包 ID/revision、policy 的精确版本、匿名下载与受限管理员/上传者权限，重启确认持久卷确实恢复状态。旧版、空版本、不匹配包及未初始化必须继续被拒绝。

这是不兼容升级，不允许新旧版本混跑，不提供旧下载源、旧进程/日志协议、同路径启动器或旧 Assets 官方包的静默回退。真实游戏内路线效果由后续实际使用验证，不能由本节开发侧检查冒充通过。

## 三、首个基线文件夹、上传草稿与发布

### 1. 准备文件夹

选择一个专用于发布的文件夹，其内容直接对应 ZIP 根，不再套第二层目录。例如：

```text
基线包目录/
  builtin/
    精英/
      线路一.json
    小怪/
      线路二.json
  pathing/                 （可选，普通选线用的官方线路）
    线路三.json
```

- `builtin/<线路目录名>/...` 必需，至少一个有效线路 JSON；保留中文、变体目录与原文件名。路线 JSON 需包含非空 positions 和合法基础类型，同步点、控制合并及变体依赖须有效。
- 所需 `control.json5` 放在线路目录中，只引用包内相对路径，不得循环；相关引用文件须齐全。元数据不混入会扫描线路的目录。
- 不上传旧更新器目录、EXE/DLL、JS、Shell/批处理/PowerShell 脚本、User、账号配置、records/settings 或第三方 JS assets。不靠压缩后大小较小绕过展开上限。
- ZIP 为 UTF-8 STORE/DEFLATE；压缩包上限 128 MiB、展开实际字节上限 512 MiB、文件数上限 10000。路径越界、绝对路径、反斜线、盘符/ADS、保留名、大小写碰撞、链接、加密或炸弹均应拒绝。

旧目录**不会自动迁移**。线路维护者如需沿用内容，应自行从确认有权发布且完整的线路来源中整理基线，再显式选择新发布文件夹；不能让客户端或服务端扫描真实 User/旧安装目录替自己决定上传内容。

### 2. 上传者上传草稿

1. 用 HTTPS 打开 `/routes/upload`，选择上面的文件夹，填写说明及独立上传 token。浏览器本地将文件夹统一打成一个 ZIP，再以单请求上传；不是逐文件网络同步。
2. 检查网页列出的待上传内容及校验结果。token 不存 localStorage，不粘贴到 URL、截图或日志，不安装外链脚本来辅助上传。
3. 等待服务端完成校验并返回草稿包 ID、SHA-256、大小、文件数/线路数等信息。服务器重算可信元数据；上传者不能指定可信散列或正式版本标签。
4. 交给管理员的是草稿包 ID 与变更说明，不是“已发布成功”。上传者不得访问房间/日志、发布、回滚或取得管理员 Cookie。

上传中断、取消、配额不足或校验失败不应改变 current，服务端回收本次临时文件；不反复重传来掩盖唯一未明故障。超出额度时先按产品保留规则核定可清理的未引用草稿，不能删除正在使用或可能恢复的唯一历史版。

### 3. 管理员审核发布

1. 管理员通过现有登录入口进入 `/admin/routes`，查看草稿详情、相对当前版的新增/修改/删除，核对基线来源、完整性和 `requiredClientVersion` 与本次允许的精确版本。
2. 需要线下复核时用管理下载入口取回单 ZIP；草稿不能被匿名读取。首包尚无 current 时，也需核对其确实包含完整 builtin，而非只含差异文件。
3. 需要修正草稿时，显式从某个历史包选文件/目录恢复，得到**新的草稿副本**，或重新上传整理后的文件夹；原包不变，不能在线改写已发布 ZIP。
4. 发布时填原因并携带当前 `expectedRevision`；首包无 publication 时按页面给出的初始 revision 提交。若遇 409，刷新当前状态、重新看差异再决定，不能盲重试覆盖另一位管理员的发布。
5. 确认发布后 current 的包 ID 与目标一致，revision 增长，查看审计结果。上传返回草稿、点击已发送或页面入队均不是发布终态。

## 四、客户端入口、轮次与失败保护

- 独立任务名称仍为「更新联机锄地线路」，内部改为原生下载、完整校验及安装；已有同名独立任务配置可继续使用。「锄地一条龙（联机）」及旧保存名「锄地一条龙」继续对应原生联机任务，配置键不因清退工具批量改名。
- 开锄前自动准备线路与独立任务使用同一安全安装链路。独立任务可用于首次准备、下轮预更新；它不是用户 Shell 的替代解析器，不会导入或运行用户旧脚本。
- 受管内容位于实际 `Global.UserRoot/AutoHoeingRoutes/current`（默认 `User/AutoHoeingRoutes/current`），含 builtin/pathing；安装状态、事务记录、staging 和 backup 为其兄弟数据，不参与线路扫描。执行中禁止替换；不要手工改名、删锁或把个人文件放进去。
- 完整包先下载到独占暂存位置，核包 SHA-256、大小及完整文件清单、解压安全和内容后才切换。两次目录 rename 不是单一原子操作，异常退出必须依靠持久化事务记录恢复；不将本地版本标签单独作为成功证据。
- 失败应保全原完整目录，但无法满足目标包时必须报失败，不能继续用旧目录冒充目标包，不能当作空世界跳过。修复只能重装锁定包；不能悄悄追 current 或跑旧工具补救。
- 房主在选线和预判前确定包 ID；成员收到房主 pin 后确保同一包，即使自己已预更新。轮次冻结后禁止改包，同一轮、多世界和守护续跑沿用 pin；发布/回滚不热换正在执行的线路。
- 普通单机、自定义绝对路径、本地导入线路、第三方 JS 与用户配置保留原有来源和数据边界，不自动迁入官方目录，不向第三方 main.js 注入代码。

## 五、回滚、保留与灾难恢复

### 1. 线路发布回滚

管理员在 `/admin/routes` 选择**历史已发布包**，检查其精确客户端要求、文件完整性和仍可下载性，填写原因、确认当前 revision 后回滚。回滚生成更大的 revision 并记录审计，不倒退 revision、不重写旧 ZIP。

回滚影响之后新选择的轮次，不能通过修改冻结房间配置强行让在跑玩家换包。若当前包有现实安全/功能故障，应先协调相关任务正常停止，再开始新轮次；不能依靠回滚按钮自动终止所有客户端。仍被任何轮次引用或承担恢复依据的历史包保留，不硬删。

### 2. 包不可用或客户端中断

- 网络、HTTPS、散列/清单校验、磁盘/权限或取消失败：保留明确错误和旧完整内容，停止相关开锄路径；修复条件后重试所需 pin，不降级旧下载源。
- 切换中异常退出：先由客户端按事务记录恢复，确认受管目录和所需 pin 的完整性后再继续；管理员不要给玩家一条递归清空 User 的命令。
- 草稿发布失败：current 应不变；先刷新管理页与审计区分“请求未送达、冲突、成功后响应丢失”，未知不能当失败后无条件再发布。

### 3. 服务端或产品版本回退

- 持久卷备份/恢复按维护窗口取得**一致的完整状态**，包括 ZIP、目录元数据、publication 与审计；在停止相应写入或使用服务支持的一致性机制后操作。不能只还原 current 指针、丢失其 ZIP，不能手工拼接不同时间的目录文件。
- 恢复后在受限访问下核对所有已引用包、SHA-256、完整元数据及下载，再开放新联机；状态未知时保持拒绝，不把 503 改成空成功。
- 回退服务程序/客户端是另一项整套维护操作：先阻止新开锄，确认服务版本、数据格式、精确版本策略及已有轮次兼容，再成套离线切换。不能为让旧客户端连上而清空版本门槛，也不能重新分发旧更新器。不能兼容时保持新版联机关闭，不宣称可无损回退。
- 本次说明不授权操作真实 User、运行目录、旧工具第三方输入或生产持久卷，也不产生自动迁移程序。

## 六、旧工具停用、分发与遗留文件边界

### 已覆盖的分发边界

`.github/workflows/publish.yml`、`tools/local-build/build.py` 和客户端 csproj 已移除 `AutoHoeingUpdater` 复制；本地构建不再把该目录作为待纳入 Git 的额外发行输入。CI 与本地完整组包后拒绝任何名为 `AutoHoeingUpdater` 或 `AutoHoeingUpdater.*` 的残留项，宁可失败也不静默删来源不明的文件。正式独立任务和锄地更新链路均改用原生整包安装，不通过旧 EXE 或其日志判定成功。

仓库保留旧第三方输入，不删除第三方 EXE/源码来换取新包通过。普通产品更新器 `BetterGI.update.exe`、联机助手和用户数据不是本次清退对象；保持原有打包路径及隔离构建/存储回收边界。

### 已安装产品的残留不等于已清退

**停止分发不会保证覆盖安装自动删除 `Tools/AutoHoeingUpdater`。** 以下是安全清退条件，不是当前已存在的自动删除实现：

1. 以确切旧发行版本的受信任发行清单确定历史随包文件相对路径、字节数及 SHA-256，记录其来源；仅凭目录名、扩展名、文件日期或签名相似不能证明归属。
2. 限定使用者确认的实际安装根及 `Tools/AutoHoeingUpdater` 子树，逐层拒绝符号链接、junction/reparse point、路径逃逸和无法确认的硬链接/文件身份。不得扫描全盘或猜测其他安装实例，也不触碰仓库中的第三方输入。
3. 确认相关旧工具已由使用者正常退出且没有活跃写者/引用；不能强杀用户进程解除锁。若占用、权限或状态未知，跳过并明确报告，不能当作清退成功。
4. 删除前再次核对具体文件身份、长度与摘要，仅删除**完全匹配受信任旧清单**的未变随包普通文件；用可防止检查与删除间替换的文件身份方式实施。清单外文件、修改过的 EXE、用户脚本、配置、下载的路线、日志和无法证明归属的数据全部保留，不改名搬走。
5. 不执行遗留工具或脚本来判断版本/卸载。只逐文件处理已核定对象；目录只在确认仍是原目录且为空时删除，禁止 `Remove-Item -Recurse` / `rmtree` 整树清退。
6. 记录清退的绝对路径、原发行依据、结果与保留项。仍留用户内容时提示“程序文件已清退，未知/用户文件保留”，不能笼统报“目录已彻底移除”。旧快捷方式或配置组内的 Shell 命令由使用者核对停用，不能自动替换成兼容启动器。

无法取得可信旧清单时，安全做法是保持旧文件不动并停止调用，或将新版安装到使用者明确选择的新目录；用户数据接续须另行核定，不自动复制/迁移真实 User。不能为了消灭可见残留覆盖用户文件。

### 本次采用的遗留文件策略

- 新版停止调用和分发旧工具，不提供兼容启动器；来源不明或用户修改过的旧目录保持不动，不为消除可见残留加入递归删除规则。保留文件不是保留旧更新协议。
- `Build/kachina.config.json`、`Build/micasetup.json` 的既有安装/覆盖行为未在本次改动中改变，也未作为旧工具安全清退的证据。尤其 `OverlayInstallRemoveExt=exe,dll,pdb` 不是逐文件归属证明，不能据此承诺保全用户改过的旧 EXE，或承诺旧目录已经清空。
- 本次未编写或运行真实安装清退器，未操作实际安装目录或 User。发行包检查通过仅证明新包不含旧工具；旧安装残留不再执行，但不声称自动删除。用户手写 Shell/JS/批处理仍需使用者明确停用，不由宿主自动改写。

## 七、运维排查入口与终态

| 情况 | 正确处理 |
|---|---|
| current 返回 503 | 核服务/策略、持久卷和首个正式包；不当作空线路成功。 |
| 上传 401/403 | 区分上传 token 与管理员 Cookie/CSRF，核权限及口令轮换；不扩大匿名权限。 |
| 发布/回滚返回 409 | 刷新 revision 和差异，重新决策；不盲重试覆盖并行操作。 |
| 上传 413 或超时 | 核代理/应用限制、网络与包真实大小；仍遵守压缩/展开/文件数边界。 |
| 存储额度不足 | 核当前实际占用、引用与保留要求；只按规则清理允许删除的草稿，不删唯一历史恢复包。 |
| 网页显示已上传 | 只代表草稿上传终态；必须另核发布结果、current 的 ID/revision 与审计。 |
| 新包不带旧工具但磁盘仍有旧目录 | 按第六节核归属；不启动、不兼容、不递归删除，保留未知文件并明确未清退范围。 |

如需直接诊断协议，公共接口为 `/api/hoeing-routes/current`、`/api/hoeing-routes/policy`、`/api/hoeing-routes/packages/{id}` 及其 `/download`；管理员目录/差异/审计使用 `/api/admin/routes` 系列接口。上传为 `Content-Type: application/zip` 的单 ZIP 原始 body（非 multipart）；上传者请求携带 `X-Route-Upload-Token`。管理员写请求必须先从 `/api/admin/routes/csrf` 获取当前会话 token 并携带 `X-CSRF-Token`。不要将诊断变成包含口令的可传播 URL 或日志。
