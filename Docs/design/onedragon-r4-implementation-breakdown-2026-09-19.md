## 1. 范围定界

**做**（总计划 §3.3 R4 行 + 审计 §8 R4.1–R4.3 + R3 终审挂账）：

1. WorkflowStore / RunStore 分离的持久化（原子写/备份/修订、坏文件隔离）；
2. 真正的任务中心：流程模型（消费 R1 `mistletoe.workflow` schemaVersion 1）、Planner、Reconciler；
3. 资源抽象落地：龙/配置组/单项任务一律资源，流程只持类型化引用（稳定标识 + 配置修订号）；
4. 通用策略能力（锚点 4）：定时/星期/循环截止/账号前置/兑换码与月卡准备前置/终止动作，全资源类型复用；
5. 启动移交：`enterTaskCenter` 占位 → 真实提交（带身份与结构化回执），防旧节点双发；
6. 结果传播显式通道（R3 终审条件①）：失败/取消/正常跳过区分 + 注册表适配层消费 + 根作业结果聚合规则；
7. 最小任务中心 UI：流程管理（C01）/预览/启动/停止/当前节点/失败原因/运行动作入口；
8. 基础失败/重试/暂停/恢复状态机（§4 执行策略的 R4 部分）。

**不做**（本期明确排除，不随施工蔓延）：

- C12 配置级树脂 / C13 自定义秘境映射 / C14 格子委派（2026-09-18 owner 决策删除不上移）；
- 监控端远程编辑执行端资源配置（锚点 1 保留能力，本期不实现；评审结论见 §2 D14 挂账记录）；
- R5 事项：接管仲裁全入口、事务迁移切换、向旧用户默认切换、User 目录写入（开发验证用独立配置根）；
- 通用可视化执行策略规则表（§4 后续扩展）；同机跨会话控制通道（§1 设计债务）；
- 不照搬启动中心临时定时器充当可恢复任务引擎；**StartupFlowStore 不可作为新 Store 实现模板**（其 Load 失败回空对象、Save 直接 WriteAllText 且吞异常，违反 §3.4 持久化合同）。

## 2. 设计决策定案（D1–D14，含 ASTRA 修订）

| # | 决策 | 定案 |
|---|---|---|
| D1 | 引擎归属 | **独立 `WorkflowRunner`（任务中心引擎）**；删除"StartupFlowRunner 不动"的绝对约束——允许改造**移交适配边界**：移交请求带固定 workflowId + 启动运行/步骤/触发出现身份 + 意图 + CancellationToken，返回 `accepted / alreadyAccepted / rejected` + runId 结构化结果。明确「进入任务中心」语义三选一（立即执行 / 恢复既有运行 / 挂载流程触发器），成功移交后**终止当前启动链及其分支回溯**（已挂载后台触发器生命周期另行定义）。StartupFlowRunner 的节点目录/分支模型/编辑器不动 |
| D2 | 存储位置 | `%APPDATA%/NexusBGI/flows/`（定义）+ `%APPDATA%/NexusBGI/runs/`（运行水位），按 Windows 用户隔离，不走 SignalR 同步；开发验证经**独立配置根注入**，不碰真实 User 目录；Store 全新实现（原子写/备份/修订），不照搬 StartupFlowStore |
| D3 | schema 演进 | 消费 `mistletoe.workflow` schemaVersion 1 原样；新增节点/策略类型按锚点 6 加法扩展。**三级未知处理**：可保留的未知描述性字段→原样往返；未支持的执行类型/必需语义→保留原件、可预览、**阻止执行**并留痕；不兼容语义→升 schemaVersion 单独评审。序列化可扩展不等于旧执行器可忽略新语义 |
| D4 | 单项资源拒绝 | `task.single.native=false` 期间单项资源节点**响亮拒绝**（rejected + 原因），且**运行前预检**——避免先执行账号/兑换等前置副作用才拒绝；不得把同一流程的整龙资源无差别连坐禁用；结果传播通道（R4.7）完成且集成验收过后再开放 |
| D5 | 资源目录 | 经 `ext.hello` capability 门控 + `ext.config.describe` 实时拉取执行端资源目录；本机缓存**仅用于展示降级**（BGI 不可达时显示上次缓存 + 留痕）；**执行时必须重新验证目标能力、epoch 与指定 revision，不静默换最新配置**；旧 BGI 无能力时响亮拒绝不降级重发 |
| D6 | 结果传播与聚合 | BGI 侧：壶/幽境等 Start 吞异常处补**显式执行结果**（失败/取消/正常跳过，含 IntoSereniteaPot false、寻找失败、活动结束），注册表适配层在子项终态提交前消费再传根作业。**根作业结果聚合规则**：失败不能被后续成功覆盖；取消/正常跳过/拒绝/未知分别表达；原生链的继续执行行为与页面展示语义保留（公版一致），**外部严格合同结果与原生展示语义区分**（对照表 B17）。助手侧：Reconciler 以**包含该结果的权威 job 快照**为推进依据，事件仅加速；不把「终态 + 另一条易丢失通道」当两套成功依据 |
| D7 | 对账触发源 | 四类：流程修订事件（UI 编辑/文件变更）、节点终态回调、**生命周期事件（启动恢复/重连/epoch 变化）**、周期 tick 兜底（可取消）；所有触发统一进入**串行状态转换**，不许多个异步回调并发推进。修订默认节点边界生效（执行中叶子不硬切）；显式打断/重排/跳过/插入/暂停后改流走动作 API |
| D8 | 账号/兑换执行点 | 职责划分不变（助手评估、BGI 执行），但**不以"原子方法保留"当作"可调用合同"**：需补**前置动作适配合同**——能力协商、任务身份、可取消执行、真实结果、UID 后置验证、兑换历史复用、月卡及准备动作归属。「前置已执行」事实绑定 run/节点出现/attempt/账号/执行会话，**不信任流程文件中持久化的"已执行"标记**；切号后至资源执行之间防账号上下文被其他任务改变（在 BGI 受保护执行阶段完成前置+验证，或执行边界复验 UID） |
| D9 | v1 语义映射（B5） | `nodes[]` 数组 = 顺序链；顶层 `loop` 归一化为**结构性循环**（非节点策略）；顶层 triggers/terminal 作用于隐式流程根；节点 `strategies[]` 维持各自作用域。`condition.weekdays` = **过滤语义**（在规定运行边界求值，不命中默认跳过该资源，**不阻塞后续节点**），等待只由显式触发/等待语义承担。Planner **惰性推进/有限窗口规划**，不设业务轮次封顶，业务循环仅由退出条件控制。`skipAcrossDays` 须定义计算公式、时区、每轮起点与截止点；区分本地午夜/游戏服 4 点/nextDay/联机宽限（§7.3 时间合同） |
| D10 | 收尾抑制合同（B2） | `execution.suppressConfigCompletionAction` 必须落实接线：经既有 ExecutionScope/严格请求扩展传递本次调用的**收尾权限**，不改标准配置、不临时写 User 文件。整龙引用与展开单项执行只能选一条路径，**展开后不得再跑完整原生链**。奖励检查/通知/关闭动作分别定义归属，不笼统一并关闭。失败/拒绝/未知/手动停止/循环等待中**均不得触发收尾**；收尾请求发送成功 ≠ 收尾完成；结果不确定时不得盲目补发 |
| D11 | RunStore 身份（B3） | 至少持久化：稳定流程身份（workflowId + 定义修订号，**不靠文件名或重算 nodeId 维持身份**）、runId、节点出现身份、循环轮次、attempt、祖先关系、绑定资源/taskId/configRevision/目标实例/epoch、**固定幂等键、提交意图、受理/jobId、观察到的终态、待执行收尾、当前等待条件与下次触发时刻（含触发出现身份）**。**提交前保存提交意图**；回执丢失按既有账本 + job 查询对账；过期/换 epoch/结果不确定 → 显式不确定状态，**不得换新键自动重跑**。R1 入口（C06）种子一次性进入 RunStore 的方式需在 R4.2 设计时说明（v1 样例无入口字段，不能认定 C06 已验证） |
| D12 | 失败/重试/暂停/恢复（I4） | 最小状态机：默认失败行为（跳过该资源继续 / 停止流程，流程级可配）、有界重试（次数封顶，attempt 递增）、停止 ≠ 暂停、跳过当前节点需取消确认、暂停期间修订按锚点 2 节点边界生效。F11/A6 之后不得被下一次 tick 自动重启、不得绕开既有恢复票据另建作业。全入口仲裁归 R5，但 R4 引擎必须**正确消费已有停止/抢占/恢复事实** |
| D13 | 激活三态（I1） | **候选（candidate-ready）只可预览，不代表可生产执行**；R4 集成验证使用独立配置根 + 配套标准产物（验证真实 revision）；正式绑定与激活由 R5 事务迁移完成。manifest 结构化 `blocked` 必须阻止提交。含关机等收尾动作的流程，集成验收须明确执行环境与**替身边界**（不真实关机）。仅解析 + 模拟执行不算「迁移流程纯本机可跑」 |
| D14 | 资源合同表（I2） | R4.3 设计时先冻结资源合同表：资源类型 / 权威标识 / 修订来源 / 目录能力 / 启动能力 / 配置形状 / 缺失引用处理。单项资源须同时绑定所属配置 + 稳定 taskId；组内 int 游标语义独立不变。R1 `ConfigKey`（Name#来源哈希）是迁移映射键，**不是永久资源 ID**，不得混用。**R2/R3 复用纪律**：ExecutionScope 承载执行身份与冻结上下文；TaskConfigurationContract 复用 ID/顺序/启用态/revision 投影（助手不另写解析规则）；ExternalInterfaceConfigurationPlane 统一配置写入面；GroupConfigWriteContract 整组编辑沿用 revision/回执；OneDragonConfigReferenceService 走既有 BGI 引用更新（不构造 VM、不反射写回）。引用失效检测归 R4，迁移引用更新事务归 R5。**远程资源编辑评审挂账**：本期不实现，记录接口边界与延期理由，保留既有远程配置组编辑通道 |

另有两条表述纪律（ASTRA 建议 1/3）：
- 「策略复用」= **同一策略实现、独立策略实例**；跨节点共享可变实例会污染账号/循环/历史状态，复用测试验证实现通用 + 运行状态隔离。
- `prerequisite.account` 等 `sensitive=true` 字段在预览/日志/备份/分享全程脱敏，失败原因与调试日志不打印完整绑定信息。

## 4. 施工顺序（会诊修订）

**R4.0 冻结合同 → R4.1/R4.2 Store ∥ R4.3 资源适配 ∥ R4.7 结果通道 → R4.4 Planner + R4.6 策略实现 → R4.5 Reconciler → R4.8 UI + R4.9 启动移交 → R4.10 真实集成收口。**

理由（ASTRA）：引擎不能建立在未定义的策略与结果语义上；结果通道是真实执行与能力开放的前置，须提前而非排在引擎之后。复杂节点（R4.5 引擎语义、R4.7 通道机制、R4.6 前置适配合同）施工中可加插 ASTRA 会诊。

## 5. 风险登记（开工即带）

- 单项资源节点在 `task.single.native=false` 期间一律拒绝（运行前预检）：含单项引用的迁移流程可预览，执行到该节点 rejected，报告如实显示。
- 流程修订对账并发边界：UI 编辑与引擎消费同进程串行化（D7）；外部编辑器直接改流程文件属不合作写方，靠写前复检发现，不承诺原子 CAS（同 R2 页首口径）。
- R4.7 触及公版容错语义边界：保留 Start 调用外观与原生继续执行行为，只加显式结果通道与外部聚合规则；原生展示语义与外部严格合同结果区分登记。
- 移交边界改造是 R4 自身入口闭环；UI/热键/CLI/v2/ext/网页全面仲裁仍归 R5，不越界施工。
- 监控端远程编辑评审挂账（D14）：本期不实现，R4.8 UI 不预埋破坏该评审结论的假设。
- 既有联机批次/人齐打断/网页控制/远程配置组编辑为不可回归面，R4.10 回归基线逐项覆盖。
- 敏感账号字段全流程脱敏（预览/日志/备份/分享）。
