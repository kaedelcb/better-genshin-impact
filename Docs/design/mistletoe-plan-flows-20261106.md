## 用户行为

- 流程默认折叠为一行，按顺序执行操作。条件、日志等步骤旁直接点击“添加动作”，明确在哪个条件下执行；不让用户选择“主链／插入到／出口”。
- 车道是一个独立任务行，在自己的设置窗内选择寄存器、星期、时间段等条件，命名两条路线。新数据只创建一个内置 decision 的车道节点；只执行一侧，结束后继续下一项。旧的独立选择流程按原身份执行，在 UI 中作为旧车道内部条件显示，不批量改写。
- 日志监听绑定指定任务的实际尝试；监听就绪后派发任务，末尾日志及已接受回调处理完毕才允许出口判断；未知不能当未命中。
- 启动中心上方只放一张运行中触发器卡，默认折叠、统计两个来源；实例很多时卡内滚动。定位、预览、撤销按真实所有者路由。
- 旧端与不支持结构编辑的 Web 入口只读保留新结构；不允许把两条车道降级成顺序全跑或有损保存。

### 狗粮例子现在怎样设置

1. 先把狗粮收集任务 A 加入计划。
2. 添加一个流程，命名“收集时监听”。添加日志触发器，选择“指定任务执行期间”，绑定 A，填写“今天执行B线”。
3. 在该步骤左侧的“日志出现时”旁点击“添加动作”，选择设置寄存器，把 R1 设为 1；在“任务每次开始前”旁添加设置寄存器，把 R1 设为 0。摘要中可以直接核对两组动作。保存后把这行放到 A 前面。
4. 在 A 后添加车道，在车道自身的设置中选择“判断寄存器”，将 R1 选为等于 1；两条路线分别命名为“B 线”“C 线”，保存。这里不会另外生成一个流程任务。
5. 在车道的上方路线添加任务 B，在下方路线添加任务 C；收尾任务放在车道行之后。执行时只会进入一条路线。

不需要日志/寄存器时，可直接添加车道并选择星期或时间条件。例如星期六、星期日走“周末收集”，其他情况走“日常任务”。

## 历史：添加车道入口修正

用户反馈“点击添加车道没有反应”。此前按钮只尝试补配对车道：没有出口流程或已经自动配对时只收起弹层并发状态消息；正常新建场景也没有进入配置。修正为：没有出口时打开带明确提示的出口编辑器，必须选定末端判断后才能应用；已有动作流程可直接补全，成功一次生成是/否两条车道并展开；已有配对时定位展开，避免重复创建。

同时修正模态窗口期间自动保存重建编辑 VM 后，新增流程、编辑流程与车道名称因引用比较而静默丢应用。应用回调按计划与节点稳定身份重绑，目标内容未变可应用；同一目标已改变则在窗口中明确报冲突，保留草稿，不覆盖新内容。
