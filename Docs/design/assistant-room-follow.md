# 助手房间跟随使用说明

房间跟随是默认关闭的独立监视模式。同步指定执行端的房间档案名称、备注、服务器、房间号、成员 UID、预期人数、已确认登录房间和查看页面；不会共享房间密码、执行配置、任务指令或执行权。跟随端仍使用自己已保存的正常房间凭据登录。

## 开启方法

1. 在执行端助手打开「助手房间 → 房间跟随」，勾选「开启房间元数据共享」。
2. 同一台机器、同一 Windows 用户的桌面监控端可以生成本机邀请。不同电脑、不同 Windows 用户及网页端使用 HTTPS 邀请；远程中继地址固定为已更新且可访问的协调服务器 HTTPS 基地址，之后执行端切换业务房间或服务器时不改变此中继。
3. 执行端生成并复制一份邀请，只交给信任的跟随端。每份邀请独立，可在执行端授权列表中撤销。
4. 桌面监控端打开「助手房间 → 房间跟随」，粘贴并保存/替换邀请，再勾选「跟随此执行端（只读）」。网页端打开「助手房间」面板，粘贴 HTTPS 跟随邀请，再勾选「跟随执行端房间」。
5. 跟随状态只有在执行端确认目标房间且本端完成普通登录后才显示已登录。档案、登录和当前查看页面是三种独立状态。

### 首次未知房间的正常授权

若跟随端从未认证目标房间、保存的服务器和房号不匹配或密码已失效，状态显示「登录待授权」，不会复制执行端密码，也不会绕过原房间认证。先关闭跟随，通过原「管理房间」或网页普通登录入口增加/核对该房间，手动完成入房认证，再重新开启跟随。

跟随为只读监视。需要远程操作任务、调整本机配置、编辑执行端任务编排等原功能时，先关闭跟随。执行端的任务明细和编排进度不属于这一只读元数据通道。

## 退出、重启与撤销

- 取消跟随：停止订阅和临时登录，恢复本端原有房间簿、登录和查看页面；原登录若已失效则按正常连接流程显示未确认。
- 桌面跟随偏好和邀请保存在当前 Windows 用户独立保护的文件中，不进入 `assistant-config.json`。
- 网页邀请只保留在当前页面内存中，不新增长期保存的邀请或房间密码。页面刷新后需要重新开启跟随；浏览器原来未勾选记住登录的凭据不会因跟随而被额外写入存储。
- 执行端可关闭共享或撤销特定邀请。断线、共享停止或未确认的切房不会被当作目标登录成功；可显示上一份档案元数据，但成员和登录均为未确认。执行端重新连接现有中继时继续跟随。网页中继的自动重连耗尽后需关闭跟随再重试。

## 协调服务器部署条件与负载

远程跟随需要升级后支持 `/room-follow` 的协调服务器及可用的 HTTPS/WSS；普通 `/gateway` 的房间鉴权保持原状。若使用 HTTPS 反向代理，须将 `/room-follow` 的 WebSocket 路径转发到协调服务器，按现有 `ROUTE_TRUSTED_PROXY_IPS` 精确配置可信代理，正确传入 `X-Forwarded-For` 与 `X-Forwarded-Proto`。不应为了远程跟随关闭证书验证或允许明文 HTTP。本机同 Windows 用户的邀请使用私有命名管道，不增加协调服务器的同步连接。

远程中继按邀请绑定读写通道，仅有订阅需求时发布变化的完整元数据，状态相同不重复发送，不做周期性房间档案查询。中继不将跟随状态写入数据库；单快照上限 64 KiB、同时最多 256 个频道、每频道最多 8 个订阅连接。实际入房和查看成员继续使用原房间连接，会产生正常入房及成员事件开销。

## 开发验证范围

使用隔离配置目录和回环网关，不启动游戏，不读写实际助手配置。主要测试入口为 `RoomFollowRelayTests`、`RoomFollowHubWireTests`、`RoomFollowTransportTests`、`RoomFollowDesktopTests`、`RoomFollowObserverGatewayTests` 和 `BgiCoordinatorServer.Tests/Web/room-follow.test.cjs`。其中桌面真实网关往返确认了普通观察者登录、连续切房、未知房间拒绝及原配置/视图恢复；网页专项确认了浏览器实际主连接切换、原登录记忆保护、迟到事件隔离。浏览器可用 `.claude/launch.json` 的 `room-follow-ui-preview`（配置为本机测试用）或 `BgiCoordinatorServer.Tests/Web/room-follow-preview-server.mjs` 的回环夹具验证桌面/手机布局。隔离的真实 WSS 与可信 HTTPS 反向代理收发由 `BgiCoordinatorServer.Tests/Web/room-follow-https-smoke.cjs` 验证通过；该测试只对本次合成证书建立进程级信任，不改变系统证书存储。生产远程部署仍需按上述条件配置，未连接用户的实际服务器或其他物理电脑。

本次定向验证结果：服务端及原房间认证/切房 40/40、桌面及原房间视图 55/55、真实桌面网关往返 2/2、本机网页资源和授权配对 19/19、相关网页回归 361/361。原控制房间真实连接恢复以及隔离 TLS/WSS 中继两项独立烟测均通过。未运行需要外部 Playwright 模块和独立模拟执行端的旧浏览器脚本；新增网页功能已通过实际浏览器的隔离模拟网关往返及桌面、375px 手机布局检查。未向生产服务部署。
