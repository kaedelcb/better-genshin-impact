# 槲寄生源码工作根与历史资料库机制

## 目的

新源码仓库是唯一开发、构建和提交根。旧目录和外部归档只保存历史资料，不能成为新开发的隐式依赖。历史查询采用按需索引，不在每个任务开始时扫描旧目录。

## 查询策略

默认任务只使用当前源码。只有以下条件之一成立时，才启动一次定向历史查询：

- 改动范围涉及任务中心、流程运行、恢复、停止、迁移或运行数据；
- 用户明确要求追溯历史决策、失败或旧实现；
- 当前源码出现索引中登记的历史风险词或路径。

查询顺序固定为：

1. 读取 [`mistletoe-source-history-index-20261009.json`](mistletoe-source-history-index-20261009.json)；
2. 查当前仓库提交、分支和已迁移的 `refs/archive/*`；
3. 只有索引命中且当前仓库缺材料时，按具体路径读取旧根或外部归档；
4. 把结果在当前 Goal/交接材料中复用，不重复扫描。

禁止把“查询历史”实现成每次全量读取旧目录，也禁止把旧目录文件自动复制进源码工作根。

## Git 历史迁移边界

当前新仓库已保留正常本地分支、标签和任务中心基线，但旧仓库中的 dangling commits、stash、Codex refs 尚未全部提升为新仓库的 `refs/archive/*`。在这些对象完成登记、迁移和读回校验前，旧 Git 根不能删除。

需要保留的旧源码历史应提升为归档 ref；只需要作为审计证据的 `_workflow`、日志和测试材料留在外部归档，不进入源码工作树。

## 删除旧根的条件

旧根只有在下列条件全部满足后才可删除：

- 新源码仓库能独立切换分支、读取历史并完成必要构建；
- 必要的 dangling commits、stash、Codex refs 已迁移或明确归档；
- 仍需保留的历史证据有独立清单、字节数和哈希；
- 依赖旧 Git 根的 worktree 已迁移、退休或明确不再需要；
- 当前任务中心和后续开发不再需要旧根作为回退来源。
