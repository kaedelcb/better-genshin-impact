# 助手房间档案复制与合并导入

本功能用于把一个助手的房间列表复制到另一个桌面助手或浏览器，不建立跟随关系，不需要跟随邀请，不启动额外的服务器中继，也不会自动切换登录房间。

## 操作

1. 在执行端打开「助手房间 → 管理房间」，点击「复制房间簿」，复制全部已保存房间（尚未保存的编辑不包含在内）。
2. 在监控端同一窗口点击「粘贴并合并房间簿」；网页端进入「管理房间 → 浏览器房间 → 粘贴合并」，将同一份房间列表粘贴到文本框后确认合并。普通 HTTP 页面可以手动粘贴，不要求 HTTPS 或浏览器剪贴板权限。
3. 系统按服务器地址及房间号合并：已有房间和原登录信息保持不变，只添加之前没有的房间。重名但不同房间采取独立的本地名称。
4. 新导入房间如果没有本端已保存的密码，在原房间管理中填入本端正常登录所需的凭据，再手动登录或查看。不复制保存的密码、执行端身份授权、联机任务绑定、完成动作、定时设置等私人运行配置。
5. 此后在三个端分别新增、编辑或移除房间；互不影响。执行端以后新增房间时，可以重新复制导入，不覆盖监控端或网页原来的独立数据。

本地房间档案容量为 64 个；服务端原有建房额度不变。导入既不会向服务器创建房间，也不会因为目标档案未认证而自动尝试登录。

## 剪贴板格式

采用版本化 JSON（`kind: nexusbgi-room-book`，`version: 1`），每次最多 64 个房间、256 KiB UTF-8。允许的房间元数据字段为 `name`、`note`、`serverUrl`、`roomCode`、`teamUids`、`expectedHoeingPlayers`。`/hub` 和 `/gateway` 路径后缀按同一个服务器基地址合并，房间号本身区分大小写。不包含房间密码或其他授权信息。请只向信任的人复制显示的房间信息。网页房间簿使用名称、备注、服务器和房间号，队伍 UID 与预期人数由桌面端使用，不额外写入浏览器档案。若当前登录没有勾选记住密码且尚未保存为房间档案，导入中包含该房间时仅将它的档案信息保存，密码仍然只在当前页面有效。

## 验证范围

桌面端使用隔离数据根验证剪贴板白名单、合并与保存、原档案保持、空密码切房拦截和原房间管理；最终 .NET 定向回归 77 项通过。相关浏览器房间管理、命令路由、任务编排和本机网页兼容回归 77 项通过；另在普通 HTTP 隔离浏览器中实际粘贴、合并、核对原登录不变，并检查电脑和 375px 手机布局。真实回环网关的跨服务器同号切换、拒绝后原房间恢复两项集成测试通过。没有连接实际用户房间、修改真实 User、增加服务器中继或推送部署。
