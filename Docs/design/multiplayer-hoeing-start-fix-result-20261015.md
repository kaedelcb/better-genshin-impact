## 最终行为

- 上线锄地、一键锄地和 Web 开始统一使用服务端 BatchId，冻结成员、任务类型、绑定、配置修订和执行端身份。从准备到清理确认都保持 busy；新的普通开始被拒绝时不取消旧批次。
- 全员先做非破坏性资源与能力准备，全部通过后才接管。BGI 在执行根锁内核对准确实例和修订；空闲接管也必须明确提交空目标，不把未知状态当作空闲。
- 每一业务项按 BatchId、成员、索引和恢复次数产生稳定请求键；丢失回执按原键补查，不生成第二次提交。只有服务端授予一次共同恢复；失败、取消和未知不作为完成推进。
- 失败和取消必须确认本批作业退出、票据处理、原计划责任及发送闸门。原任务仍在执行时，只有准确权威身份能证明未接管，才撤销准备登记；已经让位的计划按原作业证据停止和对账，不把 parked 留在后台再报告 cleaned。
- 首线前核对本批固定成员、进入世界、路线同步和本地权威路线映射。拒绝、超时、缺路线都向上失败传播；只有权威确认的空列表才允许空轮。等待进入世界的周期报告先取消并等待退出，再释放 CTS。
- 停止按点击时看到的 BatchId 定位。远端卡片、同 UID 监控端和 Web 都冻结期望身份；延迟旧停止、缺身份停止及离线缓存不能作用于新批次。收尾阶段继续保留执行所有权；发送后收到停止也保留准确后继回执，定向取消并确认退出。恢复作业自然完成时保留真实成功事实，不能强写成取消或阻断下一批。
- 成员卡片显示准备、接管、运行和清理状态；Web 的上次终态放在历史副文案，不遮住当前 BGI 未运行或普通任务状态。
