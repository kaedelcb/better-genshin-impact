# 助手多房间与房间切换

状态：精简版设计稿

## 1. 交付范围

一个助手可保存多个房间档案，同一时刻只在一个控制房间生效。切房只变更连接和房间界面。定时上线、命令上线、开锄和任务执行各自保持独立。

| 正式入口 | 使用方式 | 完成条件 |
|---|---|---|
| 耕地机页 | 从房间下拉框手动选择 | 目标房间入房确认、成员列表刷新并就绪 |
| BGI 配置组 | 添加「切换助手房间」任务，填写本机已保存的唯一房间名称 | 本机助手明确受理后，BGI 可继续执行普通本机任务。后续房间动作等切房结果 |
| 槲寄生启动中心 | 在启动流程中添加「切换助手房间」动作，选择目标房间 | 节点等目标房间就绪后继续，例如再进入任务中心 |
| 槲寄生任务中心 | 通过「添加任务 → 流程」或编辑已有流程，在流程里添加「切换助手房间」动作 | 节点等目标房间就绪，再执行计划的后续步骤 |

四个入口共用助手的切换逻辑。启动中心和任务中心保存目标档案 ID，显示名称和房间号。档案无法解析时明确失败。第一版支持流程主链和普通条件分支。

典型配置组是 `切换到 B → 联机锄地上线 → 切回 A → 日常任务`。B 就绪后才提交 B 的上线。切回 A 等 B 的上线意图或批次结清。期间普通本机任务可继续，B 人齐后仍用现有联机接管和完成后动作。回到 A 时只恢复 A 的连接和界面。

## 2. 房间档案和现有数据

- 每个房间独立保存档案 ID、名称、助手控制服务器地址、房间号、密码、成员 UID、预期开锄人数、耕地机绑定、完成后动作、快捷指令、定时上线、当日触发记录和原有的定时授权状态。BGI 路径、本机身份及启动设置仍为全局设置。不同服务器可以有相同房间号。远程写入按服务器和房间定位，提交时复核仍是当前连接。旧档案沿用此前的服务器地址，无需重填。
- 同版升级时，原单房间设置一次性迁为默认档案，保留原房间号、绑定、定时和当日触发状态，旧锄地历史、日志和备注继续按原房间号查询。迁移可重试，先保留原配置。房间归属无法确认时保留历史并提示核对。仍待确认的定时保持待确认。协议随助手、BGI、服务端同步升级。
- 新房间由服务端登记唯一房间号，成员用该房间号和密码加入。改显示名称保留房间号。默认每个 UID 可创建 5 个房间，本机可保存 5 个档案，服务端只持久化房间基本登记和限额所需信息。这个限额用于防止误建。停用房间需明确操作，房间号和历史归属继续保留。
- 定时上线只在已确认的当前房间执行。切房期间先不提交，超出原有补触发期限或确认已离开时记为跳过。别的房间到点仍保持当前连接。

## 3. 一次切房怎样完成

### 3.1 只受理一条切房请求

- 有切房在等待或执行时，其他入口或运行提交的切房返回「切换忙」。用户可以取消尚未发出的请求，再重新选择。同一 BGI 运行的后续信号留在原链路缓冲中，按 §4.1 逐步提交。
- 独立切房离开原房间时，同步撤回本机尚未开批的上线意图。服务端在批次准入锁内检查本机的批次责任并移除原房间资格，避免离房与本机开批同时成立。已有本机批次、接管票据或清理责任时等待本机结清。队友的上线、收尾和目标房间的任务准入独立处理。
- 单机模式直接明确拒绝切房，原有本机流程照常使用。设置导入和正在提交的配置写入复用已有互斥检查，避免切换中改写档案。F11、本机停止和既有批次清理入口仍可使用。
- 独立切房等待超时便结束请求，尚未离房时留在原房间并提示原因。配置组中明确排在上线之后的切回，保留上线意图，等意图撤回、过期或本机批次结清后再切换。入房使用独立的有界时限。离房或入房结果无法确认时显示「待核对」。尚未提交离房时，取消只结束本次切房请求。

### 3.2 先确认离房，再确认入房和界面

1. 助手先解析目标档案。目标已是当前且已就绪时直接成功。其余情况在首次发出离房请求之前，只保存一条本机记录，包含原房间、目标房间和请求 ID。该记录用于中断后的提示和核对。
2. 服务端明确回复「已离房」后，助手关闭 A 的连接，清掉 A 的成员列表和订阅，显示「正在进入 B」。此时暂停房间操作和定时上线。旧连接、旧房间的回调在应用到界面或提交命令前被拦截。
3. 用 B 的档案入房。业务回执明确接受或拒绝，接受时返回当前连接的全量成员快照。目标暂时只读。应用 B 的房间号、成员和绑定界面后，首次状态上报明确从目标档案取成员状态和配置，由服务端确认该连接在 B 就绪。就绪前冻结命令下发和批次准入。就绪确认后，助手提交当前档案并清除中断记录，节点才可继续。若通知早于本机提交，提交后按当前连接重新核对房间和批次状态。
4. 连接和成员快照都绑定本次会话。正常更新仍走增量，按增量的基准版本匹配，正常跳号照常应用。基准不匹配时合并为一次全量补取。切换成功后统一更新耕地机成员和绑定、标题栏、嘟嘟可的房间订阅以及槲寄生远程入口。

入房和首次状态上报均须得到与本次房间、连接相符的业务结果。收到通用 `ack`、事件已送达或状态已发出时仍应等待业务确认。

服务端命令缓存按房间和 UID 隔离，只向就绪会话投递，执行前再检查当前房间和有效期。对于同一个 UID，已有未清理批次时，其他房间不能为其开批。控制房间的切换沿用现有 BGI 锄地批次和本机任务恢复，切房模块只查询其结果。

### 3.3 异常时停止自动推进

| 情形 | 第一版处理 |
|---|---|
| 等待时取消、F11 停止或超时 | 结束本次未提交的请求，显示原因。已提交到服务端的操作先核对结果，停止后的流程不运行后继 |
| 明确拒绝入 B，确认目标连接已收口且本机在 B 无批次责任 | 将切房结为失败并清除在途记录，保留 A 为最后确认的档案。尝试重连 A 一次。A 也暂时连不上时显示断线，交给原有重连处理。流程后继保持停止 |
| 离房或就绪结果无法确认，或 B 可能已开批 | 保留本机切换记录，显示「切换结果待核对」，暂停相关自动操作。复用现有成员状态、批次查询和 BGI 执行状态核对。确认 B 有责任时先按原流程清理 B，再允许切房。证据不足时保留现状 |
| 助手或相关连接中断后重启、重连 | 等待中的自动切房和信号到此结束。已成功的房间按最后确认的档案重连。若有在途记录，先显示待核对。已开始的联机批次仍用原有恢复路径 |

确认从未离房，或已经安全回到原房间时，清除本次在途记录。「待核对」显示原房间、目标房间和已知结果，并提供「重新检查」。它可查询成员资格及本机联机状态，保留原有停止和清理入口。确认本机不再承担目标房间的未清理批次，且旧连接资格已失效或已安全收口后，用户可重新选房间。

切房模块只保存最后确认的房间以及单条在途记录。服务端在当前会话内处理重复请求和确认结果。双端重启、回执丢失等异常按上表安全收口，原自动切房流程到此结束。

## 4. 三个自动入口如何接入

### 4.1 BGI 配置组

- 复用本机 BGI 与助手之间的 IPC。切房、命令上线分别有自己的信号，按同一活跃配置组运行的顺序交接。BGI 保留一条尚未确认接收的信号，直到助手明确接收或有界超时。下一条房间信号等前一条的接收确认，防止轮询覆盖。接收确认只表示本机已接管请求，网络入房和联机等待由助手处理。助手按本机 IPC 会话和配置组运行保留一条「去 B → 上线 → 回 A」的内存缓冲。预期中的房间连接变更继续沿用这条链路。
- B 确认切房成功后才提交上线，并在发送前复核 B 的房间和连接身份。上线须收到服务端对本次信号在 B 已受理的确认，或确认同一个信号早已在 B 受理。回 A 此时才作为切房请求进入等待，等本轮上线意图或批次结清后执行。轮询和事件通知共用同一请求 ID，关联切房的上线只经这条链路。独立的普通上线沿用原入口。
- 信号携带 BGI 进程实例、运行、步骤和当前 F11 停止版本。助手在接收和提交前核对原实例和停止版本。前序失败、结果未知、另一入口切走、任一端重启、本机 IPC 断开或停止授权无法确认时，结束尚未提交的后续信号并显示原因。接收超时时停止交接后续房间动作，已发出的操作按原请求核对。正常联机让位保留已确认交接的请求，配置组恢复时沿用原结果。无法确认已交接的步骤明确提示中断。普通本机任务按原规则执行。
- 游戏内入队仍走既有白名单和识别路径。各房间绑定的 BGI 配置组明确配置本队的游戏内名单。批次模式的协调房按本轮 UID 准入，游戏内自动同意前用本轮已确认的成员昵称校验。名单缺失、同名或识别不清时暂停自动同意，提示房主核对。单独联机使用现有规则。

### 4.2 槲寄生启动中心和任务中心

- 启动中心将切房登记为独立动作。明确失败、停止、超时或未知时结束本条流程的后继，并显示原因。「进入任务中心执行」只能在前置切房已确认时执行。
- 任务中心沿用「流程」编辑，在动作锁外等切房。切房确认失败时当前流程停止后继并显示原因，结果未知时进入待核对。联机接管时允许任务中心按原机制停驻，让正在进行的批次收尾。批次结束后，同一次运行查询内存中的原请求。停止或跳过当前流程行时先取消它的切房等待。助手重启时，未确认的切房行显示中断或待核对，由用户核对后再操作。
- 依赖该房间的后续上线或远程动作使用切房返回的身份，在最终提交前再次检查。启动中心向任务中心移交这一依赖时沿用同一份身份。本机普通任务照常执行。

## 5. 实施顺序和验收

| 实施顺序 | 完成标准 |
|---|---|
| 房间档案与服务器边界 | 默认房间迁移后可查旧资料，新房档案独立。旧房命令和过期意图无法影响新房，离房与开批互斥 |
| 共用切房与耕地机页 | 手动往返稳定，确认拒绝后可安全回原房间，结果未知时有明确提示，旧成员和旧命令无法进入新房 |
| 接入三个自动入口 | BGI 配置组、槲寄生两个中心接入同一切房逻辑。正常自动往返、联机让位、停止和失败能正确收口 |
| 联调 | 先验证下列关键场景，再整版交付四个入口 |

1. **正常切房与配置隔离**。四个入口都能切房，切后核对房间号、成员、绑定和定时。跨房旧命令及迟到界面更新均被拦截。切房本身不产生上线和任务启动。
2. **正常自动往返**。延迟 B 入房和业务确认，让 BGI 先交接上线及切回信号。确认同链顺序推进、只在 B 上线一次、本机结清后切回 A。覆盖进度卡片显示未运行但本机接管尚未结清的时点，切回请求应继续等待。任务中心等待期间不阻塞联机接管，启动中心切 B 成功后才移交任务中心。
3. **等待与失败**。独立切房可撤回本机等待，原房队友保留各自的上线和清理责任；本机结清后可入 B，后续任务仍按 B 的规则准入。单有通用 `ack` 时不推进后继。明确拒绝入 B 后停止后继，分别验证 A 恢复和 A 暂时断线。另测两入口争用、等待超时和过期意图与开批交错。
4. **停止与中断**。等待时停止或按 F11，重连后已取消请求不执行。丢失离房或就绪确认后重启时，不自动上线、切房或假报成功。已知 B 有批次时先处理 B，停止和清理入口保持可用。
5. **原有功能与数据**。不切房的旧用法继续验证，包括单机流程、配置导入、日常任务恢复、当前房间定时与待确认设置、游戏内白名单和远程控制。升级后的默认房间仍可查旧锄地历史、日志和备注。成员快照正常跳号可更新，实际缺包才补全量。
   - **待机配置**。自动联机使用关闭「仅组队，不跟跑」的配置组，确认可以正常执行。误用已开启该选项的配置组时，协同批次和任务中心仍按现有规则拒绝并显示原因。
   - **多世界轮换**。给 A、B 绑定采用不同白名单顺序的配置组。切到 B 后联机按 B 的白名单顺序轮换，切回 A 后再次联机按 A 的顺序轮换。

## 6. 本版取舍

- 保留四个入口、独立房间档案和正常自动往返。每次切房只有一个待处理请求，用户可取消后重试。
- 房间登记和本机最后确认的房间可跨重启保留。在途异常只保留一条本机核对记录。自动请求、BGI 信号补读和成功后的流程推进只服务于当前运行与连接。
- 双端重启时自动恢复半完成的切房、后台切房排程、多房间常驻监听、以及抢占或自动替换其他切房请求，均留待后续根据实际使用需求再考虑。
