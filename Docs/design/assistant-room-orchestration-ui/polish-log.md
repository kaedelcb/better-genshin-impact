# 任务编排 UI 初稿审核记录

日期：2026-11-25。设计基线：`08be447ef`。范围仅为设计原型，与正式 WPF 程序独立；未接真实服务器或任务。选定方向后的正式稿和实际 WPF 仍须审核。

## 视觉打磨

1. 第一轮实渲染 A：卡片纵向高度偏大，丙及独立房间被首屏下缘截断。调整卡片内边距、元信息布局、连接线说明；默认 1180×860 的推荐版可见全部四个示例房间，最小窗使用内容区滚动而非压缩字号。
2. 第一轮实渲染 B：任务状态单独占行且房间卡片偏高。改为任务名称/类型与状态分栏，保留整张卡底部操作对齐；窄窗改为垂直排列。
3. 第一轮 C：清楚显示选中房间的执行细节，补充独立房间和全部接续动作；不把紧凑路线节点的房间状态误作逐任务状态。
4. 状态全局：区分「当前登录」与「联机执行/等待」；后继准备任务未结束时不把乙的联机标为执行中；补充已停止、失败、未知、无记录，以及边上的切换确认时间、准备任务实际状态和上线受理标识。状态切换时示例诊断栏同步更新。
5. 配置编辑：弹窗标题及取消/保存固定，滚动内容独立；待命折叠任务参数，指定任务展开类型、目标、起点和优先级。编辑任务顺序后保留冻结的旧执行记录，不能用旧列表下标为新配置标记完成。
6. 多房间：每条接续关系明确由源指向目标，独立房间不假装有连线；多个路径、汇合/回环显示对已出现节点的明确引用，不复制节点或覆盖任务文字。

## 原型实际检查

使用本机已安装 Edge + Python Playwright 逐个渲染，而非启动正式助手。所有示例均来自原型内存。

- A/B/C 默认 1180×860、最小 980×720、额外压力尺寸 820×640、375×812：文档及内容区无横向溢出，检查的房间卡、任务行、连线、标题、状态容器无裁切。超过窗口高度时内容区可滚动。
- 五个房间、超长名称与任务名、汇合和回环：三版在 980×720 均未出现水平溢出；有明确的接续引用。
- 三版状态选择、房间弹窗、返回成员视图后重载、进入编排后重载、编辑打开/关闭、选择待命折叠、指定任务与起点展开、保存指定房间且不改变实际登录均通过；未发现 JavaScript pageerror。
- 980×720 滚动完成动作面板后保存按钮可见且可操作；对应 `completion-editor-min.png`。实际 WPF 应继续验证 150%/200% DPI，以及显示器工作区缩小时的弹窗边界。
- 主要状态前景/背景 WCAG 对比值：完成 6.92、执行中 5.95、等待 7.18、未开始 7.47、未知 6.79、已停止 7.21、失败 6.05；正文 13.21，次要正文 7.61，辅助文字 6.10，均大于 4.5:1。状态另有中文及形状标识。
- 设计 lint 默认 Chromium 未安装，使用现有 Edge 运行。通用 lint 提示保留的原助手顶部英文副标题/诊断日志字号及原产品中点式文案小于营销网页标准；本次保持不改原有外壳。实际测量发现编排新增区域个别编号和辅助标签为 11–11.5px，已提高到 12px 后重新跑过上述全部交互和尺寸检查。主要任务文字 14px。未安装任何新浏览器。

## 独立视觉复核与修订

两个独立方向的实际截图复核（`wf_e4922ac8-279`）均认为现有主题一致，推荐 A。逐项处理发现的显示问题：

- 最小窗口原来不易发现还有其他房间：增加可滚动提示，内容区滚动不遮挡保存或顶部导航，预留滚动条宽度。
- 顶部信息汇总按最近确认的各房间状态统计，不显示虚假的整条路线百分比；提升辅助文本对比与图例间距。
- 上线已受理改为独立淡蓝信号图标；无记录采用短横/虚线，与待核对的问号区分。当前房间的准备任务、等待人数、后继失败及切换待核对原因进入醒目的卡内阶段行；仍保持联机绑定逐项真实状态。
- 助手房间标题与任务编排均明确可点击并区分选中，保留原房间列表；该操作只切换视图而非真实登录。未知状态的固定顶栏优先完整房间号，并在概览展示完整最后确认房间。
- 完成动作窗策略与动作在宽窗并列，窄窗自然换行，默认顶部打开，固定标题及按钮区明确提示内容可滚动。`completion-editor.png` 是有意滚到两阶段完成动作位置的截屏，不代表打开时截断顶部字段。

已重新渲染 A/B/C、相关状态和弹窗，重跑前述尺寸、长名称、多房间、回环和实际交互检查，均通过；没有 JavaScript pageerror 或检查容器水平溢出。用户尚未选定正式视觉方向，不将 A 的推荐状态作已确认。

## 用户选定 B 后的修订及二轮复核

用户明确选 B 横向关系图，要求完整删除上方重复标题行、缩放另放，并支持超过三个房间的横向浏览及直接拖动；未来网页版另做。见[方向选择](direction-approved.md)。两条专项设计建议 (`wf_6ec1b24c-959`) 支持固定卡片可读宽度、独立可滚动画布和拖动阈值，按用户最后要求不保留两行标题。

- B 优化版：标题行删除，数量与图例合并，只保留紧凑当前状态条。四个接续房间及第五个独立房间展示；缩放、定位、左右按钮与横向滚动条固定在画布底部。
- 首次渲染发现最小窗会把底部缩放滚走，已改为画布内独立滚动、固定操作条。默认 1180×860 可见三张完整卡片，第四张通过横向拖动访问；最小窗保留滚动条和完整控件。卡片与对应接续动作同步滚动，字体不随房间数量挤小。
- 真实 Edge 交互检查：[默认截图](design-demos/dir-2-v2.png)、[实际左拖到末尾](design-demos/dir-2-v2-dragged.png)、[最小窗口](design-demos/dir-2-v2-min.png)。1180×860 下画布内容宽 1180、视口宽 890，向左拖 260px 后滚动偏移 260，再拖到 290 最大偏移可见第四房间。三房默认窗刚好放下时横条隐藏，980×720 时实际溢出自动显示；五个接续房间（内容宽 1480）均可到达。空图没有横向滚动条。
- 1180×860、980×720、820×640、375×812 的外层均无横向溢出，画布中有意水平/垂直滚动；底部操作条始终可见。长名称、五房间、等待/准备/未知状态无检测到的容器文字溢出。实际鼠标左拖、滚动条、左右按钮、键盘首尾、Shift+滚轮、定位当前、90%–125% 缩放、编辑不误触拖动及页面记忆通过；无 JavaScript pageerror。新增画布状态计数以最近确认的房间状态为依据。
