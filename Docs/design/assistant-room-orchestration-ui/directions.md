# 任务编排方向比较

目标：操作者在不切房、不打开多层窗口的情况下，一眼看懂本机所配置的房间连接、实际登录位置、每个绑定任务的执行状态，以及切房后的普通任务是否执行。所有布局使用同一套助手视觉与虚构示例（甲已完成，乙正在执行，丙未执行，丁未编排），不设计其他产品功能。首屏比较尺寸 1180×860，重点复核 980×720 窗口和长文本。形式由真实的房间接续关系决定。

| 候选 | 版式/设计思路 | 主角与取舍 |
|---|---|---|
| A · 纵向接力图（推荐） | 纵向连续轨道，单个房间展开全部绑定和设置，边上独立显示后续任务 | 阅读顺序与执行顺序一致；长任务、数量多、高 DPI 下自然扩展，修改范围小 |
| B · 横向关系图 | 房间卡片并列，中间箭头独立留槽，下面提供连接动作细节 | 全链空间关系一眼可见；窄窗口自动退为纵向布局 |
| C · 全局路线＋房间详情 | 顶部紧凑房间路线，下方左侧选中房间详细执行，右侧所有房间摘要 | 当前执行优先、能审阅复杂任务；其他节点需点选查看全部绑定 |
| D · 分房状态矩阵 | 房间、任务、状态、完成动作列式对齐 | 多房间比较快速，但图示弱；仅备选 |
| E · 双层关系图 | 当前前后房间一行，其余连接及独立房间下一行 | 关系图有较好密度，但换行连线增加布局成本；仅备选 |
| F · 当前执行聚焦 | 当前房间大卡、下方其余房间按配置路线列出 | 当次任务可见性突出，但跨房关系不如 A/B 直观；仅备选 |

真实参考：现有 MainWindow 的委托卡片、助手房间弹窗、完成动作设置，以及当前仓库已有 WPF 流程图。三个主要候选的差异在信息结构和阅读路径，非换色。外部资料不涉及本机用户数据；当前任务优先使用已存在的产品界面本身作为参考。

方向 A/B/C 用完整交互原型展示。D/E/F 作为缩略图备选。上表及[B 横向优化版](design-demos/dir-2-v2.html)保留历史设计；用户最新[改选 A](direction-approved.md)，正式方向为[A 纵向简洁版](design-demos/dir-1-v2.html)：删除重复标题、适应和缩放工具栏，只保留自然纵向滚动与直接拖动。产品只实现 A，不增加布局切换。
