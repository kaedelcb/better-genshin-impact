## 实现

- 新协议 `hoeing.worldPlan.v1`。游戏协调服务器保存本次计划及每名成员独立随机票据，不依赖助手控制服务与游戏服务部署在一起。
- 全员收取计划并报告本机结果，再全员确认；`Planning/Prepared/Committed/NoWork/Legacy/Aborted` 各有明确意义。查询失败、资源或 CD 损坏不能成为空结果。候选世界先按原顺序截取配置轮数，再排除空世界。
- 预判与正式房主线路上传共用筛选函数；读取实际本地变体的 CD；临近刷新者保守保留。预判不写运行/CD记录。自动更新失败、缺资源和无有效路径点均不能授权跳过世界。
- 若首项仍为 A，直接使用原房；首项为 C 时，所有客户端先隔离源房事件，再登记进入交接。服务端在全员登记后才释放原房，单次操作不触发游戏 F2/退世界。
- C 建房以本次计划幂等；丢回包时重发返回同一码、同一房间实例，补齐广播组。停止后的专用撤销只取消原计划；目标实例校验阻止旧票据影响后继房。
- 游戏入队前核对当前连接、目标房实例、房主 UID 和计划未撤销。旧源房事件永久退役；当前房的合法同步补发仍携带房间码并正常放行。
- 全空结果在源房释放确认后才能正常结算，不伪造全员已进入游戏世界。固定批次的原成员合同和配置组后续任务仍由原结算链处理。
- 缺新能力、旧房主、UID不可靠或预判未知统一走旧流程；不放松原协议、版本或固定批次准入。Legacy 允许按原规则迟到成员取得同一回退决定。
