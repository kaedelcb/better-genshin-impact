# 槲寄生辅助设施：按需使用

2026-10-08 用户授权精简。采用[当前交付流程](../../_workflow/usable-delivery-20261003/DELIVERY-FIRST-POLICY.md)。设施帮助完成选定的产品工作，不再作为每次开工、修改或交接的强制流水线。

## 保留的用途

- 需要检查相关并行成果时读取索引/JSON，核真实终态和输入后复用；准备成果和正式交付分别判断，不让用户搬运。
- 需要固定一次独立审查的版本、保存执行来源或核已有证据时，选择现有适用工具或可复核原始来源。先确定产品问题和结束判据，再选择工具。
- 生成快照、取证及审查材料仍经[共享存储入口](mistletoe-storage-limits.md)，以实际规模预约，复用不可变材料和同套产品；不换目录/预算域绕额度。
- 并行 Agent 用于确有独立收益的只读分析或独立文件工作，保护单一产品写者和运行环境；不为了流程要求凑数量或写决策证明。

## 删除的默认工序

不再要求每次新批次创建 manifest、开工快照、八维表单、状态/并发/故障全矩阵，再执行 begin/audit/verify。也不默认每行绑定 testId、每个关键断言反向突变、每次材料版本变化重新全面认证或审查。

需要上述工具时遵守它的实际协议；未选用不影响安全可行的产品工作。旧机械门不能反向生成新的产品目标；文档/规则维护只校对内容、引用、格式和范围。

## 审查与证据复用

稳定完整版本按[审查流程](mistletoe-review-process.md)及当前有限授权集中复核；有具体理由才新增定向检查。有效源码、直接依赖和运行条件匹配则复用，变化只检查受影响部分，不重复整树复制。

大型材料按需分步读取，保留相关证据，不把附件字节上限或模型公开窗口当作通道保证；不为了传输扩建工具。渠道不适用时记录真实错误，选择现有等价可复核来源；固定模型/强度/次数和授权不变。

## 并行成果发现与回收

相关任务选择、集成边界和交付收口时读取[成果索引](mistletoe-parallel-deliveries.md)及 JSON 的 deliveries/preparations；关联登记漏项由执行者定向核实。独立完成不等于集成，集成不等于验收。历史目录只在有相关成果线索时检索，不每次枚举全部旧包。

## 交接与生效

接班仅携带完整产品目标、当前剩余功能/实际阻断、有效材料、相关未消费成果及有限授权。旧事故工序不再整体注入 Goal，不新开预算，不假标旧义务 closed。

按全局原生 Goal/唯一接班/实际模型继承规则执行；新工作区核真正需要的入口，不复制整库设施。不新增 hooks、定时器、后台服务或强制时间盒，不修改在途其他聊天 Goal。

旧工具代码、协议、原请求、opening、报告及失败保存。此次正文精简不宣称工具已按新协议认证，显式调用仍如实记录版本/机械限制，不能修改旧哈希或收据伪通过。
