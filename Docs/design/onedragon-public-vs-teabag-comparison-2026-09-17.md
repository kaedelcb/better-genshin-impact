## 1. 审查口径

比较分为四类：**共有能力**、**同一功能的实现/行为差异**、**茶包新增编排或工具**、**公版有而茶包缺少/改变的行为**。不能看到字段或方法不同就把整个功能算作茶包独有。例如两版均有“从此处开始执行”、重复任务、每周秘境和指定树脂次数。

本表穷举本轮在一条龙配置、任务项、XAML/后台事件、VM 的直接功能差异，并列出直接调用的游戏任务与配置/IPC/助手/网页衍生差异。颜色/文案/布局等按类别合并；不逐条列每个 Margin 或 using。战斗/传送完整引擎是独立模块，本表列实际受影响的调用和参数，不声称穷举整个茶包版所有游戏算法差异。

“恢复”指恢复公版的一条龙格式/界面/编排行为；**共享游戏执行器仍有独立茶包差异**。因此标准一条龙 JSON 互通，不能推导出所有底层游戏动作完全相同，也不能推导出茶包专用脚本在公版可运行。

## 3. 同一功能的实现或行为差异

| 编号 | 对象 | 公版 | 茶包 | 对审查/迁移的影响 |
|---|---|---|---|---|
| B01 | 任务身份 | `Id: string`，通常 GUID | `Index: int`，找 1–999 可用数字 | 这是标识模型不同，不是有无重复任务的区别 |
| B02 | 保存开关/名称/顺序 | `TaskEnabledList: id→bool` + `TaskDefinitions: id→name` + `TaskOrder` | `TaskEnabledList: int→(bool,name)`，字典枚举顺序承载执行顺序 | 茶包文件不能直接交给公版；转换不能排序数字键 |
| B03 | 从此处开始的数据 | `NextTaskId` 空串为无标记；按 ID 定位，SelectedTask 选中项 | `NextTaskIndex` 0 为无标记；按数字键定位，另受计划选择校验 | 迁移一条标记即可；外部客户端不能继续强转 int |
| B04 | 起点失效回退 | 未找到标记项时日志警告并从头 | 当前茶包也有同类回退 | “失效入口阻止自动激活”是新迁移保护建议，并非公版现有行为；原生是否完全沿用需按模式区分 |
| B05 | 任务/配置自动保存 | 公版重建三件套保存；观察属性变化 | 茶包清理重建 tuple 字典，增加 `_isLoading/_autoRun`、计划匹配和延迟处理；配置拖动回写 IndexId | UI 状态与存储耦合不同，恢复时清理所有旧写入者 |
| B06 | 多选添加任务窗口 | View 的 XAML Popup，返回 `List<string>`；保留重复组 | VM 动态 MessageBox，结果逗号拼接再 Split；1–999 键及 999 项入口限制 | 功能相同，窗口归属/容量/含逗号组名处理不同；批量超容量还需验证 |
| B07 | 单项复制的代码 | 有 `CopyTask`/`DeleteTask`/`SetTaskAsNext` 方法；本基线全仓未找到这些对应 Command 的绑定引用 | 没有同名独立方法；多选重复添加仍存在 | 只能称公版存在方法实现，不能据此宣称公版界面一定有“复制单项”按钮 |
| B08 | 选中项与右键 | 公版 `DockPanel_ContextMenuOpening` 命中测试选中行 | 茶包 `GotFocus` 选中行，菜单/控件布局不同 | 验证右键对准的任务，不能只看命令名称 |
| B09 | 配置列表/删除后选中 | 公版读取目录，回退第一项/默认配置；“按创建时间”注释没有对应显式排序 | 茶包按 IndexId 排、按计划过滤，删除后重编号并选计划内项 | 不把注释当实际排序；跨配置顺序属于计划层 |
| B10 | 重命名 | 公版写新文件再删旧文件，并更新全局选择名 | 茶包先移动旧文件，再改 Name/写回，另验证计划归属 | 同功能、写入事务与失败边界不同 |
| B11 | 秘境选择控件 | 普通下拉选择秘境 | `DomainSelector` 国家/秘境双列，展示奖励；可有“自定义”“事件任务”，选择后收起、防滚轮穿透 | 国家筛选/奖励展示是 UI 差异；自定义执行路由是独立编排增强 |
| B12 | 合成数量识别 | OCR 读取浓缩树脂数量 | 优先 0–5 数字模板，失败 OCR 回退，图像释放方式改变 | 同功能不同识别实现，保留/恢复需实机判断，不迁到助手 |
| B13 | 壶地图点击 | 住宅搜索循环每次新截图；点击前释放按键 | 茶包住宅循环用循环外截图，缩放前移鼠标，等待更长，去掉该释放步骤 | 同功能但存在旧画面风险，见审计 F16；不是“茶包多一个壶任务” |
| B14 | 首领/幽境条目方法组织 | 一条龙 `InitAction` 内联大段委托 | 茶包提为 `RunAutoBossAsync`/`RunAutoStygianAsync` | 标准条目参数来源基本相同；不能把提取方法误算新功能 |
| B15 | JSON 路径与战斗实现 | 各原生任务已有 JSON 分支，各自准备/结束检测 | 茶包秘境/首领/幽境调整路径解析及准备流程，并按开关路由公版/茶包引擎；地脉不同，见 D07 | 保留双引擎边界；不是把“支持 JSON”整体移到槲寄生 |
| B16 | 地脉战后万叶拾取 | 自行切换、CD、长 E、OCR/视觉确认及点击 | 茶包委派共享 `KazuhaCollectExecutor`，读取 RunnerContext 队伍，有显式跳过原因 | 同一拾取功能的复用实现，不属于计划表 |
| B17 | 收尾异常/通知/运行状态 | 公版也存在组异常捕获后继续等处理，但没有茶包的整龙注册表结果合同 | 茶包增加父子作业、进度与来源；若直接沿用“正常返回”会造成假成功 | 问题不全是茶包新造，但接管后必须如实报告；原生继续策略与对外结果分别定义 |
| B18 | CLI 解析方式 | `CommandLineOptions`/Action | VM 直接解析 Environment 参数，茶包额外接连续计划和批次提示 | 公版能力不应删除；扩展参数另设兼容映射 |
| B19 | 页面组织/文本 | 原生单配置布局，XAML 使用 i18n | 茶包任务侧栏+计划/配置界面切换、序号/周期/账号等列、动画/颜色；大量硬编码中文 | 该 XAML 去注释后公版有 129 个 i18n 用法，茶包为 0；恢复要连后台事件一起恢复 |
| B20 | 模型/源码组织 | 配置类相对纯粹 | 茶包静态 AllConfig、UID/绑定 setter 弹 Toast、UI 折叠字段、重复 using、BOM/方法位置差异 | 解析器不能依赖有 UI 副作用的模型；纯格式差异不计新增能力 |

## 5. 公版已有而茶包缺少或改变的部分

| 编号 | 差异 | 公版 | 茶包 | 审查建议 |
|---|---|---|---|---|
| D01 | 每周空队伍/秘境回退 | 空白回退普通 PartyName/DomainName | 直接返回当天字段 | 原生恢复公版；迁移预览标出行为变化 |
| D02 | 每周全局奖励选项 | `SundayWeeklySelectedValue`；单日空/0 经函数回退 | 无该字段；周一至周六默认空串，周日改 `SundayDaySelectedValue` | 公版字段/回退恢复；茶包 UI “留空取全局”提示与当前方法不一致，不能按提示迁移 |
| D03 | 每周秘境日期来源 | `ServerTimeHelper`，4 点日界线 | 本地 DateTime，4 点日界线 | 跨时区会不同；公版地脉日界线两版仍共有，不能把全部星期功能都说成茶包差异 |
| D04 | 原粹 20/40 分项配额 | AutoDomainConfig/Param/ResinUseRecord 有 `OriginalResin20UseCount/OriginalResin40UseCount`，消费路径识别两种名称 | 这两字段及记录构建分支缺少，另有首次奖励界面点击处理 | 它们是共享秘境能力，不能仅用四类字典宣称完整承接；需要单独合同/回归 |

## 7. 字段级核对清单

### 7.1 标准一条龙数据

- 任务结构：公版 `NextTaskId`、`TaskEnabledList<string,bool>`、`TaskOrder`、`TaskDefinitions`；茶包 `NextTaskIndex`、`TaskEnabledList<int,(bool,string)>`。
- 公版有、茶包无：`SundayWeeklySelectedValue`；`SundaySelectedValue` 在茶包对应 `SundayDaySelectedValue`，不能作为两个无关功能处理。
- 茶包额外：`Version`、`IndexId`、`NextConfiguration`、`Period`、`PeriodList`、`EverySelectedValueListConverter`、`ScheduleName`、`CustomDomainList`、`ResinCount`、`SpecifyResinUse`、`GenshinUid`、`AccountBinding`、`AccountBindingCode`。
- 茶包 UI 字段：`IsCraftingResinExpanded`、`IsAutoDomainExpanded`、`IsAutoLeyLineExpanded`、`IsClaimRewardsExpanded`、`IsSereniteaPotExpanded`、`IsCompletionActionExpanded`、`IsBindUidExpanded`。
- 茶包类级耦合：静态 `Config`，`BossEventMarker`/`StygianEventMarker` 常量，旧格式嵌套类。它们不全是普通 JSON 字段，分别处理。
- 同名但默认/类型变化：周一至周六 SelectedValue 公版为 `"0"`、茶包为空；周日同类变化并改名；`SecretTreasureObjects` 在茶包标为可空，弹窗代码仍调用 `.Any()`。
- 其余共有字段组：Name、地区、普通队伍/秘境、每周开关与每日队伍/秘境、AutoBoss 全组、每日奖励队伍、MinResinToKeep、SundayEverySelectedValue、壶传送/商品、全部地脉字段、CompletionAction。不能将它们随旧调度字段删除。

### 7.2 全局及共享任务数据

- AllConfig 的一条龙新增：`SelectedOneDragonFlowPlanName`、`ScheduleList`、`ScheduleLoop`、`CycleTime`、`CycleMode`、`ScheduleLoopSkip`、`ScheduleStartOnTime`、`ScheduleStartTime`、`ContinuousCompletionAction`。
- `SelectedOneDragonFlowConfigName` 公版已有，应保留。`SuspendedTaskContext` 是运行上下文，`AutoDomainEnable` 是共享执行来源分支，不能都当计划持久字段机械搬家。
- AutoDomainConfig 新增 `ResinOrder/ResinCount`，保留共有 SpecifyResinUse、ResinPriorityList、四类标量计数；茶包删除公版 20/40 两个分项。AutoDomainParam/ResinUseRecord 必须对应检查。
- AutoLeyLineOutcropFightConfig 的五个公版局部参数缺口见 D08；这些不在标准一条龙 JSON 内，但影响同一任务的真实运行。
