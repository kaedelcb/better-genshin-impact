# 监控端远程启动中心与任务中心

监控端连接指定执行端后，使用执行端原有的槲寄生页面。顶部增加执行端选择、扫描同机、重新读取和返回监控端按钮。启动中心和任务中心的编辑、运行及管理操作由选中的执行端处理。

## 更新与启动

监控端和执行端的助手都需要更新。使用网络连接时，服务端也需要支持 `center.request` / `center.data` 转发。只更新一端不能获得完整功能。

独立测试包中的 `assistant` 目录包含助手程序和运行依赖，不含用户配置。退出当前 Windows 用户下旧助手后，运行 `启动助手.cmd`。该入口带 `--no-auto-launch`，打开后由使用者手动开始或恢复任务。助手仍使用当前 Windows 用户已有的 `%APPDATA%\NexusBGI` 数据。

同电脑不同 Windows 用户，各自启动自己的助手。不要把某个用户的 `assistant-config.json`、流程目录或运行记录复制给另一用户。

## 连接执行端

两端的玩家 UID、控制房间密码和队伍 UID 列表需要一致。执行端使用执行端模式，监控端使用监控端模式。

同电脑时，可在两端使用单机模式。监控端进入槲寄生，点击“扫描同机”，选择执行端实例，再点击“连接执行端”。本地通道使用 Windows 命名管道，验证房间密码及目标实例，无需网络服务端。发现多个执行端时，必须选择具体实例。

异机时，两端关闭单机模式，连接同一个服务端。在监控端的槲寄生页面选择在线执行端，再点击“连接执行端”。程序根据机器身份选择网络通道。目标未提供机器身份时会明确拒绝，避免猜测通道或转发给错误终端。

目标标签包含执行端名称、玩家 UID 和实例编号前缀。修改配置和按执行按钮前，先核对该标签。

## 编辑与执行

- 启动中心：编辑节点及分支、方案保存/恢复/导入/导出、开机启动设置、选择执行端上的程序路径、立即执行和取消。
- 任务中心：计划新建/删除/恢复、增删与排列配置单、计划设置、资源目录刷新、内部任务启用/排列/起点设置、单项或连续执行、运行控制及历史查看。
- 导入文件从监控端选择，内容传给执行端保存；导出文件保存到监控端选择的位置。
- 程序路径和 BGI 路径从执行端目录中选择。“配置 BGI”保存执行端助手设置，执行端助手重启后使用新的路径。
- 定时器、电子狗、日志触发器、流程图和节点运行态展示执行端状态；人工确认在监控端作答后传回执行端。
- “执行策略”“三方接入”和任务中心高级模式沿用执行端现状；原本规划中的功能仍为规划中。

两端均可编辑，连接监控端不会锁定执行端。监控端保存后，执行端已打开的计划立即同步；执行端保存后，监控端在刷新时同步最新修订（正常连接约 2 秒）。已打开的内部任务窗口随计划资源修订刷新。

同时编辑同一计划时，未保存草稿会保留，自动保存暂停，两端显示冲突提示。点击“读取最新计划”前会确认是否放弃本端未保存修改；读取期间出现新修改时也会保留草稿。请先读取最新内容再重新修改，不需要重启助手。

编辑会自动保存到执行端。保存失败或修订冲突时，草稿保留，并阻止使用未确认配置启动任务。“重新读取”会在确认放弃草稿后读取执行端当前配置。

运行结果未知时，程序保留原请求编号，不自动重发。任务中心的“核对未确认操作”先查询原回执；只有使用者已核对执行端实际状态，才可人工解除阻断。解除阻断不会把旧结果判成成功，也不会立即重发。停止操作可在存在未确认请求时继续使用。

监控端顶部“修改”和配置单旁的“⚙”按钮打开助手原有的“内部任务”窗口，两处沿用同一个窗口。启用、拖动顺序和右键起点操作保存到所选执行端的 BGI；“同步计划引用”和“重新读取 BGI”同样读取或保存该执行端。切换目标或返回本机时关闭原编辑弹窗。

内部任务保存丢失回执时保留原请求身份，显示“保存结果未确认”并阻止重复提交；可通过“核对未确认操作”查询执行端原回执，再重新读取并同步计划引用。执行端计划行换成另一个配置时，即便配置字节相同也拒绝旧编辑请求。

## 当前开发侧验证范围

已验证助手现有 WPF 页面与远程数据绑定、独立执行端进程的配置读写/导入导出/删除、启动流程回执、实例校验和修订冲突。执行端重启后，同一请求返回原回执；内容不同的同编号请求拒绝再次执行。回执文件损坏时，新的写操作被阻止，停止请求仍可到达宿主。

本机服务器与真实助手进程的网络请求链已验证，测试强制选用了网络分支；这不等于两台物理电脑的网络验收。跨 Windows 用户实测由使用者进行。游戏中的执行效果同样由使用者测试反馈。

助手包需要 .NET 8 Windows Desktop 运行时，服务端需要 ASP.NET Core 8 运行时；依赖要求可在各自 `runtimeconfig.json` 中核对。
