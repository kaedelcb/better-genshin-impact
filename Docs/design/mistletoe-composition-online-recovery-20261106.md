# 流程、车道与联机锄地恢复

本轮待办：针对用户“车道内被联机锄地中断后是否能正常恢复”的实际问题，核对新增流程和车道与现有真实接管/续跑协议的结合；修复缺口并验证原路线、原节点、原作业恢复身份与作用域接续，不以普通暂停用例或 Unknown 停驻冒充正常恢复。完成后本地提交，不推送、不部署。

基线：ccc76cfec7a1a0d75769e888c9581841778f6059。源码预检通过；任务中心历史门命中当前路径但无归档条目，不扫描旧源码根。

## 查出的实际缺口

1. 车道判断结果和普通任务节点的持久游标已存在，但此前没有把新流程内部等待、寄存器副作用、后台触发回调接到联机门。只在节点边界等待，不能阻止同一流程内部继续向后执行。
2. 任务日志作用域包住原任务及其整段 OnlineHoeingContinuation，联机期间的相同关键字可能污染原任务。
3. 节点间门关闭后返回停驻会走 Runner finally，撤销本轮监听；重新进入流程时又会因已挂载的本轮实例丢失而进入 Unknown，不能称作正常续接。
4. 流程内部等待退出驱动后，原 Host 空隙准备只挑仍在驱动的运行，可能漏掉已明确联机停驻的流程。相反顺序（先 preparedGap 后流程停驻）也必须保留可恢复的 LocalWaitParking 状态。

## 接线约定

- 联机开始前：先关普通任务发送门，再挂起任务流程副作用并结束本段日志观察。保留已选车道、步骤检查点和已接受但尚未执行的动作，不把联机日志纳入本任务。
- 原任务恢复前：所有实际恢复发送路径都经 Host PreparePlanResumeAsync。在票据、节点和进程身份确认后先重建观察片段，再允许发送恢复命令；重布防完成后再次核对停止与身份，避免异步期间停止后复活。
- 观察门与普通新作业派发门不同：原 A 的续跑日志可以先于恢复 ACK 到达，普通派发门也可能保持关闭到 A 终态保存。因此已确认续跑的原运行必须能消费回调，不能等全部开门后才处理，造成尾部互等。
- 联机结束的一般开门：先布防保留的监视，再真正打开普通发送门，再释放流程步骤与回调等待，最后自动唤醒原停驻计划。
- 已完成步骤和条件子分支记账后不重放；等待保存剩余时间；续接不是新任务开始，不再执行“任务每次开始前”的初始化。普通重试的原规则保持。
- 旧配对车道与新独立车道都通过相同的原节点/出现/轮次/尝试身份恢复。已经选择 B 后，联机期间 R1 或星期改变不重判为 C；B1 不重发，B2 观察续跑作业，随后 B3 和公共后继各执行一次。
- 停止、作业未知、进程身份变化或真实日志覆盖缺失不猜测成功，不重发原任务；受控在线暂停与助手重启丢失现场仍要区分。
- 流程因联机门停驻不属于本地排队裁定。显式停止先保存 StopRequested、清除自动唤醒标记并撤销其作用域；未释放的联机票据继续保留 Unknown 责任，不以“停止请求已登记”冒充全部责任结清。

## 已确认的使用结果

- 独立车道与旧配对车道在B2中断、联机期间R1变0后，仍使用已保存的 branchYes；B1不再次Submit，B2只绑定恢复作业观察，不从头重发；随后B3和D各一次。
- 原作业票据的内部检查点/NextTaskIndex、原submissionKey与jobId保留；恢复job必须匹配原节点、出现、轮次、尝试与进程身份，并实际取得退出证据才推进。
- 流程完成的寄存器写入和内部条件分支不重放，等待保存剩余时间。两个相反时序（先退出驱动再准备接管、先收到gap票据再异步停驻）都能恢复，不把旧联机中断信号当用户停止。
- 原任务联机前已经命中的标记不因恢复attempt变化而被初始化清掉；联机期间相同日志不触发；恢复首日志先于ACK、普通派发门仍关时，回调也可执行并收尾，避免终态/开门互相等待。
- 真实日志同路径、同完整epoch且有来源证明时可以继承有效空续接段；换路径无新证明仍unknown；同PID不同启动身份直接拒绝续接，实时onHit前也校验epoch，防止先误写状态再事后报未知。
- 节点间停驻的显式停止会持久化、撤销作用域，之后开门不复活；有未结票据时保留Unknown责任而不假报结清。宿主退出会在原有关闭预算内撤销保留作用域，不遗留后台写入。

状态类电子狗/条件在恢复后等待新采样，不使用恢复前仍“新鲜”的联机缓存，也不把缺失样本判为否；它仍受实际采样频率约束，不承诺捕获短于采样间隔的全部瞬时变化。
