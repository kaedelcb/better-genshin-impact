# 槲寄生任务中心双模式 UI 重构计划

原始计划：2026-10-09
本次修订：2026-10-10
范围：`MultiplayerHoeingAssistant` 任务中心 UI；`TaskCenterHost`、运行台账、执行准入和停止/恢复合同继续是唯一运行事实来源。

## 本次调整的产品决定

任务中心分为两个明确模式，先完成基础模式，再施工高级模式：

1. **基础模式：茶包版兼容模式**。直接移植茶包版已经可用的“计划表”和“连续一条龙”使用流程，目标是打开旧配置就能看、选、改、保存和运行。基础模式不要求用户理解时间轴、流程节点或判断连线。
2. **高级模式：流程编排模式**。承载新的时间轴、流程节点、判断是/否去向、资源目录、路径和调度编排。它是后续独立扩展，不作为基础模式的前置条件，也不把高级字段塞进基础计划表。

两种模式不是两套执行器：`TaskCenterHost`、`RunStore`、准入、运行身份、暂停/恢复、停止、Unknown 和终态对账继续共用。模式只决定编辑模型、展示入口和可用命令；任何模式都不得绕过宿主自行判断成功或发送任务。

## 当前状态与临时措施

当前用户入口位于 `Views/MistletoePage.xaml`，旧入口装载 `Views/ScheduleListView.xaml`；`MistletoeViewModel` 创建 `TaskCenterPanelViewModel` 并持有 `TaskCenterHost` 的刷新和命令调用。

当前 `ScheduleListView` 已混入时间轴、车道、判断、资源目录和拖放编辑，它应归入高级模式候选，不能继续作为基础模式的实现合同。

本轮仍将 `MistletoeViewModel.IsTaskCenterUiVisible` 设为 `false`：

- 任务中心页签和内容区暂时隐藏；
- `SelectedTabIndex` 不允许切入隐藏页签；
- `TaskCenterHost`、后台刷新和启动中心的 `enterTaskCenter` 交接保留；
- 启动中心、旧计划和连续一条龙的底层能力不因隐藏入口而停用。

这只是重构期间的入口闸门。基础模式完成并通过实际入口验收前，不重新开放任务中心页签。

## 基础模式：先交付的完整功能

基础模式以茶包版旧计划表和连续一条龙的正常使用路径为准，直接借鉴 BGI 现有的一条龙页面、计划表和任务设置 UI。第一版按用户可见功能、字段、按钮、菜单、默认值、禁用条件、起点选择、保存反馈和错误提示一比一复刻；视觉可以接入助手窗口风格，但不能借重新设计删减或改变原有行为。基础模式不引入高级模式的时间轴和流程图概念。

### 计划表

- 选择已有计划；空列表时新建计划；显示计划名称、稳定 ID、修订和当前状态；同名计划不能只靠名称区分。
- 新建、重命名、保存、删除、恢复、整份导入和整份导出；有运行责任时按宿主规则拒绝删除或保留归档。
- 添加和移除资源，调整顺序，设置开始时间、星期/参与状态、循环、跨天、失败处理、完成后动作、账号和前置策略。
- 运行前明确显示“保存后手动开始”；保存不改变已经运行实例的冻结设置。
- 旧计划和旧一条龙配置正常读取；打开不自动转换、不覆盖原文件。真正编辑时保留对应原字节备份，保存和重启后能读回同一计划身份和内容。

### 连续一条龙

- 从基础模式选择原生一条龙配置，保留茶包版的配置单、组和单项任务顺序及其启用/过滤语义。
- 支持茶包版已有的直接开始、从指定项开始、暂停、恢复、停止、跳过/重载以及运行结果展示；不把一条龙拆成高级流程节点。
- 启动中心的 `enterTaskCenter` 默认进入基础模式；同一流程身份在启动中心交接和任务中心直接开始两条入口中保持一致。
- 缺少资源、账号绑定或 BGI 能力时显示明确的不可用/Unknown 原因，不以残留文件或“已发送”冒充执行成功。

### BGI 原生 UI 与命令行合同

- UI 以 `BetterGenshinImpact/View/Pages/OneDragonFlowPage.xaml`、`OneDragonFlowViewModel.cs` 和对应的 `OneDragonTaskItem`/配置模型为逐项参考：左侧配置单和任务列表、任务启用/排序、从此开始、复制/删除/重命名、右键菜单、右侧任务设置和保存反馈都要有对应入口。
- 连续计划的配置单、账号绑定、循环/定时、完成后动作和计划表入口按茶包版语义接入基础模式；不能只复制控件外观而把原有字段变成无效占位。
- 基础模式同步保留 BGI 的两个命令行入口：`BetterGI.exe startOneDragon [配置名]` 和茶包版 `BetterGI.exe startContinuousOneDragon [计划表名]`。后者省略计划表名时使用已持久化的当前基础计划；没有可解析的当前计划、名称不存在或名称不唯一时必须明确失败，不能静默执行第一份配置。
- `startContinuousOneDragon` 进入与基础模式 UI、启动中心相同的 `TaskCenterHost`/`RunStore`/准入和终态链，作业来源标记为 CLI；不得恢复一套绕过宿主的旧黑盒执行器。`startOneDragon` 的单条龙语义继续由 BGI 原生入口保持。
- 用户从 BGI 命令行触发时，BGI 自动拉起或唤醒同一 Windows 会话中的槲寄生助手；助手未就绪、跨会话或无法建立可靠通道时响亮失败，不把命令伪装成已执行。
- BGI 的命令行解析、应用激活、助手 `startBgi` 节点和任务中心入口要统一识别上述参数；命令已受理、已入队、执行中和终态必须分别反馈，Unknown 不能显示成功。

### 基础模式的页面边界

基础模式只需要：按 BGI 现有布局复刻的计划选择/管理区、计划表或顺序任务列表、计划设置区、运行状态卡片、开始/暂停/恢复/停止/核对操作，以及清晰的离线、隔离、不支持和 Unknown 提示。

以下内容不进入基础模式第一版：时间轴拖放、车道覆盖、判断节点和连线、复杂路径编辑、资源目录拖拽编排、迁移演练和高级调度策略。

## 高级模式：后置的流程编排能力

高级模式另设明确入口和页面适配层，后续再接入：

- 0–24 小时/游戏日基准、小时/分钟刻度、时间轴卡片和重叠集合；
- 流程节点、路径、条件判断及是/否去向；
- 资源目录拖放、跨车道任务、路径预览和高级调度；
- 迁移、LocalWait、准入状态、资源修订和诊断工具的独立面板。

高级模式可以只读引用基础模式中的计划、资源或一条龙配置；需要转换或复制时必须由用户明确操作并生成新的模式标记、稳定 ID 和修订，禁止打开高级页面就隐式改写基础计划。高级模式的判断/路径执行语义单独冻结和验收，未冻结前不得反过来限制基础模式。

## 页面与代码分层

### 1. 宿主层

`TaskCenterHost` 继续拥有持久化、执行准入、运行生命周期、停止/恢复、未知状态和终态对账责任。UI 不拼接运行记录、不按名称决定身份、不自行发送任务。

### 2. 模式壳层

新增一个任务中心模式壳，负责：

- 默认打开基础模式；
- 展示基础模式/高级模式的入口和可用状态；
- 保持同一份宿主刷新、运行卡片和结构化回执；
- 不允许高级页面的未完成状态污染基础模式。

### 3. 基础模式适配层

基础模式 ViewModel 负责旧计划表和连续一条龙的兼容投影、编辑草稿、管理命令、启动中心交接和用户文案。它复用现有 `TaskCenterPanelViewModel`、`WorkflowStore`、资源目录和 `CommandExecutor` 的有效能力，但不继续把时间轴/判断后置事件扩大到基础页面。

### 4. 高级模式适配层

高级模式 ViewModel 单独承载时间轴和流程编辑状态。它可以复用宿主和资源服务，但不能把高级草稿当作基础计划直接保存。

## 分阶段实施

### 阶段 A：入口封存（已完成）

以 `IsTaskCenterUiVisible` 作为临时开关，隐藏用户入口但保留宿主、启动中心交接和后台状态能力。完成判据：启动中心及其他页签不受影响，宿主项目编译通过。

### 阶段 B：基础模式合同和兼容投影

在入口保持隐藏时，先冻结茶包版计划表/连续一条龙的字段、命令（含 `startContinuousOneDragon`）、旧配置读取和运行回执；逐项对照 BGI 原生页面和命令行解析/激活路径，按隔离 User 根确认旧计划、原生一条龙、配置组、JS/宏引用和账号/过滤信息的投影。不得先实现时间轴或判断连线来代替这一步。

完成判据：代表性旧计划和旧一条龙能按原身份加载，原文件打开不被覆盖，基础模式的状态能区分 Ready、隔离、不可用和 Unknown。

### 阶段 C：基础模式 UI 移植

按 BGI 原生页面的布局和交互实现基础模式页面和管理入口：计划选择/新建/保存/删除/恢复/互导、顺序任务表、计划设置、旧一条龙选择、运行卡片、命令行启动和宿主动作回执。开始前保存当前草稿；运行实例使用开始时的修订；未知结果只能核对或恢复，不能连续重复开始。

完成判据：不需要时间轴或流程图知识即可完成“打开旧计划 → 修改/保存 → 开始 → 查看进度 → 暂停/恢复/停止/核对”的完整流程。

### 阶段 D：基础模式实际入口验收并开放

使用同一构建产物和隔离 User 根验证：

- 任务中心直接进入基础模式；
- 启动中心 `enterTaskCenter` 交接到同一计划；
- 从 BGI 进程执行 `BetterGI.exe startContinuousOneDragon [计划表名]`，有名按名称选择、无名按当前基础计划选择，并得到同一作业身份和终态回执；
- 连续一条龙的顺序、起点、暂停/恢复/停止和终态回执；
- 保存、退出、重启后的计划/运行记录读回；
- Unknown、停止责任、旧文件备份和数据保留。

以上判据满足后才把 `IsTaskCenterUiVisible` 改为可开放状态。真实 User、游戏效果和发布仍单独验收。

### 阶段 E：高级模式骨架（基础模式交付后）

保留基础模式可用，新增高级模式入口、独立 ViewModel 和最小时间轴/流程骨架。先完成模式标记、草稿隔离、引用/复制规则和只读预览，再施工编辑动作。

### 阶段 F：高级模式功能扩展

按独立完成判据接入时间轴、车道、判断、路径、资源拖放、调度、迁移和 LocalWait。高级模式每次写入都需验证模式隔离、修订冲突、运行身份和旧计划不变；高级功能未完成不得回退或削弱基础模式。

## 当前证据和未完成项

现有源码曾记录宿主定向编译和任务中心筛选测试通过，但这不能替代基础模式的真实入口交付。当前已接入 `startContinuousOneDragon` 的 BGI 参数解析、本机会话命令桥和助手自动拉起/唤醒路径；尚未完成同一产物下的基础模式实际打开、旧配置接续、连续一条龙（含 CLI）、停止/重启和数据保留闭环。原有 Unknown、corrupt/unsupported 停止合同失败继续保留，不能改写为通过。

## 下一项施工

保持入口隐藏，先从现有时间轴候选中拆出基础模式适配层和 BGI 原生布局的简洁顺序任务表；以茶包版旧计划表/连续一条龙和 `startContinuousOneDragon` CLI 为逐项合同，完成旧数据读取、管理、运行控制、命令行兼容桥和启动中心交接。基础模式实际验收通过后，再单独开放高级模式并冻结时间轴、流程和判断语义。

## 保护边界

- 只修改当前源码仓库；旧目录只读，仅按历史索引做定向查询。
- 共享 `TaskCenterHost`、`RunStore`、准入和终态合同，不复制执行器，不向 `main.js` 注入代码。
- 旧 User、计划、第三方 JS、宏和历史失败保持原样；测试使用隔离数据根。
- 不把测试通过、候选高级页面、静态报告或阶段提交写成完整交付。
- 每个阶段只重验受影响的入口和数据路径；基础模式交付不等待高级模式全部完成。
