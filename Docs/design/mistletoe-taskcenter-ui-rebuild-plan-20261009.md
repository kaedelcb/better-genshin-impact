# 任务中心 UI 重构计划

日期：2026-10-09  
范围：`MultiplayerHoeingAssistant` 任务中心 UI；底层任务中心运行链保持为唯一事实来源。

## 目标

把任务中心从当前难以使用的复杂面板，重构成一个先能稳定使用、再逐步扩展的 UI。第一版只承诺基础流程管理和运行控制，优先保证茶包版已有的连续一条龙交接链；高级节点、调度、迁移和等待能力逐项接入，不在第一版把所有能力堆进一个页面。

## 当前状态与临时措施

当前用户入口位于 `Views/MistletoePage.xaml`：顶部“任务中心”页签装载 `Views/ScheduleListView.xaml`。`ViewModels/MistletoeViewModel.cs` 同时创建 `TaskCenterPanelViewModel`，它继续持有 `TaskCenterHost` 的展示刷新和命令调用。

本轮已将 `MistletoeViewModel.IsTaskCenterUiVisible` 设为 `false`：

- 顶部任务中心页签折叠；
- 任务中心内容区即使被程序切到索引 1 也保持折叠；
- `SelectedTabIndex` 拒绝切换到隐藏页签；
- `TaskCenterHost`、后台状态刷新、启动中心的“进入任务中心执行”交接未删除，连续一条龙链路仍由底座处理。

这只是入口闸门，不是底座停用开关。新 UI 完成前，用户仍可使用启动中心和其他已开放功能。

## 底座能力盘点

| 能力 | 当前真实承载 | 重构策略 |
| --- | --- | --- |
| 流程持久化 | `WorkflowStore`，由 `TaskCenterHost.Workflows` 暴露 | 保留，UI 只通过页面适配层调用 |
| 运行记录 | `RunStore`，由 `TaskCenterHost.Runs` 暴露 | 保留 `workflowId`、`revision`、`runId` 身份 |
| 执行驱动 | `WorkflowRunner` + `BgiWorkflowExecutionBoundary` | 不在 UI 重写；先确认入口和状态语义 |
| 启动中心交接 | `MistletoeViewModel.EnterTaskCenterAsync` → `TaskCenterHost.RegisterHandoffAsync` | 作为连续一条龙的回归入口长期保留 |
| 运行控制 | `StartWorkflowAsync`、`ResumeRunAsync`、`RequestRunActionAsync` | UI 只展示宿主返回的结构化结果；Unknown 不显示为成功 |
| 资源/迁移/等待 | `ResourceCatalogService`、迁移组件、LocalWait/准入链 | 作为后续能力模块接入，不阻塞基础页面 |

当前证据说明底座可以继续作为开发基础，但还不能把它写成完整可用交付：宿主项目定向编译为 0 错误；开启测试工程测试目标后，任务中心相关筛选执行 40 项全部通过；尚未完成隔离 User 根上的真实 BGI 入口、连续一条龙、停止/重启和数据保留实机验证。

## 目标 UI 分层

### 1. 宿主层

`TaskCenterHost` 继续拥有持久化、执行准入、运行生命周期、停止/恢复和未知状态责任。UI 不直接拼接运行记录、不自行决定成功或失败，也不把流程名称当作身份。

### 2. 页面适配层

新增任务中心页面 ViewModel 作为 UI 与宿主之间的唯一适配面，负责：

- 页面状态：加载中、空列表、离线、不可用、运行中、未知；
- 流程列表和稳定身份展示；
- 能力开关与命令可用性；
- 结构化操作结果到用户文案的映射；
- 后续功能模块的挂载点。

现有 `TaskCenterPanelViewModel` 和 `ScheduleListView` 先保留作为底座参考，新的页面不继续扩大它们的代码后置事件耦合。

### 3. 基础页面层

第一版页面只包含：

1. 可用流程列表（名称、稳定 ID、修订、状态）；
2. 选中流程的基本信息；
3. 开始/刷新；
4. 当前运行卡片（节点、状态、进度）；
5. 暂停、恢复、停止、核对状态等由宿主判定的动作；
6. 清晰的离线、Unknown、隔离和不支持提示。

第一版暂不把时间轴、复杂节点编辑、迁移演练和高级策略塞入主页面。

## 分阶段实施

### 阶段 A：入口封存（已完成）

以 `IsTaskCenterUiVisible` 作为唯一临时开关。完成判据是任务中心页签和内容均不可见，启动中心及其他页签不受影响，宿主项目编译通过。

### 阶段 B：底座合同冻结与页面骨架

在任务中心仍隐藏时新增页面适配层和最小 XAML 骨架，先接入流程列表、运行快照和结构化命令结果。不得改写 `WorkflowRunner` 或绕过 `TaskCenterHost`。完成判据是隔离数据根中可加载已有流程，页面状态能区分 Ready、隔离、不可用和 Unknown。

### 阶段 C：连续一条龙基础版本

接通“选择已有流程 → 开始 → 观察运行 → 暂停/恢复/停止/核对”的最短闭环，并复用启动中心的 `enterTaskCenter` 交接。完成判据是同一流程身份在启动中心交接和直接开始两条入口中都能得到宿主回执，运行终态和异常不被 UI 改写。

### 阶段 D：基础编辑与数据保护

逐项加入新建、保存、修订冲突提示、导入导出、删除/恢复等基础管理；继续保留未知字段、稳定 ID 和未保存草稿保护。每加入一种写操作，都用隔离数据根做读写回读和重启检查。

### 阶段 E：扩展模块

在页面适配层上按能力接入资源目录、节点/路径编辑、条件分支、调度、迁移、LocalWait 与准入状态。每个模块拥有独立状态和完成判据，避免再次形成一个无法维护的巨型页面。

### 阶段 F：重新开放入口

基础版本完成后才将 `IsTaskCenterUiVisible` 改为可开放状态，并进行同一构建产物的实际入口验证：启动中心连续一条龙、直接开始、暂停/恢复、停止、Unknown 对账、冷重启和数据保留。验证未满足时保持隐藏。

## 保护边界

- 只修改当前源码仓库；旧目录只读，不复制 `_workflow`、User 或构建产物。
- 不把现有测试通过、候选页面或静态报告写成完整交付。
- 先使用隔离数据根验证写入和运行；真实 User、实机迁移和发布仍需单独授权与验收。
- 每个阶段只重验受影响的入口和数据路径，保留原有失败与 Unknown 事实。

## 下一项施工

在隐藏入口保持不变的前提下，创建页面适配层和第一版基础页面骨架；先实现流程列表、运行状态和宿主动作回执，再接入连续一条龙入口，完成后才考虑开放 UI。
