# 槲寄生当前启动入口

2026-10-08 更新：旧 422 故障、ownership/CAS 链、逐小批新 Goal 及固定证明工序已移出活跃提示词。过去的失败仍保存在原记录；它们不能自动生成当前故障或待办。

仅在用户明确启动完整产品施工，或真实施工按全局常驻授权需要接班时使用。普通读文档、审核或规则维护不恢复产品 Goal，不另外创建施工聊天。

先读项目 AGENTS、[当前交付流程](../../_workflow/usable-delivery-20261003/DELIVERY-FIRST-POLICY.md)、[总计划](../../槲寄生调度器总计划.md)当前约定功能和相关剩余事项；按需读具体功能合同，不全量加载 R5 历史、旧会诊/认证清单或旧 hooks 协议。

开工核自身原生 Goal、当前目录/分支/HEAD/工作区及在途写者。不存在 Goal 时按本次明确启动授权建立一次完整目标并原生读回 active；文字 `/goal` 不等于已建 Goal。同一完整产品 Goal 不因局部阶段完成被清除或收窄。

初始目标模板如下；执行者补入真实剩余工作、有效证据、当前有限授权和保护边界，同一消息一次完整发送，不让用户搬材料。

```text
/goal 完成槲寄生总计划当前约定全部功能及正式可操作UI的完整可运行版本；保护真实User、第三方JS、其他会话成果和原失败/报告/授权账，复用现成产物与有效证据，特殊小范围普通BUG登记后修；完成判据为功能正常可用、必要影响相称验证和当前明确授权的综合复核成立，同套程序、启动/迁移/恢复步骤及已知问题齐备。

按当前项目AGENTS和交付流程核已有成果、真实入口与剩余功能；集中补齐缺失/不可用功能及有具体依据的误执行、数据或停止风险。新增验证说明它决定哪个产品动作、现有证据为何不足和何时结束；不默认每个小改双审、全量回归、反向突变、全历史或全依赖认证。当前已授权的审查范围、模型/强度/固定次数保持，不自动追加或重置。稳定同套版本完成支持范围实际运行、停止、重启和数据保留，然后交付完整程序与步骤。用户游戏测试等其主动反馈，不以此停下可完成的开发侧工作。

若是自动接班，携带来源聊天与唯一接续标记、当前实际model/effort继承证据、旧Goal真实暂停状态、实际分支/HEAD/未提交成果、当前未完成项和相关有效来源。接班先查询自身Goal并核完整active，核实际cwd和rollout继承值后才写入；不恢复旧写者、不复制无关历史清单或重置预算。
```

执行中的实际新约束沿既有授权及时保留；创建结果未知先核已建身份，不重复开写者。自动交接详见[接续说明](mistletoe-session-relay-2026-09-24.md)。
