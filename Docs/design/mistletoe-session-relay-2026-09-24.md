## 4. 自动交棒（桌面工具执行；不是 Stop 钩子自行建任务）

**单写者规则**：一条计划链同时只允许一个任务修改产品仓库。父任务完成落盘后才派发；子任务收到提示不代表已经取得写权。

链路账放在仓库外 `C:\Users\Administrator\.codex\task-relays\mistletoe\`，不放入产品 Git 快照或交接证据集合，避免接力元数据自己制造业务漂移。首次任务以排他创建文件方式认领 `active.json`，记录 runId、ownerThreadId、状态及时间。已有活动链时读取身份并核对真实任务状态；不得因超时就抢占、删除锁或并发另起链。用户取消的链不得自动复活。

每次移交使用唯一 transferId（runId + 前任任务 ID + 本批次 ID），分别保存不可覆盖的 `offer`、`created`、`ack`、`taken` 记录。记录至少含前任/后继 ID、hostId、cwd、manifest 绝对路径、下一批范围及工具返回状态；落盘用临时文件+原子替换，首次占位用排他创建。该账仅辅助串行与幂等，不能替代真实工具状态或 manifest 审计。

1. **准备**：完成写入/测试，更新计划状态并核对 Git；提交 handoff 判断，生成 JSON/Markdown/prompt 三件套并 audit 通过。offer 保存确切产物路径和剩余工作。正常路径要求 submit 在当前回合内返回真实三件套并 audit 通过，然后继续第2步。若返回 handoff_pending，不在工具里轮询等待本回合 Stop；按现有引擎的首次 Stop 行为结束输出，让可信钩子生成产物并以 decision=block 触发同任务续做。续做收到真实产物链接后先 audit，再执行本次交棒（不是开启新的产品批次）。源码依据为 semantic_handoff.py event_main 的 handoff 分支：首次生成且 stop_hook_active=false 时返回 block。若实际没有该续做信号、产物仍缺失或钩子报错，自动派发路径即为外部阻塞，明确报告；不声称在已结束的回合仍能调用工具，也不制造事件。
2. **封存**：产物成功后前任停止修改产品仓库和被 manifest 引用的材料；交棒记录仅写仓库外。后续若必须修仓库，先取消这次派发且确认后继没有写权，再重新生成交接，不能边写边叫后继接手。
3. **创建唯一后继**：先检查此 transferId 是否已有后继；有则复用，不能重复创建。用 `create_thread` 选择已核对 projectId、`environment.type=local`，不指定模型/强度（沿用用户当前默认设置，除非已有明确指定）。标题写实际下一批工作。提示词含：持续授权、前任 ID、transferId/链路账路径、三件套路径、权威入口、下一批结果/约束/验收；明确“先只读确认接收，待前任回合完成才审计并获得仓库写权”。**只创建后继，不 fork 整段旧聊天。**
4. **核实接收**：保存返回的 threadId/hostId；若仅返回 clientThreadId，属于建立中，不能冒充成功或传给需要 threadId 的工具，应经任务列表/状态找到真实任务。前任调用 `wait_threads(timeoutMs=0)` 只取一次即时状态，并直接读取仓库外的 ack 文件核对 transferId、后继 threadId 和 manifest；尚未出现时用短暂等待后重读并检查真实状态。**前任绝不通过阻塞式 wait_threads 等待后继完成或等待 ack**，因为写 ack 不是该工具的唤醒事件。后继只读核对链路身份/材料可读，先写自己的 ack，然后才用有界 `wait_threads` 等前任回合完成；前任收到匹配 ack 立即执行第5步退出。这样前任等文件、后继等前任回合，不形成双方等任务完成的环。
5. **前任退出**：接收确认后，批次 Goal 只有在其既定验收和交棒要求确实达到时才标 complete，语义状态仍如实为 handoff，不把总计划标完；最终答复给交接链接和 `::created-thread{threadId="..."}`。此后前任不再改仓库，也不自动恢复本批写权。安全中途交接若批次未完成，不得伪标 Goal complete；须在建立 Goal 时把“可审计的安全交棒”明列为该执行批次的合法退出结果，同时保留产品未完成状态。
6. **后继接管**：真实状态证明前任回合结束、交接有效且无取消/冲突后，重新 audit 冻结 manifest，核对 Git 和语义；写 taken 并将链路 owner 转为自己，随后创建自己的批次 Goal并开始修改。不要只凭 ack/文件存在或 Goal 标完判定前任结束。若前任 Stop 续做、外部任务正在同范围写入、或审计漂移，继续只读核查，不能同时施工。
7. **重复上述流程直到总完成**；最后任务不再创建后继，将链路记 complete 并交付总验收报告。旧任务无需用户逐个点“继续”或复制提示词。

**不确定调用处理**：创建工具超时/回包不明时，先用 transferId、任务列表和近期状态查明是否已创建；不盲目重发。创建失败则记录真实错误并保持单写者，仍可在当前任务安全继续的工作继续；任务工具不可用、账号/额度/应用退出等导致无法接续时如实报告，不能写“已自动接上”。这不是绕过使用限制的任务轮换器。
