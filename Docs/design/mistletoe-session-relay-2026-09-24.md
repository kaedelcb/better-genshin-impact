## 必要交接步骤

1. 先结束当前写入/构建/测试/突变恢复并核终态，保存归属明确成果和必要本地提交；保留未提交工作、原失败、未解决问题和生产数据边界。
2. 原生暂停自身未完成 Goal，查询确认同一 Goal 为 paused；无 Goal 不临时创建，真正完成的保持 complete。暂停未知不派接班，不改数据库。
3. 核来源最新有效 rollout 的实际 model/effort 与 settings，核正确项目、路径、host，创建恰好一个同项目 local 接班并显式继承。初始消息一次完整发送，首行完整 `/goal`，携带当前剩余产品工作、有效证据、相关并行准备和有限授权，不带旧工序全集。
4. 记录返回身份，核新 rollout 实际模型/档位一致；用 wait_threads 核接收标记、实际 cwd、自身完整原生 active Goal 后才写入。接班无 Goal 时按授权只建一次并读回，不把初始文字当证明。
5. 创建未知先查已有聊天，不盲目重试。已建但失败保留身份和旧暂停状态；仅确认未创建且工具失败/不可用时提供一个完整人工回退块。接班确认后旧聊天停工，报告真实状态及 created-thread 入口。

当前同一完整产品 Goal 沿用；交接不代表交付，不削功能、不自动加审查次数或换模型。旧聊天自动续做不恢复写入，用户明确选择恢复前先核接班停止写入。
