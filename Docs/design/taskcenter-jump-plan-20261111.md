# 任务中心跳转（流程与车道）设计与执行计划

日期：2026-11-11
状态：方案已确认，**尚未施工**（不改代码，等待开工指令）
范围：`MultiplayerHoeingAssistant` 任务中心基础模式（编排计划：流程 / 车道）；PC 与网页两端。
前置：`86233de78`（编排计划车道任务进入下一行时不再误算新一轮）、`95d7d2072`（对应运行测试）已合入本分支。没有这项修复，往后跳会被误判成新一轮。

## 一、功能范围

| 行类型 | 能力 |
|---|---|
| 普通任务 | 显示编号：主计划行 #1、#2…，车道内任务 #3.1、#3.2…。**只能被跳到**，自身不能设置跳转 |
| 流程 | 整行一个设置：「执行完后：继续下一行 / 跳到 #N」。**流程内部不加跳转步骤** |
| 车道（新版内置条件） | 每条路线一个设置：「走完后：继续下一行 / 跳到 #N」 |
| 旧版配对车道（条件在独立流程上） | 不支持设置跳转（含其条件流程）；可以作为跳转目标 |

规则：

- 目标只能是来源行**之后**的**主计划行**，按界面显示顺序判断；不能往回跳，不能跳进车道里面。
- 跳转存目标行的稳定 Id，增删行导致编号重排不影响。
- 流程跳转是无条件的；需要按条件选择是否跳过时，用车道（一条路线留空并设跳转）。

## 二、已确认的决定（2026-11-11）

1. **流程这一行没有执行时不跳转**：流程被停用、被执行日期或时段过滤、或运行中被「跳过当前」时，跳转不起作用，接着执行下一行。只有流程正常执行完才跳。与启动中心「停用的跳转节点不执行」一致。
2. **目标跑到来源前面时标红并禁止启动**：例如拖动后目标行位于流程或车道之上，来源行标红并提示原因，计划暂时不能启动，等用户改正；不自动改成「继续下一行」，避免跳转悄悄失效、本应跳过的任务被执行。

## 三、技术方案

### 1. 数据（加法字段）

- `WorkflowFlowDefinition.JumpTo`（`jumpTo`），`WorkflowLanesDefinition.YesJumpTo` / `NoJumpTo`（`yesJumpTo` / `noJumpTo`），值为目标行 NodeId。
- **为空时不写入**（`JsonIgnore WhenWritingNull`）。现有计划序列化结果完全不变，这是保证旧版配对车道运行布局键不变的前提（见审核第 4 条）。
- 有跳转的行带标记策略 `flow.jump`：新版本登记为已知类型；旧版执行端不认识，按「未支持类型」拒绝执行，不会忽略跳转、按顺序执行。执行端保存计划时按实际跳转统一补齐或移除该标记，网页、导入等来源漏加也能纠正。

### 2. 保存时派生去向（`WorkflowComposition.Compile`）

- 流程有跳转：去向在原「下一行」之外另记「跳转目标」（见下条）。
- 车道路线有跳转：路线最后一个任务的 `Next` 改为目标行；路线为空时，判断的是/否去向直接为目标行。
- 目标是旧版配对车道时，换算为它的条件流程行（仍先判断再选路线）。

### 3. 执行器（唯一改动点：`WorkflowPlan.Path.cs` 的 `PathSuccessor`）

- 流程行的派生路径增加跳转目标；**仅当结果为 `succeeded` 时**使用跳转目标，`skippedFilter` / `skippedUser` 仍走 `Next`（决定 1）。
- 车道跳转只改派生的 `Next` / `Yes` / `No`，执行器不感知。
- 断点恢复、补跑义务扫描、联机锄地接续、本地等待、准入均不改。

### 4. 校验（`WorkflowComposition.Validate`，进入启动前预检）

阻止启动并在来源行标红的情况：目标不存在；目标不是主计划行；目标在来源之前或就是来源本身；旧版配对车道或其条件流程设置了跳转。

- 这些问题允许保存（编辑中途合法），启动前预检拦住。
- 运行中保存了不合法的修订：沿用现有机制，新修订预检不通过，运行继续用旧定义。
- 另提示「没有路径会走到这里」：从首行沿派生去向做可达性检查，不可达的行仅提示，不阻止启动。

### 5. 编辑操作配套

| 操作 | 处理 |
|---|---|
| 删除被跳到的行 | 先确认；确认后把指向它的跳转改回「继续下一行」 |
| 拖动导致目标在来源之前 | 标红、禁止启动（决定 2），不自动改去向 |
| 复制流程 / 车道 | 跳转设置随之复制，目标不变 |
| 撤销 | 跳转属于计划内容，按现有撤销机制恢复 |
| 导入导出、远程保存、网页保存 | 新字段随计划原样往返；执行端保存时统一补齐保护标记 |

### 6. 状态显示（PC 与网页一致）

| 位置 | 显示 |
|---|---|
| 计划表 | 编号 #N / #N.M；来源行「→ 跳到 #5」；被跳过的行「本轮跳过（跳转）」；目标无效时标红并写明原因；不可达行提示 |
| 运行卡片进度链 | 被跳过的行显示「跳转跳过」，不显示「待执行」 |
| 流程图 | 跳转来源到目标画紫色虚线；被跳过的行灰显 |
| 编辑窗口 | 流程编辑窗口顶部、车道编辑窗口每条路线各一个目标下拉框，只列合法目标 |

计划表、流程图、运行卡片共用 `TaskCenterRunTrace`（本轮走过的路径），被跳过的行由跳转来源的本轮结果推出，三处同口径。网页脚本版本号随施工更新。

## 四、审核：风险与处理

| # | 风险 | 结论 / 处理 |
|---|---|---|
| 1 | 往后跳被误算成新一轮 | 已由 `86233de78` 修复（编排计划只经链尾进入下一轮），是本功能前提 |
| 2 | 恢复时把被跳过的行当成漏执行补跑 | 编排计划恢复只用持久游标，不扫描未到达的行；补测试证明 |
| 3 | 流程执行完、结果落盘前重启 | 现有机制重放流程：步骤检查点均为完成，直接得出结果再记录并跳转，不重复执行步骤 |
| 4 | **旧版配对车道运行布局键** | 旧版布局键序列化整个车道定义，定义变化会让暂停中的运行无法恢复。新字段必须「为空不写入」；旧版配对车道不允许设跳转，字段恒为空，布局键不变。新版车道布局键不含跳转字段 |
| 5 | 运行中修改跳转目标 | 已落盘的游标不变，新目标从下一次执行该行起生效 |
| 6 | 旧版执行端忽略跳转 | `flow.jump` 保护标记拦截；执行端保存时统一补齐 |
| 7 | 网页旧缓存脚本 | 更新脚本版本号 |
| 8 | 停用 / 过滤后的流程仍跳转 | 按决定 1，仅 `succeeded` 时跳 |
| 9 | 车道路线最后一个任务失败 | 失败设为「继续」时路线结束并跳转；设为「停止计划」时计划停止。与现有失败处理一致 |
| 10 | 计划表、流程图、运行卡片显示不一致 | 三处共用同一份路径推算 |
| 11 | 被跳过的行导致运行无法判定成功 | 成功只看是否到达链尾，不要求每行都有结果 |
| 12 | 「从此任务开始执行」选在被跳区间内 | 照常从该行开始；跳转只影响经过来源的路线 |
| 13 | 单任务启动 | 只执行选中行，跳转不起作用 |
| 14 | 联机锄地接管与接续 | 不影响。接管、锄地结束后重发原任务、优先级接续、本地等待重驱都按「任务 Id + 轮次」定位停住的任务，从它继续，不计算去向。流程执行到一半被接管时保留步骤进度，流程执行完才跳转。接续前的车道布局检查不包含跳转字段（见第 4 条）。锄地期间修改跳转目标，接续仍从原任务继续，新目标下一次经过来源时生效 |

**联机锄地相关代码核对（2026-11-11）**：`TaskCenterHost.OnlineHoeing.cs`（接管、终态接续、重发）、`TaskCenterHost.PriorityProcessContinuation.cs`、`TaskCenterHost.LocalWait.cs` 只用 `TryLocate` 按身份定位，不调用 `Next`；唯一的结构检查是 `ValidatePathCursor`（车道布局键）。

**不受影响的功能**：普通任务、没有跳转的流程和车道、旧自定义路径计划、联机锄地、本地等待、按时段执行、循环、断点恢复主逻辑。没有跳转时，保存文件、派生去向、运行布局键与现在逐字节一致。
