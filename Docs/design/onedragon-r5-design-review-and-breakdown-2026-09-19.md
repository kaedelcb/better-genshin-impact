## 2. 待决策点逐项裁决（登记册 §8 ①–④）

### ① 条件出边 schema 演进路线——裁决：兼容加法 + 新 kind 落在已检出位置，不升 schemaVersion

1. **路线定案**：采用**兼容加法表达**，不升 schemaVersion。条件路由属锚点 5「流程图结构」类（非策略修饰），
   以**新节点 kind**（候选名 `route.condition`，实施时冻结）出现在 `nodes[]` 中承载；出边目标为节点身份引用（D11 身份体系）。
2. **fail-closed 成立性**：`node:` 是 `WorkflowKindCatalog.FindUnsupportedKinds` 已检出位置——旧执行器/旧 Store 遇到
   未知节点 kind → D3 第二级「可加载可预览、阻止执行并留痕」。条件边**不可能**被旧执行器静默降级为顺序执行。
3. **禁区纪律（固化登记册首轮阻断项）**：携带执行语义的新增字段**禁止塞入已知 kind 的参数袋**
   （ExtensionData/Params 是 FindUnsupportedKinds 检出盲区）。任何新执行语义（条件边、优先级、固定型、灵活型、
   伴随观察器）一律以新 kind 落在已检出位置（node:/strategy:/trigger:/terminal:/loop:）。此纪律适用于全部机制，不只条件边。
4. **三层区分固化**：可序列化保留（ExtensionData 往返，仅限描述性字段）/ 执行器识别（kind 目录登记）/
   执行准入（FindUnsupportedKinds 阻止执行 + D13 激活态）——三层分别测试，不以「能序列化」推「可执行」。
5. **实施归口：后置，不在 R5 实施范围**。路由求值引擎、分支/汇合范围、无匹配/多匹配规则、求值时点
   （节点终态后、D7 串行对账内）、路由事实持久化（条件输入/选中边/目标出现身份入 RunStore）随机制四实施阶段落地；
   实施开工前置 = 登记册 ①b 评审（流程定义与 RunStore 读写兼容、执行准入，覆盖存量运行记录/暂停中断中运行/回滚后读取）。
   R5 退出不依赖条件边。R1 迁移器本期不动（不升版本；新 kind 为 R5+ 实施期新增，R1 产物不含）。
6. **机制五同理**：伴随观察器的 schema 承载（实施时定）同样只准新 kind 落已检出位置，候选为节点级新策略/修饰 kind。

### ② 打断-恢复粒度——裁决：节点（任务）粒度；被切三选「放弃（默认）/顺延/显式恢复」；任意断点续排除

1. **粒度定案**：打断-恢复一律为**节点（任务）粒度**。现实约束：BGI 游戏任务多为任务粒度重跑，
   任务自身不支持任意断点续，且多数任务有前置状态依赖。
2. **任意断点续排除**：owner 对「断点续」若指任意断点续，属重大范围扩张，**排除出 R5**，单独立项评估才可重启。
   ✅ **owner 已表态（2026-09-19）**：确认节点粒度——被打断的任务整个重跑，不要求断点续；任意断点续排除维持。
3. **被切任务三选语义**（流程级/节点级可配，默认放弃）：
   - **放弃（默认）**：当前 attempt 按取消语义记录（远端取消确认后 skippedUser/cancelled 按事实归类），
     流程按该节点失败策略推进（D12 默认失败行为流程级可配）；
   - **顺延**：被切节点在抢占方结束后重新参选；**仅当前窗口/本轮内有效，跨窗即放弃不补跑**
     （与 `skipAcrossDays=true` 语义一致化，不引入第三套补跑规则）；
   - **显式恢复**：走 R4 既有显式恢复合同（Interrupted + 游标身份重定位，人工显式动作），**不自动恢复**。
4. **四类区别登记**（与 D8/D11/D12 逐项对齐，实施时落文档与测试）：暂停续行 / A6 票据恢复 /
   确认取消后任务重跑 / Unknown 待对账。关键纪律：确认取消后的重跑 = **新 attempt**（提交键含 attempt，
   不违反 D11「结果不确定禁止换键重跑」——该纪律针对结果不确定场景）；**取消未确认（cancelUnconfirmed→Unknown）
   一律停驻待对账，禁止自动重跑**；前置复验按 D8（前置事实绑定节点出现/attempt/账号/会话）。
5. **启动链纪律**：任务中心恢复不得默认重放已终止启动链（D1/R4.9 既有合同，R5 仲裁面消费此事实）。
6. **时间轴交叉**：固定型到点错过按 missPolicy（默认 skip+留痕，不排队无限等待）；顺延不跨窗；
   联机 15 分钟宽限仅限联机批次既有场景，不外推到任务中心候选；停机恢复后已过期的固定型触发不补跑，
   恢复事实进 D7 对账。各触发器既有时间语义（本地午夜/游戏服 4 点/nextDay/联机宽限）保留，不全局套同一规则。

### ③ 优先级仲裁排序——裁决：结构性层级 → 优先级 → 计划到点时刻 → 稳定身份

1. **排序键（从高到低）**：
   - **结构性层级**：系统级抢占源 > 固定型到点候选 > 灵活型窗口候选/普通顺序链候选。
     系统级抢占源 = F11（独立停止约束，在一切之上，非优先级参与者）、A6 抢占、人齐打断、人工显式动作
     （UI 跳过/打断/重排）——既有联机语义保留，进入同一仲裁面而非旁路；
   - **优先级**：int32，**数值大者优先，缺省 0**；旧流程（无 priority 字段）缺省 0 同级——
     不高于任何显式正值、不低于显式负值。承载 = **新策略 kind**（候选名 `schedule.priority`，节点修饰，锚点 4），
     strategy: 为已检出位置，旧执行器 fail-closed 自动成立；
   - **到点时间**：采用**计划时刻**（触发器预定触发时刻），非入队时刻；
   - **稳定身份兜底**：workflowId + 触发出现身份字典序——跨恢复稳定、确定性可重放。
2. **安全交接先于启动**：到点 = 进入仲裁参选，**不等于立即执行**。胜出后走交接状态机
   （请求取消在跑 → 确认/超时 → 启动）；**取消未确认、退出超时、恢复票据仍有效时不得仅凭优先级启动另一任务**，
   该次触发按 missPolicy 处置——宁可错过，不破坏无双跑。
3. **作用粒度与参选资格**：优先级为**节点级修饰**；参选资格 = 已到点/窗口内且前置就绪的候选；
   **顺序链内未就绪节点不参选，链内顺序不受优先级影响**——优先级只在仲裁面跨候选比较时生效
   （采纳登记册机制一缺口②建议：跨流程冲突生效，不在顺序链内插队）。
4. **机制二语义落位**：固定型不拥有超越优先级的特权——「到点无论在做什都执行」由结构性层级
   （固定型 > 灵活型/普通链）达成；同层冲突（固定型 vs 固定型）按优先级 → 到点 → 稳定身份；
   系统级抢占源在固定型之上。固定型硬切经安全交接状态机，不另起打断通道（全部入口同一仲裁面，保无双跑）。
5. **边界情形**：同源重复到点按触发出现身份幂等去重；**低优先级饥饿不设老化机制**
   （24h 周期任务场景量级小，固定型长期占满导致灵活型不执行是语义使然，监控可见即可——登记为已知边界，
   不新增机制）；过期窗口按 ②6 处理。
6. **机制三语义落位**：灵活型窗口候选的空闲判定 = **仲裁面全局空闲**（无任何在跑任务、无固定型已排程占用该时段）；
   「特殊原因」初始枚举 = 联机批次进行中 / 人工暂停 / 恢复票据有效 / F11 冷却 / 系统级抢占源活跃（开放集合，锚点 6）；
   窗口**约束启动时刻**——窗口内取得执行权即锁定本轮，执行允许越窗完成（与 scheduled 轮次窗口语义一致：
   窗口定义轮到谁，不硬切执行中叶子）；被抢占顺延跨出窗口 → 本轮放弃不补跑。

### ④ 伴随观察器生命周期——裁决：拆分收口（a 现存后台触发器 R5 内收口；b 新增伴随观察合同定案、实施后置）

**a) 现存后台触发器（D1 挂账对象，R5 退出前必须收口）**：

1. **统一触发器台账**：每个后台触发器（定时 arm / 电子狗 / 日志）登记——所有权（挂载来源：启动链 runId+节点身份 /
   任务中心触发出现身份 / 手工）、挂载时刻、意图、撤销入口。台账可查可撤。
2. **回溯边界维持**：R4.9 启动链终止**维持不回溯既有后台触发器**（既有行为不变），台账提供显式撤销；
   F11/有界退出兜底不变。
3. **动作准入**：后台触发器产生的执行动作一律进统一仲裁面（R5 接管后无旁路）。
4. **跨重启**：启动中心临时触发器 = 进程级不跨重启恢复（现状保留）；任务中心根级 trigger.time = 持久化可恢复
   （D11 既有）；三类触发器（启动中心临时 / 任务中心根级持久化 / 节点伴随观察器）界限入档，不得混称。

**b) 新增伴随观察能力（机制五完整生命周期，合同本次定案，实施后置——依赖机制四路由求值）**：

1. **收场规则**：宿主终态 → 伴随者**强制收场**（取消）；宿主跳过/打断/失败同此。F11/有界退出兜底不变。
2. **注册绑定**：细化到宿主节点出现 + 轮次 + attempt + 观察器实例（宿主 runId 不足以隔离同运行多节点/循环/attempt）。
3. **生命周期绑定叶子执行区间**：叶子开始执行 → 挂载（**先 arm 就绪、后启动**，防启动即漏事件）；
   叶子终态 → 先冻结观察事实、再收场、再求值分支（顺序固定）；宿主暂停 → 观察挂起；
   宿主 Waiting（未开始执行）→ 未挂载。
4. **观察事实语义**：已产生事实**冻结保留**供对账与路由求值（不删除）；多次命中全量记录（路由按合同消费，
   默认首命中）；收场后迟到事件丢弃留痕；丢失/重启缺口 = **Unknown——未知不等于未命中**，不按无命中走默认边；
   伴随观察器 v1 **不跨重启自动恢复**（观察缺口如实记 Unknown）。
5. **结果载荷**：业务观察值（如「今天跑 A 线」）为**独立结果载荷**，不由失败/取消/跳过三态代替。
6. **持久化与对账**：观察事实入 RunStore（保存/去重/恢复同 D11 纪律），路由求值经 D7 串行对账；
   纯观察器不占 BGI 执行槽位，其触发的执行动作进统一仲裁。

## 5. 施工顺序

**R5.0 冻结合同 → R5.1 仲裁面合同与租约 →（R5.2 全入口接入 ∥ R5.4 机制 schema/引擎）→ R5.3 打断/恢复 →（R5.5 触发器台账 ∥ R5.6 事务迁移）→ R5.7 旧补丁退出 → R5.8 集成验收与仲裁评审兜底。**

理由：仲裁面合同是一切入口与机制语义的地基；机制 schema 与入口接入可并行（同一排序纯函数两侧）；
打断/恢复依赖入口已归一；迁移切换与触发器台账可并行；旧补丁退出必须在迁移承接就绪之后，防功能空档。

## 6. 风险登记（开工即带）

- **R-0（owner 决策带入）**：A/B/C1 真实段未验证（owner 决策跳过，非验证通过）。仲裁面建立在结果通道/收尾抑制/
  单项拒绝的组件级事实上；真实段行为未观测可能暴露组件级夹具未覆盖的交互。兜底：R5.8 仲裁评审逐项复核 +
  owner 实机窗口一旦出现优先补验 A/B/C1；`task.single.native` 维持 false。
- **R-1 无双跑是 R5 第一退出条件**：任何交接不确定（取消未确认/超时/票据有效）→ 不启动，宁可错过触发不错跑。
- **R-2 v2 旧入口**：不携合同字段，仲裁面按兼容候选处理，不得要求旧客户端升级；旧 v2 task.start 行为冻结面不破坏。
- **R-3 不碰真实 User 目录**：开发验证全程独立配置根；真实切换 = owner 另行下令的实机动作；
  配置权威存储唯一在 BGI 本机（文件+修订号），写入一律走 revision 守卫的同一配置面。
- **R-4 既有面不可回归**：联机批次、人齐打断、网页控制、远程配置组编辑；R5.8 回归基线逐项覆盖。
- **R-5 离线优先**：全部夹具本机内存/临时目录，无网络依赖；监控端继续仅启动中心，不越界。
- **R-6 低优先级饥饿**：不设老化机制（§2③5），监控可见即可，登记为已知边界。
- **R-7 第三方 JS 只读**：任何观察/适配经宿主 API 与生命周期实现，不注入 main.js。
