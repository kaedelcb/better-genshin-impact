# 槲寄生共用寄存器

本轮补充：按用户要求增加本位手动归零和全部寄存器归零；复用执行端原子写入、权限和操作回执，只改状态、不改名称和自动规则，定向验证后本地提交，不推送。

## 手动归零

- 每位设置窗新增“本位归零”“全部归零”，点击立即执行，不关闭窗口、不保存尚未应用的名称/自动规则；状态行改为显示当前读取的状态，执行期间禁用重复操作。
- 启动中心和基础计划表共用的十格状态条旁新增“全归零”，紧凑行保留18×18格并维持标题同一行。
- 本位只向选中位写0，全部一次原子写R1–R10；保留名称、重置规则与配置修订，清除归零位的待重置截止时间。状态条以执行端返回快照更新，失败或未知不能显示成功。
- 远端使用 `registers.reset`，继承本人/目标实例、配置写入闸门和耐久回执。请求须明确本位 `Number` 或 `All=true`，空参数与非法位号不解释成全部归零；不回落到监控端本机。

用户已选紧凑方案：在“启动流程”和基础计划表标题旁显示“寄存器”和10个22×22小格。点击小格修改名称和规则，悬停显示R1–R10、名称、当前值及重置规则。用户进一步确认：本次两个节点在启动流程使用，基础计划表先共用状态条和设置；基础/高级模式合并是后续工作。

- R1–R10为稳定身份，名称最多40字；改名不改变任何节点引用。新数据全部为0。
- 不重置、每日固定时刻、状态变化后延时归零三选一；时间全部使用选择组件，延时支持天/时/分/秒。
- 状态从0变1时开始延时；重复写1、保持、改名不延长计时。变为0取消该位的计时。改变延时长度仍以原始状态变化时刻为起点。
- 名称、状态与截止时刻保存到当前助手数据根的`mistletoe-registers.json`。重启先兑现已到期重置，未到期继续；不自动重置的状态保留。每日时刻以执行端本机时间为准。
- 设置节点对每位选择保持/置0/置1，整组校验后原子保存；判断节点对每位选择忽略/等于0/等于1，支持且/或，只读取并执行是/否分支。未选择任何位、数据损坏、节点类型不符时明确失败并停止后续流程。
- 状态服务和两类参数独立于启动流程宿主，供任务中心后续复用；本轮不将尚未开放的高级流程编排标为可用。
- 本机两个中心使用同一服务；远程中心始终读写所选执行端，复用既有身份核对、请求回执和逐位设置修订保护。旧执行端未提供状态时显示“?”，不使用监控端本机状态冒充。
- 旧启动配置缺少新增字段时保持原行为，缺省不插入寄存器节点，不因切换方案而清零寄存器。

验证范围：对本轮新增状态持久化、自动重置、重复写入、重启、节点只读判断及旧配置兼容做定向检查；对实际WPF状态条和时间选择窗口验证尺寸、命名及保存入口。复用既有其他节点和计划执行证据，不重启历史整版认证。
