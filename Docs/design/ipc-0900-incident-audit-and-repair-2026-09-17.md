## 4. 完整修复合同

### 4.1 分开三种身份和两种锁

- 请求身份：BGI 实例/进程 epoch + 客户端 ownerId + batchId + 稳定 requestKey；同一次重试复用 key。
- 根运行身份：workflowRunId + 冻结配置修订 + 节点出现位置 nodeId + iteration。重复同名组仍是不同节点。
- 尝试身份：attemptId/jobId；恢复沿用原逻辑根/节点关系但创建新执行尝试，不重开已终态的 job。
- 逻辑租约：保留整批任务/根流程的执行权，覆盖 UID、切号、配置组和结束动作，也覆盖中间空隙。
- 物理信号量：仍仅由真正执行游戏动作的叶子持有。严禁父级拿着 TaskSemaphore 等子级拿同一把锁。

复用 JobRegistry/BgiTaskCoordinator，不另建竞争的队列或第二套作业真相。新增 ExecutionScope/接管票据可作为现有执行层的一部分；不依赖 VM 可变全局字段或仅凭 AsyncLocal 猜测跨 dispatcher 身份。调用时显式传递并验证父子关系。

### 4.2 接管、执行、释放的状态机

`本地根运行/空闲 → 请求接管 → 旧根静止确认 → 批次独占 → 原策略收尾 → 释放/恢复`

接管票据包含 owner、batch、epoch、停止代际和有效期，重复 suspend 必须幂等返回同一结果，不能再次清恢复点或 Arm 新代际。其他所有者不得消费票据。

对活体旧根，在仲裁状态锁内先禁止下一叶子起步，固定其不可变身份和可恢复游标，设置 Suspending；锁外取消/等待当前叶子退出。必须同时确认物理槽位释放和旧根不会继续启动节点，才可交接。不得持普通 lock 跨 await。

对于真正空闲，不造恢复点。全局历史 taskProgress 可以继续用于显示，但不能提供恢复权威。刚提交未执行的本地任务应按已定义策略拒绝或排队，不冒充被中断的历史任务。

每个游戏动作准入检查必须覆盖 UID/切号/兑换、StartGameTask 等前置副作用、独立任务及旁路直接持锁入口。叶子持物理锁后再次验证根身份/票据/停止代际，关闭“检查通过到起步之间”的竞态。同根嵌套调用复用上下文，不再次申请根所有权。

接管等待上限沿用 30 秒合同；超时明确失败，不强行释放别人持有的锁，不自动重启/杀进程来伪造成功。90 秒意图 TTL 不能充当长时间锄地租约时长。批次存活续约、断线宽限、有界取消后释放必须分开；旧 owner 的迟到释放/恢复不得影响新 owner。

### 4.3 真实结果从叶子传到父级

准入结果与执行结果不同。建议引入结果对象：Admission=Accepted/Rejected，Outcome=Succeeded/Failed/Cancelled/Preempted/Skipped，Reason、实际启动标志、节点计数及失败明细。旧 Ran 只能说明曾进入执行，不能说明成功。

RunMulti 必须返回真实汇总；内部捕获异常继续下一个项目可以保留，但该失败不得消失。一条龙需逐项处理返回值：抢占停止旧根循环；拒绝不推进成功游标；用户停止直接终止；普通失败按既有继续/停止策略执行并累计失败。

取消原因明确区分 UserStop、Preempted、Superseded、Shutdown；TaskCanceledException 不得因 WasCancelled=false 变成功。NormalEndException 当前混合“正常结束/停止”，需按抛出点建立明确分类，不能全部改失败或全部成功。

父 Succeeded 条件：所有必需节点有实际成功/明确合法跳过结果，没有失败或未解释的未执行节点。配置/执行器缺失应 Rejected/Failed；空配置应明确 no_work，不能触发“成功锄地后”的动作。UI/IPC/CLI/恢复均使用同一父汇总出口；协调器只转交结果，不能用 false=completed 再覆盖父结论。

### 4.4 恢复点只能属于真实被暂停的根

记录 rootRunId、原 attempt、配置修订、龙/组/项目祖先链、节点位置、重复次数、进度阶段、暂停原因、接管票据及进程 epoch。游标定义“下一待执行”或“当前被中断节点需重跑”，不得混用整数 0/1 基准。

恢复点在旧运行拥有上下文时固定，发布 slotReleased 前完成提交；不在释放后重读 VM/全局进度。只存一个有效受害者，后续联机子节点永远不能成为自己批次的受害者。已完成根、上线信号及无活体空闲不可恢复。

resume 使用 CAS/票据比较：创建明确 resumeAttemptId，确认该尝试被受理/起步才消费对应恢复点；“看见任意任务持锁”不算恢复成功。重复请求复用同一尝试。失败保留有效恢复点；旧请求不能删除新恢复点。配置被删除/修订不匹配、进程重启后的旧现场必须显式拒绝或要求用户确认，不按 UI 当前配置静默替换。

### 4.5 用户停止是独立的最高优先级事实

统一停止入口先递增 stopGeneration，撤销逻辑租约/待接管/自动恢复意图，标记整个根终止，清排队，再取消活体令牌。即使 CTS 已 disposed，也必须完成前半段。

Set/Clear 仅管理叶子令牌，不能擦除用户停止代际。协调器已 dequeue、尚未进入执行的项也必须复核 stopGeneration。不要靠短冷却到时自动恢复被否决的同一批次；新的显式用户启动或新的合法调度意图才可生成新代际。

停止当前脚本与停止截图器在现有产品里是不同动作，需分别接入相应生命周期，不能只修文档中写的“F11”。

### 4.6 助手与协议兼容

BGI 返回 batch/owner/ticket/epoch、quiesceConfirmed、受理/执行状态及 outcome/reason；SDK 保留字段并在 hello/capability 中协商。老端保留基础单任务能力，不靠缺字段猜测拥有新租约；无法验证所有权的旧自动抢占应明确拒绝并说明需升级。无需另起 IPC v3 或同时重写传输层。

助手只把 UserStop 当用户停止，不把 Preempted 叫 F11。Complete 表示全部终态，不等于成功；输出 Succeeded/Failed/Cancelled/NoWork 批次结果。ResumeOld 与“成功后运行指定任务”分开决策：批次失败仍可按原冲突策略恢复真实受害者，但不得打印成功或执行仅成功时允许的后续任务。没有受害者时输出“无原任务需要恢复”。

slotReleased/job.* 只用于唤醒，最终从匹配 epoch/票据的权威状态确认。查询超时/未知不能放行。应答丢失按稳定 requestKey 查回已有作业，不能仅按 generation+name 找最近一个；BGI 重启与终态淘汰不保证 exactly-once，未知是否执行过时不得盲目重放有副作用任务。

服务端这次已成功广播，不是主因。新增 owner/batch 相关字段若穿过服务端，应完整保留、校验目标实例并做兼容合同测试，不改全员就绪的业务条件。

### 8.1 已实施的事故闭环

- 新增 ExecutionScope：根运行占逻辑执行权，叶子仍独占 TaskSemaphore；UID/切号/兑换/一条龙子组继承同根，显式校验父作业身份，不按来源白名单放行。覆盖独立任务与两处直接持锁的自动追踪入口。
- 接管使用独立票据与现有进程 epoch；重复请求不覆盖受害者，外来/撤销/旧进程票据不得接管或释放。助手串行化重复 suspend，查询为活跃票据续约；租约失联后取消根。30 秒未静止明确失败，不自动杀/重启 BGI。
- TaskRunResult 区分成功、拒绝、失败、取消、让位；RunMulti 返回结果并保留捕获到的项目失败，一条龙按根汇总写父终态。空配置、截图器未初始化、子任务拒绝不再成功；旧连续入口遇到非成功结果停止推进。
- 恢复现场来自活体根，不从 taskProgress 历史或 UI 当前选择推导；保存原根/尝试、龙节点、子组、项目和已读取配置文件的修订。已完成根、已停止根、上线信号不恢复。
- resume 创建新尝试并沿用根身份；按该尝试的真实准入确认消费现场，拒绝配置删除/修改、旧停止代际。准入超过 30 秒保留现场并撤销迟到启动；重复恢复返回既有回执，不重复执行。
- 手动停止独立递增停止代际，撤销票据和恢复现场；即使叶子 CTS 已释放仍有效。Set/Clear 不再擦除停止冷却；停止/暂停热键不受启动门控影响。
- 助手区分让位、用户停止、失败与未知；全部终态不再等于全部成功。无受害者明确输出“无原任务需要恢复”，恢复成功文案只声明“尝试已受理”。
- 强 requestKey 贯穿 SDK/协调器/注册表/对账；同名父子与重复节点不合并。应答丢失限次复用同一 key；已知句柄消失、BGI 重启和长时间无权威状态不自动重放。失败时不得执行仅成功时允许的指定后续任务。
- 批次名单只包含外部配置组，跳过判断前移，单次外部组不吞掉龙内所有同名重复出现；批次期间其他启动命令不能借用现有票据。

兼容边界：可靠接管要求配套新版 BGI 与助手的 task.takeover 能力；旧端仍可使用基础能力，不能缺字段猜测拥有接管权。未改服务端全员就绪业务，未改第三方脚本。
