# 嘟嘟可（Dodoco）日志与监控系统 · 完整设计方案

> 适用分支：`main-OldTeaBag-B151`（茶包版滚动主干）
> 落地项目：`MultiplayerHoeingAssistant`（联机助手，独立 WPF 进程）
> 状态：方案设计稿，待评审后分期实施

---

## 1. 背景与目标

联机助手在锄地过程中目前是"黑盒遥控器"：用户只能从左侧"冒险日志"（内存 100 条）看助手自己的行为，看不到 BGI 主程序（真正执行锄地的进程）在干什么、卡在哪、报了什么错。根目录《联机锄地上线链路稳定性分析报告》也指出当前链路存在多处"静默丢失、无日志"的盲区。

嘟嘟可页面的目标：**把锄地全过程变成可观测**——实时看 BGI 日志、回溯历史日志、自动抓异常、看桌面实况、统计各配置组运行数据。

## 3. 总体架构

```
┌──────────────────── 嘟嘟可页 (DodocoPage) ────────────────────┐
│  Tab1 实时日志   Tab2 日志浏览   Tab3 异常监控                 │
│  Tab4 桌面监控   Tab5 锄地数据   (Tab6 时间线, 进阶)           │
└──────────┬──────────────────────────────┬────────────────────┘
           │                              │
  ┌────────▼─────────┐          ┌─────────▼──────────┐
  │ BgiLogTailService │          │ ScreenshotService  │
  │ (tail+解析+环形缓冲)│          │ (CopyFromScreen)   │
  └────────┬─────────┘          └────────────────────┘
           │ 结构化日志事件 LogEntry
  ┌────────▼─────────┐   ┌──────────────────┐   ┌────────────────┐
  │ KeywordWatchService│  │ HoeingStatsService│   │ LogFileBrowser │
  │ (关键字/正则规则)   │  │ (事件提取+计时统计) │  │ (分块读取/导出) │
  └────────┬─────────┘   └──────────────────┘   └────────────────┘
           │ 命中 → 异常记录 + 通知
     异常库 (异常.json / 内存环形)
```

核心设计：**一条日志管道，多个消费者**。`BgiLogTailService` 负责读文件、切分多行事件、解析级别/实例/来源，产出结构化 `LogEntry` 流；实时显示、关键字监控、锄地统计都只是这个流上的订阅者。这样 F1/F3/F5 共用一份解析，不重复读盘。

`LogEntry` 模型：
```csharp
record LogEntry(DateTime Time, string Level, string? Instance,
                string Source, string Message, string? Exception, long FileOffset);
```

## 4. 用户五大功能细化方案

### F1 实时显示 BGI 日志

- **读取方式**：`FileStream` 以 `FileShare.ReadWrite | FileShare.Delete` 打开（Serilog `shared:true` 下文件被 BGI 占用，必须共享读）；记录已读偏移量，只增量读新增字节。
- **变更感知双保险**：`FileSystemWatcher`（`log` 目录，过滤 `better-genshin-impact*.log`）+ 1 秒轮询兜底（Watcher 在某些环境会丢事件）。
- **跨天滚动处理**：监测到文件名变化（出现新日期文件）时自动切换 tail 目标，无缝衔接。
- **多行事件切分**：用 LogParse 同款行头正则；不匹配行头的行并入上一条的 Message（兼容无实例标识的历史格式）。
- **大文件首次打开**：**不全量加载**——默认只从文件尾倒读最近 2000 行作为上下文，顶部提供"加载更早日志"入口（跳转到 F2 浏览）。
- **UI 性能**：内存环形缓冲窗口（最近 5000 条），`ListBox` + `VirtualizingStackPanel` 虚拟化；后台线程解析，`Dispatcher` 每 200ms 批量合帧刷新，避免日志风暴卡 UI。
- **交互**：自动滚动开关（用户上翻时自动暂停跟尾）、级别筛选（DBG/INF/WRN/ERR 复选）、实例筛选（多开时按 `[BgiInstance]` 下拉）、暂停/继续、清空视图（不影响文件）。

### F2 日志浏览与下载

（用户原文"流量日志"按上下文理解为**浏览历史日志文件**功能。）

- **文件列表**：枚举 `<BGI>\log\better-genshin-impact*.log` + 助手自身 `assistant_runtime.*.log`（两个数据源用分组区分），显示文件名、日期、大小、实例数。
- **大文件查看**：分块随机访问（`FileStream.Seek` + 按块解码），滚动到接近边界时按需加载相邻块；支持跳转到行号/时间。
- **搜索**：当前文件内关键字/正则搜索，结果列表点击跳转，匹配高亮。
- **下载/导出**：
  - 原样导出：复制整个 `.log` 文件到用户指定位置；
  - 筛选导出：把当前过滤结果（级别/关键字/时间范围）导出为 `.log` 或 `.csv`；
  - 复用"打开日志目录"思路（`CommonSettingsPageViewModel.OnGoToLogFolder` 同款 `explorer.exe` 调用）。
- **注意**：正在写入的当天文件复制时同样要 `FileShare.ReadWrite` 打开，避免 IOException。

### F3 异常监控（关键字检测）

- **规则模型**：`WatchRule { 关键字/正则, 匹配级别范围(如仅 WRN+ERR), 启用开关, 是否告警, 备注 }`，持久化到 `User/dodoco_watch_rules.json`（跟随助手配置目录约定）。
- **内置预置规则**（开箱即用，基于 §2.2 语料）：
  - `出错|异常|失败|错误`（宽匹配，默认只记不告警）
  - `执行路线 .* 出错`、`锄地一条龙任务被取消`、`[联机] ===== 联机锄地退出`
  - 级别 = ERR（兜底：任何 Error 级自动入异常库）
- **命中记录**：异常库保存 `时间、规则名、级别、实例、命中行原文、前后各 5 行上下文、文件偏移`。持久化为 JSONL（`log/dodoco_exceptions.{date}.jsonl`），重启不丢。
- **防风暴**：同一规则 60 秒内最多记 N 条（默认 5），超出合并计数显示"×N 次"——对应《通信架构标准化方案》的 500ms 去抖思路放大到分钟级。
- **提醒**：命中且开启告警的规则 → 托盘气泡 + 嘟嘟可导航按钮红点 + 可选提示音；提供"全部静音"开关。
- **异常库视图**：按时间倒序列表，可按规则/级别/日期筛选；点击某条 → 跳转到 F2 浏览中对应的文件位置（用保存的 FileOffset 精确定位上下文）。

### F4 桌面监控（实时截图）

- **本机截图**：`System.Drawing.Common` 的 `Graphics.CopyFromScreen`（助手已引用该包），截取主屏全屏。
- **刷新策略**：手动"刷新"按钮 + 可选自动刷新（间隔 1/3/5/10 秒下拉选择，默认手动）。自动刷新时缩略图 JPEG 压缩（质量 ~70）降低内存。
- **DPI 适配**：助手进程需感知 DPI 缩放，否则高分屏截不全——在 manifest 或 `App.xaml.cs` 设 `PerMonitorV2`（需检查现有 manifest，若未开则截图前用 `GetSystemMetrics` 按物理像素计算区域）。
- **历史帧**：保留最近 10 帧可左右翻看（内存位图池，超出释放）。
- **隐私与性能提示**：页面注明截图仅本地显示不上传；离开 Tab 时自动停止自动刷新定时器。
- **（进阶，见 §5-B）远程成员桌面**：经控制房间 SignalR 上报缩略图。

### F5 联机锄地运行数据

两个数据来源组合：

**A. 实时状态（已有机制，零成本）**：订阅现有 `ControlRoomPlayersUpdated` 广播，展示各成员 `CurrentTaskGroupName / CurrentRouteDisplay / AutoHoeingProgress / TaskRunning` 的实时表格（比主页成员列表更聚焦锄地维度）。

**B. 运行时间统计（新做）**：`HoeingStatsService` 消费 `LogEntry` 流，用 §2.2 模板做事件提取：
- **配置组级**：`锄地一条龙任务启动 [配置组: X]` → 启动时间；下一个组启动/任务结束/取消 → 结束时间。得出**每组实际运行时长**。
- **路线级**：`开始执行地图追踪任务: X` ↔ `→ 脚本执行结束: X` 配对，得出**每条路线耗时**；异常配对失败（出现"出错"而无结束）标记为中断。
- **联机级**：`[联机] 人齐…开始锄地` ↔ `[联机] ===== 联机锄地退出`，得出**联机会话时长与退出原因**。
- 统计结果按"批次（generation）"分组展示：本次锄地从几点到几点、跑了哪几组各多久、哪条路线最慢、中断了几次。
- **持久化**：`log/dodoco_stats.{date}.jsonl` 追加写，历史 Tab 可查过往批次的汇总（日均时长、最常中断路线 TOP5）。
- **与服务器侧规划衔接**：《架构审核与重构方案》§8.1 规划的每房间 BoundedEventLog（环形 500 条 + revision）落地后，可新增 Hub 查询方法把房间级事件也并入本页，覆盖"为什么集体卡死"的场景。当前版本不依赖它。

## 5. 建议新增的功能（参考同类产品设计）

参考对象：Seq / Grafana Loki（日志流 + 告警规则）、klogg/glogg（大文件 tail 与分块）、游戏运维面板（在线状态 + 截图巡检）、BGI 自带 LogParse HTML 报告。

**A. 卡死心跳检测（强烈建议，低成本高价值）**
日志流本身就是一个心跳：若 `task.status` 显示锄地运行中，但日志超过 N 分钟（默认 3 分钟，可配）无任何新行 → 判定"疑似卡死"，红色横幅 + 告警。BGI 已有守护重启机制，本功能是给它加上"用户可见的眼睛"。实现只需在 `BgiLogTailService` 里记最后一条日志时间戳。

**B. 远程成员监控汇聚（联机场景的核心差异化）**
助手本就身在控制房间里。各成员端每 10s 已在报 `ControlStatus`——嘟嘟可做一个"多成员巡检墙"：每成员一张卡片（状态 + 当前路线 + 进度 + 可选缩略截图）。缩略截图需要各端助手/BGI 新增一个 SignalR 上报通道（JPEG 缩略图 base64，限宽 480px、10s 一帧，流量可控）。这是把"联机"优势变现的功能，单机日志工具做不到。**作为 P4 之后的服务端联动项，需要 Hub 加一个方法。**

**C. 诊断包一键导出（对应"为什么这次集体卡死了"）**
选一个时间点，自动打包：前后 10 分钟 BGI 日志切片 + 助手 runtime 日志 + 异常库命中记录 + 当前成员状态快照 → 单个 zip。排查联机问题时直接发给别人，替代现在手工翻两个目录。

**D. 收益与效率报表（数据来自现成日志）**
`路线组合结果：…收益 {G} 摩拉，预计用时…` 已在日志里，配合实际耗时统计，可出"摩拉/小时"效率趋势。放 P5，先做时间统计再谈收益。

**E. 日志级别/来源过滤的搜索栏统一化**
参考 Seq 的表达式过滤：一个搜索框同时支持 `级别`、`来源(SourceContext)`、`关键字` 组合（如 `ERR 路线`），实时 Tab 和浏览 Tab 共用同一套过滤控件与解析。

**F. 锄地事件时间线视图（F5 的可视化增强）**
把提取出的事件（组切换/路线开始结束/战斗/联机同步点）画成横向甘特条，一眼看出"这一晚时间花在哪"。可用纯 XAML `Canvas` 绘制，不引图表库。

## 7. 关键技术风险与对策

| 风险 | 对策 |
|---|---|
| BGI 占用日志文件 | 全程 `FileShare.ReadWrite\|Delete`；复制/导出同样共享读 |
| 单文件几万行全量加载卡死 | 实时默认倒读 2000 行；浏览分块 seek；UI 虚拟化 + 环形缓冲 5000 条 |
| 日志风暴卡 UI | 后台解析 + Dispatcher 200ms 合帧；规则命中去抖合并 |
| BGI 未来改日志模板导致解析失效 | 行头不匹配的行一律并入上一条（容错降级，绝不丢行）；正则常量集中一处并注释同步来源 `LogParse.cs:22-24` |
| 多实例/多开日志混杂 | 按 `[BgiInstance]` 分组 + 筛选；无实例标识的历史文件归为"未知实例" |
| 大量错误日志无堆栈（只记 ex.Message） | 异常库保存前后 5 行上下文补偿；关键字规则不依赖"Exception"字段存在 |
| FileSystemWatcher 丢事件 | 1s 轮询兜底，比对文件长度变化 |
| 截图 DPI 截不全 | PerMonitorV2 感知 + 物理像素计算 |
| 助手与 BGI 不在同一台机器（遥控器模式） | F1/F2/F4 标注"本机模式可用"；F5-A 状态流在遥控模式仍可用；远程汇聚（§5-B）是遥控模式的正解 |
