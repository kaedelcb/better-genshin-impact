# 联机助手 · 远程配置组编辑 — 实施方案与通信契约

> 目标：在联机助手成员卡片昵称右侧加 ⚙ 按钮，点击 → 列出对方配置组 → 选择后拉取对方配置 →
> 本机 BGI 弹出与 BGI 完全相同的设置页（组级设置 ScriptGroupConfigView / 锄地一条龙 MultiplayerHoeingSettingsView）→
> 修改保存 → 回传对方 → 对方 BGI 合并落盘并刷新内存。

## 0. 总体架构

```
A 助手 ⚙ → 选组 → RemoteCommand "remote_config.pull" ──SignalR/服务器──→ B 助手
B 助手 → IPC "config.pull_group" → B 的 BGI 读配置 → 回包 → B 助手
B 助手 → RemoteCommand "remote_config.data" → A 助手
A 助手 → IPC "config.open_remote_editor" → A 的 BGI 弹远程编辑窗口（原样复用两个设置页）
A 的 BGI 保存 → A 助手轮询 IPC "config.remote_editor_result" 取回修改
A 助手 → RemoteCommand "remote_config.push" → B 助手 → IPC "config.apply_group" → B 的 BGI 合并+原子写+刷新
B 助手 → RemoteCommand "remote_config.push_result" → A 助手提示结果
```

- 服务器（BgiCoordinatorServer）**零改动**：全部走现有 SendRemoteCommand 定向投递 + 离线缓存。
- 所有 RemoteCommand.Params 的值**一律用 string**（SignalR 会把 Dictionary<string,object> 反序列化成 JsonElement，大 JSON 必须作为字符串整体传输）。

## 1. RemoteCommand 契约（4 个新 Cmd）

### 1.1 `remote_config.pull`（A→B）
Params: `{ "groupName": "<组名>" }`，CommandId 关联后续回复。

### 1.2 `remote_config.data`（B→A，pull 的回复，Target=[A 的 UID]）
Params:
- `ok`: "true" / "false"
- `error`: 失败原因（ok=false 时）
- `packageJson`: 一个 JSON **字符串**，内容为：
```json
{
  "groupName": "string",
  "scriptGroupJson": "string（User\\ScriptGroup\\{组名}.json 的完整文件文本）",
  "autoHoeingConfigJson": "string（对方全局 AutoHoeingConfig 序列化）",
  "autoFightStrategyFiles": ["文件名.txt", ...],
  "autoGeniusFiles": ["文件名.txt", ...],
  "bgiVersion": "string",
  "groupRunning": true,
  "fileMd5": "string（组文件 MD5，用于乐观并发提示）"
}
```

### 1.3 `remote_config.push`（A→B）
Params（均可选，至少一个非空；全部为 string）:
- `groupName`
- `baseMd5`: pull 时的 fileMd5
- `scriptGroupConfigJson`: 编辑后的组级 ScriptGroupConfig JSON（组级设置保存时有）
- `soloTaskName`: 组内锄地一条龙 project 的实际 Name（"锄地一条龙（联机）" 或 "锄地一条龙"）
- `soloTaskSettingsJson`: 编辑后的 SoloTaskSettingsObject 字典 JSON

### 1.4 `remote_config.push_result`（B→A）
Params: `{ "ok": "true"/"false", "message": "人类可读结果" }`
message 需包含：是否覆盖期间变化（baseMd5 不匹配）、对方正在运行该组（"下次启动生效"）等提示。

## 2. BGI 侧 IPC 新操作（InstanceIpcProtocol 加 4 个常量 + InstanceRequestHandler 加 4 个分支）

注意：助手 IpcClient 只接受响应 data 为 **JSON 对象**（IpcClient.cs L108），所有响应 data 必须是对象。

### 2.1 `config.pull_group`
请求 data: `{ "groupName": "..." }`
响应 data: `{ "ok": true, "package": { ...同 1.2 packageJson 结构... } }` 或 `{ "ok": false, "error": "..." }`
实现：读 `User\ScriptGroup\{groupName}.json` 原文；序列化 `TaskContext.Instance().Config.AutoHoeingConfig`（System.Text.Json）；
列 `User\AutoFight`、`User\AutoGeniusInvokation` 文件名（AutoFightViewModel.LoadCustomScript 同款过滤规则）；
版本号；`TaskSemaphore.CurrentCount == 0 && RunnerContext 组名匹配` → groupRunning；文件 MD5。

### 2.2 `config.open_remote_editor`
请求 data: `{ "targetName": "...", "targetUid": "...", "groupName": "...", "packageJson": "..." }`
响应（立即返回）: `{ "state": "editing" }` 或 `{ "state": "rejected", "error": "已有进行中的远程编辑会话" }`
实现：Dispatcher 上弹 `RemoteConfigEditWindow`（见 §3）。单会话：已有会话时 rejected。

### 2.3 `config.remote_editor_result`（助手每 2s 轮询）
响应 data:
- `{ "state": "editing" }` —— 还在编辑
- `{ "state": "saved", "scriptGroupConfigJson": "...", "soloTaskName": "...", "soloTaskSettingsJson": "..." }` —— 各字段可选；读取后会话关闭、状态回 idle
- `{ "state": "cancelled" }` —— 用户放弃；状态回 idle
- `{ "state": "idle" }` —— 无会话

### 2.4 `config.apply_group`
请求 data: `{ "groupName", "baseMd5", "scriptGroupConfigJson"?, "soloTaskName"?, "soloTaskSettingsJson"? }`
响应 data: `{ "ok": true/false, "message": "...", "md5Changed": true/false, "groupRunning": true/false }`
实现（全部在 Dispatcher 上执行）：
1. 从 `App.GetService<ScriptControlViewModel>().ScriptGroups` 找组（找不到则从文件 `ScriptGroup.FromJson` 加载）
2. 有 scriptGroupConfigJson → 反序列化为 ScriptGroupConfig **替换** `group.Config`
3. 有 soloTaskSettingsJson → 找 `group.Projects` 中 Name == soloTaskName 的 project，将其 `SoloTaskSettingsObject` 内容**整体替换**（反序列化 Dictionary<string,object?>，注意 JsonElement→CLR 原生类型归一化，参考 ScriptGroup.NormalizeSoloTaskSettings）
4. 调 `ScriptControlViewModel.WriteScriptGroup(group)`（内部走 WriteToFileAtomically 原子写）
5. 触发内存刷新，防止旧内存覆盖新文件：重新执行 ReadScriptGroup 等价逻辑刷新 ScriptControlViewModel；OneDragonFlowViewModel 若已加载也重读（InitConfigList/ReadScriptGroup）
6. message 组装：md5Changed → "对方配置在编辑期间有变化，已按远程版本覆盖"；groupRunning → "该组正在运行，下次启动生效"

## 3. BGI 远程编辑窗口（新文件）

`BetterGenshinImpact/View/Windows/RemoteConfigEditWindow.xaml(.cs)`（FluentWindow，WPF-UI 风格；提示用 ThemedMessageBox）：
- 标题：`远程配置编辑 - {targetName}（UID {targetUid}）`
- 顶部横幅（警示色）：`正在编辑远程成员「{targetName}」配置组「{groupName}」的配置，保存并回传后将覆盖对方配置。`
- 版本不一致时横幅追加警告（package.bgiVersion vs 本机版本）。
- 两个按钮：
  - 「配置组设置」→ 弹组级设置（复用 ScriptGroupConfigView）
  - 「锄地一条龙（联机）设置」→ 组内无该任务时禁用并 ToolTip 说明
- 底部：「保存并回传」（有 dirty 才可用）/「关闭」（有 dirty 时二次确认）

### 3.1 组级设置复用方式
```csharp
var remoteGroup = ScriptGroup.FromJson(package.scriptGroupJson); // 临时对象，不落盘
var vm = new ScriptGroupConfigViewModel(TaskContext.Instance().Config, remoteGroup.Config);
// AutoFightViewModel 需新增可选参数注入远程策略清单（见 §4.2）
var view = new ScriptGroupConfigView(vm);
```
保存 = 把 `remoteGroup.Config` 序列化为 scriptGroupConfigJson，标记 dirty。**不写本地文件。**

### 3.2 锄地一条龙设置复用方式
- 从 remoteGroup.Projects 找 Name 为 "锄地一条龙（联机）"/"锄地一条龙" 的 project，取（或新建）其 SoloTaskSettingsObject 字典
- 构造**脱离本地配置组的临时 ScriptGroupProject**：Name 用对方 project 的实际名，SoloTaskSettingsObject=对方字典，GroupInfo=remoteGroup
- `new MultiplayerHoeingSettingsViewModel(settings字典, 对方的AutoHoeingConfig, groupOptions, groupDefault)`（groupOptions/groupDefault 取 SoloTaskRegistry.GetSettingItems 的 groupIndex 定义，同 ShowHoeingSettingsDialog L2064-2068）
- `new MultiplayerHoeingSettingsView(item, vm, remoteMode: true, globalCfgOverride: 对方AutoHoeingConfig, remoteStrategyFiles: package.autoFightStrategyFiles)`
- 保存 = view.Save() 后序列化字典为 soloTaskSettingsJson。**不写本地文件。**

## 4. 现有代码的改造点（全部遵循"可选参数+默认值=旧行为"）

### 4.1 `MultiplayerHoeingSettingsView.xaml.cs`（加可选构造参数）
新增可选参数：`bool remoteMode = false, AutoHoeingConfig? globalCfgOverride = null, IReadOnlyList<string>? remoteStrategyFiles = null`
remoteMode=true 时：
- `_globalCfg` 用 globalCfgOverride（L67）；L351/L1129/L1366 的 `TaskContext...AutoHoeingConfig` 同样换 override
- **跳过/禁用磁盘扫描区域**：BuildBuiltinRouteHost / HookVariantPanel / BuildMemberRouteRolesHost 改为显示一行占位文本"远程编辑模式：路线相关设置请在对方本机修改"
- `SaveVariantPreferences()` 跳过 `gcfg.SetVariantPreference` 全局镜像（L1366-1368）
- 战斗策略下拉选项源换 remoteStrategyFiles（HookFightStrategyCombo，L79）
- "打开联机战斗策略文件"按钮禁用（L79 HookFightStrategyButton）
无辜调用方：`ScriptControlViewModel.ShowHoeingSettingsDialog` 不传新参数 → 行为逐字节不变。

### 4.2 `AutoFightViewModel.cs`（加可选策略清单覆盖）
构造函数加可选参数 `IEnumerable<string>? strategyOverride = null, IEnumerable<string>? combatStrategyOverride = null`，
非 null 时跳过 LoadCustomScript 磁盘扫描直接用覆盖清单。默认 null → 旧行为。
无辜调用方：现有 `new AutoFightViewModel()` / `new AutoFightViewModel(config)` 全部不变。

### 4.3 `InstanceIpcProtocol.cs` / `InstanceRequestHandler.cs`
纯新增常量与 switch 分支，不改任何现有分支。

## 5. 助手侧改动

### 5.1 `Views/MainWindow.xaml`
昵称 StackPanel（L723-727）右侧加 ⚙ 按钮（样式 TextAction，ToolTip"远程编辑该成员的配置组"），
Command 绑 `DataContext.RemoteConfigEditCommand`（RelativeSource AncestorType=Window），CommandParameter={Binding}。
自己的卡片禁用（IsEnabled 绑一个MemberViewModel 新属性 CanRemoteEdit = 非自己 && Online）。

### 5.2 `ViewModels/MainViewModel.cs`（纯新增）
- `public RelayCommand RemoteConfigEditCommand => new(OnRemoteConfigEdit);`
- `OnRemoteConfigEdit(object? param)`：MemberViewModel → 弹配置组选择窗（列出 member.ConfigGroups，新小窗口或复用现有弹窗模式）→ 选定后：
  1. 发 `remote_config.pull`（Target=[member.PlayerUid]，CommandId=Guid）
  2. 等待 `remote_config.data`（20s 超时 → AddLog + 提示"对方未响应（可能不在线或版本过旧）"）
  3. ok → IPC `config.open_remote_editor`（本机 BGI 未运行 → 提示"远程编辑需要本机 BGI 运行中"）
  4. 每 2s 轮询 `config.remote_editor_result`（最长 10 分钟）
  5. saved → 发 `remote_config.push` → 等 `remote_config.push_result`（15s）→ AddLog 结果
  6. cancelled → AddLog "已取消"
- `OnRemoteCommand` 新增 4 个分支（pull/data/push/push_result），放 ack 分支之后、其他分支之前，各自 return，不影响现有分支。
  - pull 分支：IPC `config.pull_group` → 回 `remote_config.data`（不复用 ack 通道，data 有独立语义）
  - push 分支：IPC `config.apply_group` → 回 `remote_config.push_result` + AddLog
- 新服务类 `Services/RemoteConfigEditService.cs`：会话状态机（等待回复的 TaskCompletionSource 字典按 CommandId 关联、超时、单会话锁），把上述流程从 MainViewModel 里拆出去。

### 5.3 `MemberViewModel`（MainViewModel.cs L4867 起）
加 `CanRemoteEdit` 属性（PlayerUid != 自己 && Online）。

## 6. 边界与防御

- 新旧版本混跑：旧端收到未知 Cmd 静默忽略 → A 端 20s 超时提示"对方版本过旧"。
- B 离线：pull 会被服务器缓存，A 端按超时放弃即可（不等待离线成员）。
- 并发：A 端同一时刻只允许一个远程编辑会话；BGI 端 open_remote_editor 单会话拒绝第二个。
- 安全：沿用房间密码+白名单鉴权；push 目标校验由服务器 RoomManager 既有逻辑保证。
- 数据量：packageJson 通常 < 100KB，远低于 SignalR 10MB 上限。
- 绝不写 A 本地的 `User\ScriptGroup` 目录；远程数据全程只在内存临时对象中。
